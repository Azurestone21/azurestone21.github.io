JS 闭包

JS 闭包

1. 核心定义

闭包 = 函数 + 该函数能够访问到的外部词法环境（Lexical Environment）的捆绑集合。

通俗讲：当一个函数能够记住并访问它定义时所在的作用域（即使这个函数在作用域之外被调用），就形成了闭包。

outer 执行完后，正常情况下 count 应该被回收，但因为 inner 引用了它，所以 count 一直存活 —— 这就是闭包。

三个核心特征：

  1. 函数嵌套（内部函数引用外部变量）
  2. 外部函数执行完毕后，变量不被销毁
  3. 内部函数可以在外部被调用，仍能访问那些变量

2. 底层运行原理（内存视角）

  • 作用域链：函数定义时，会保存一个[[Scope]]属性，指向其父级作用域。
  • 引用传递（非复制）：闭包捕获的是外部变量的内存地址（引用），而不是值。所以外部变量变化时，闭包读到的也是最新值（这也是循环陷阱的根源）。
  • 内存驻留：只要闭包还在使用，外部函数的变量就不会被垃圾回收（GC）销毁。

翻车现场（var + 异步）：

原因：var 无块级作用域，三个定时器共享同一个 i 引用；循环结束后 i=3。

解决方案对比：

方案 原理 代码
let 声明（ES6） 每次迭代生成独立的块级作用域 for (let i = 0; i < 3; i++) { ... } // 输出 0,1,2
IIFE（ES5 垫片） 立即执行函数+传参，将引用变成值拷贝 (function(j){ setTimeout(()=>console.log(j)) })(i)
forEach 高阶函数 回调函数自带独立作用域 [0,1,2].forEach(i => setTimeout(()=>console.log(i)))

5. 内存泄漏风险与解除

风险：闭包引用着大对象（如 DOM 节点、大型数组），而 DOM 被删除或组件卸载时，由于闭包仍存在，内存无法释放。

解决方案（切断引用链）：

框架（React/Vue）中，务必在 useEffect 的清理函数或 onUnmounted 中清除定时器/事件监听。

6. 现代框架（React/Vue）中的特殊闭包陷阱

场景：useEffect / onMounted 中使用了 setInterval 或异步请求。

错误表现：定时器里打印的 state 永远是初始值（过期闭包）。

原理：空依赖数组 [] 导致回调函数只捕获了第一次渲染时的变量值。

解法：

  • 将依赖变量加入数组：[count]。
  • 或使用 ref（引用对象）来保存最新值，因为 ref 是对象引用，不形成闭包快照。

7. 总结

“闭包是 JavaScript 作用域链机制的自然延伸。它让内部函数始终持有外部作用域的引用，这赋予了 JS 封装和状态持久化的能力，但也带来了内存管理的责任。ES6 的 let/const 通过块级作用域从根本上解决了经典的循环引用陷阱，而 IIFE 则是这一机制的经典手写替代方案。”
