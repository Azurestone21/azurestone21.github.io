常见安全响应头

常见安全响应头

一、概述

安全响应头是服务器通过 HTTP 响应下发给浏览器的安全策略，用来限制资源加载、防止 XSS、点击劫持、MIME 嗅探、信息泄露等。它们是纵深防御的重要一环，配置成本低、收益高。

二、核心安全响应头

1. Content-Security-Policy（CSP）

作用：限制页面能加载哪些资源，防 XSS、数据注入、点击劫持。

常用指令：

指令 作用
default-src 所有资源的默认策略
script-src JS 来源
style-src CSS 来源
img-src 图片来源
connect-src fetch/XHR/WebSocket 目标
font-src 字体来源
object-src <object>/<embed>，建议 'none'
base-uri 限制 <base> 标签，建议 'self'
frame-ancestors 防点击劫持，替代 X-Frame-Options
form-action 限制表单提交目标
upgrade-insecure-requests 自动升级 HTTP 到 HTTPS

nonce 示例：

注意：frame-ancestors 优先级高于 X-Frame-Options，现代浏览器推荐用 CSP。

2. Strict-Transport-Security（HSTS）

作用：强制浏览器后续只用 HTTPS 访问，防降级攻击和 Cookie 劫持。

参数 含义
max-age 强制 HTTPS 的秒数
includeSubDomains 子域也生效
preload 申请加入浏览器预加载列表

注意：一旦设置，在 max-age 内无法回退到 HTTP，调试时慎用。

3. X-Content-Type-Options

作用：禁止浏览器 MIME 嗅探，防止把非脚本文件当脚本执行。

场景：攻击者上传一个伪装成图片的 JS 文件，浏览器嗅探后当脚本执行。加 nosniff 后，浏览器严格按 Content-Type 处理。

4. X-Frame-Options

作用：防点击劫持，控制页面能否被 iframe 嵌入。

取值 含义
DENY 禁止任何页面嵌入
SAMEORIGIN 只允许同源嵌入

注意：已被 CSP frame-ancestors 取代，但为了兼容老浏览器可以同时设置。

5. Referrer-Policy

作用：控制请求头 Referer 发送多少信息，防敏感 URL 泄露。

取值 含义
no-referrer 完全不发送
same-origin 同源发送完整，跨源不发送
strict-origin 只发送源，HTTPS→HTTP 不发送
strict-origin-when-cross-origin 同源完整，跨源只发源，降级不发（推荐）
no-referrer-when-downgrade 默认行为，降级不发送

6. Permissions-Policy

作用：限制浏览器特性 API，防滥用。

常见限制：

  • geolocation：定位
  • camera：摄像头
  • microphone：麦克风
  • payment：支付
  • usb、fullscreen、autoplay 等

7. Cross-Origin 系列

用于隔离跨源资源，防侧信道攻击（如 Spectre）。

Cross-Origin-Opener-Policy（COOP）

隔离浏览上下文，防止跨源窗口引用。

Cross-Origin-Embedder-Policy（COEP）

要求跨源资源必须显式授权才能加载。

Cross-Origin-Resource-Policy（CORP）

控制资源能否被跨源加载。

组合使用：COOP + COEP 可以启用 crossOriginIsolated，使用 SharedArrayBuffer 等高精度 API。

8. Access-Control-Allow-Origin（CORS）

作用：控制跨源请求能否读取响应。

注意：

  • 带凭证时不能用 *。
  • 不要反射任意 Origin。
  • 加 Vary: Origin 防止缓存错乱。

9. Set-Cookie 安全属性

属性 作用
HttpOnly 禁止 JS 读取，防 XSS 窃取
Secure 只走 HTTPS
SameSite 防 CSRF，Lax/Strict/None

10. Cache-Control（敏感页面）

作用：防止敏感页面被缓存。

场景：登录页、支付页、个人中心。

三、速查表

响应头 防什么 推荐值
Content-Security-Policy XSS、注入、点击劫持 default-src 'self'; object-src 'none'; base-uri 'self'; frame-ancestors 'none'
Strict-Transport-Security 降级、Cookie 劫持 max-age=31536000; includeSubDomains
X-Content-Type-Options MIME 嗅探 nosniff
X-Frame-Options 点击劫持 DENY 或 SAMEORIGIN
Referrer-Policy URL 泄露 strict-origin-when-cross-origin
Permissions-Policy 特性滥用 geolocation=(), camera=(), microphone=()
Cross-Origin-Opener-Policy 侧信道 same-origin
Cross-Origin-Embedder-Policy 侧信道 require-corp
Cross-Origin-Resource-Policy 跨源读取 same-origin
Access-Control-Allow-Origin 跨源读取控制 白名单具体源
Set-Cookie XSS、CSRF、窃听 HttpOnly; Secure; SameSite=Lax
Cache-Control 敏感页面缓存 no-store

六、注意事项

  1. CSP 要逐步上线
    先用 Content-Security-Policy-Report-Only 观察，再正式启用，避免误伤。

  2. HSTS 不可轻易回退
    max-age 内无法回退，调试时用短时间。

  3. 不要只依赖响应头
    响应头是纵深防御，不能替代输出编码、CSRF Token、输入校验。

  4. 兼容性
    老浏览器可能不支持 CSP、COOP、COEP，需评估目标用户。

  5. CSP 不是银弹
    配置不当仍可能被绕过，需配合 Trusted Types、nonce、hash。

七、总结

常见安全响应头有：CSP 防 XSS 和注入，限制资源来源；HSTS 强制 HTTPS；X-Content-Type-Options 防 MIME 嗅探；X-Frame-Options 和 CSP 的 frame-ancestors 防点击劫持；Referrer-Policy 控制 Referer 泄露；Permissions-Policy 限制浏览器特性；Cross-Origin 系列做跨源隔离；CORS 头控制跨源读取；Set-Cookie 的 HttpOnly、Secure、SameSite 保护 Cookie；敏感页面加 Cache-Control: no-store。
实际项目可以用 Helmet 一键配置，CSP 建议先用 Report-Only 观察再正式启用。
这些头是纵深防御的一环，不能替代输出编码、CSRF Token 和输入校验。
