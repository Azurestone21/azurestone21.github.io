前端性能优化

前端性能优化

前端性能优化可以概括为：用指标定位瓶颈，围绕“更快加载、更早渲染、更流畅交互、更少资源”做优化。实际项目中先测量再优化，避免过早优化。

1. 核心指标

  • TTFB：首字节时间，反映网络/服务端响应。
  • FCP：首次内容绘制。
  • LCP：最大内容绘制，关注首屏主图/大标题。
  • INP：交互到下一次绘制，已取代 FID，关注交互流畅度。
  • CLS：累积布局偏移，关注视觉稳定性。
  • TBT：总阻塞时间，实验室里常看主线程长任务。

2. 加载阶段优化

网络传输

  • 用 CDN、HTTP/2 或 HTTP/3，减少连接和传输开销。
  • 开启 Brotli/Gzip 压缩。
  • 配好缓存：静态资源 hash 文件名 + 强缓存 Cache-Control: max-age=31536000, immutable；HTML 用协商缓存或短缓存。
  • 用 preconnect、dns-prefetch、preload、prefetch 控制资源优先级。
  • Service Worker 做离线缓存和重复访问加速。

资源体积

  • 代码分割、路由懒加载、动态 import()。
  • Tree shaking、压缩混淆、移除未用代码。
  • UI 库按需引入，避免整包引入。
  • 图片用 WebP/AVIF，配合 srcset、sizes，首屏外懒加载；首屏 LCP 图不要懒加载，可 preload。
  • 字体用 woff2、子集化、font-display: swap，关键字体可 preload。
  • 视频用流媒体、预加载元数据、懒加载。

关键渲染路径

  • 内联关键 CSS，非关键 CSS 异步加载。
  • JS 用 defer/async/type=module，避免阻塞解析。
  • 使用 SSR、SSG、ISR、流式 SSR 或边缘渲染，减少首屏白屏。
  • 骨架屏提升感知性能，但不能替代真实指标。

3. 渲染与运行时优化

  • 减少重排重绘：批量 DOM 操作，用 transform/opacity 做动画，必要时 will-change。
  • 避免强制同步布局：不要在读取布局属性后立刻写样式。
  • 拆长任务：Web Worker、时间切片、requestIdleCallback、requestAnimationFrame。
  • 事件用防抖、节流、事件委托。
  • 长列表用虚拟滚动、分页、无限加载。
  • 框架层：React 用 memo、useMemo、useCallback、合理 key、Suspense；Vue 用 v-show/v-if、keep-alive、异步组件。
  • 及时解绑事件、取消定时器/请求，避免内存泄漏。
  • 注意 hydration 成本，避免 SSR 后大量同步 JS 阻塞主线程。

4. 工程与监控

  • 用 Webpack Bundle Analyzer、Vite 分析产物体积。
  • 配 splitChunks、按需 polyfill、合理 browserslist。
  • 实验室工具：Lighthouse、Performance 面板。
  • 真实用户监控：Web Vitals、PerformanceObserver、RUM、Sentry。
  • 建立性能预算，比如首屏 JS < 170KB、LCP < 2.5s。

5. 高收益优先级

  1. CDN + 缓存 + 压缩。
  2. 图片/字体优化，尤其是 LCP 资源。
  3. 减少首屏 JS，代码分割和懒加载。
  4. SSR/预渲染/流式渲染。
  5. 拆长任务，优化 INP。
  6. 治理 CLS：设置宽高、预留位置、字体 fallback。

前端性能优化不是单纯“压缩代码”，而是从网络、资源、渲染、运行时到监控的系统工程，核心是减少关键路径资源体积和主线程阻塞。
