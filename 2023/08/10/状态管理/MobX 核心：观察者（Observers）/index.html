MobX 核心：观察者（Observers）

MobX 核心：观察者（Observers）

1. 定义

观察者是所有对可观察状态变化做出响应的消费者。它们是连接“数据”与“副作用（UI渲染/日志/请求）”的桥梁。

2. 分类与对比

通用反应式 API（无框架依赖）

API 首次执行 触发条件 生命周期 最佳场景
autorun 立即执行 追踪的任何依赖变化 持续（手动dispose） 初始化同步、日志打印、本地存储同步
reaction 惰性（首次不执行） 追踪函数返回值发生变化时 持续（手动dispose） 依赖变化后发请求、表单校验（精确触发）
when 惰性 条件表达式首次变为true 一次性（触发后自动销毁） 等待数据加载完成、路由守卫拦截

核心要诀：

  • autorun：立即执行一次，以后每次变都执行。
  • reaction：只有依赖值发生变化时才执行，且值不同才执行。
  • when：等判断条件为 true 时执行，就执行一次然后自动销毁。

React 专属观察者（连接 UI）

  • observer HOC：包裹整个组件，使组件在依赖状态变化时自动重渲染。
  • Observer 组件：细粒度控制，只让 JSX 中的特定区域响应式。
  • useObserver Hook：在函数组件内部实现细粒度响应。

3. 生命周期与内存管理（致命陷阱）

黄金法则：在 SPA（单页应用）组件内创建的 autorun 或 reaction，必须在组件卸载时调用 dispose()。

  • 为什么？ 组件卸载后，DOM 被移除，但 Store 的 observers 列表依然强引用着这些回调函数，导致组件无法被垃圾回收（内存泄漏），且状态变化时仍会触发已卸载组件的 setState 报错。

  • 例外：挂载在 window 上或应用入口（App.tsx）的全局监听，可以忽略 dispose（伴随应用生命周期）。

4. 底层依赖追踪机制（怎么知道当前在监听？）

MobX 通过**全局指针（globalState.trackingDerivation）**管理上下文：

  1. 入栈：当 autorun 或 reaction 执行前，将自身放入全局指针。
  2. 读取：当函数内读取 observable 属性时，属性通过检查全局指针，将当前观察者存入自己的 observers 列表（建立双向连接）。
  3. 出栈：函数执行完毕，全局指针置空（防止幽灵依赖，确保只记录本次执行路径下的依赖）。
  4. 删除：只有主动调用 dispose() 或 when 自动触发，才会从 observers 列表中移除记录。出栈时不会删除记录，因为监听契约需要长期生效。
