1. 什么是 polyfill

polyfill 就是“垫片”或“补丁代码”：用一段 JS 代码，为旧浏览器或旧运行环境补上它们原生不支持的新 API，让新代码在旧环境里也能运行。

2. polyfill 解决什么问题

polyfill 主要补的是 运行时 API，不是新语法。

类型 解决的问题 例子 谁负责
语法转译 新语法旧环境不认识 箭头函数、let/const、可选链 ?.、async/await Babel
polyfill 新 API 旧环境没有 Promise、Array.from、Object.assign、fetch core-js 等

比如：

Babel 可以把 const 转成 var，但转不了 includes。
因为 includes 是运行时 API，旧浏览器里根本没有这个方法。
这时候就需要 polyfill 补上 Array.prototype.includes。

常见组合：

  • Babel：转译新语法。
  • core-js / polyfill：补缺失的 API。

3. 常见 polyfill 库

大多数人不会自己写 polyfill，而是用现成库：

  • core-js：最全面、最常用的 polyfill 库，补 Promise、Array.from、Object.assign、Symbol、Map/Set 等。
  • regenerator-runtime：补 async/await、generator 相关运行时。
  • whatwg-fetch：补 fetch。
  • promise-polyfill：专门补 Promise。
  • es5-shim / es6-shim：补 ES5、ES6 的一些 API。

4. polyfill 一般是谁做

polyfill 一般不是浏览器厂商做的，而是由开源社区、工具链和库作者实现，应用开发者负责按需引入和配置。

4.1 开源 polyfill 库

代表是 core-js，作者是 Denis Pushkalov，靠社区和赞助维护。
其他还有 regenerator-runtime、whatwg-fetch、promise-polyfill 等。

4.2 工具链自动引入

现代前端项目里，polyfill 往往由构建工具自动引入：

  • Babel + @babel/preset-env：根据目标浏览器，自动决定需要哪些 polyfill。
  • 配合 core-js 和 regenerator-runtime，可以按需引入。

4.3 框架和脚手架

很多框架/脚手架会默认帮你配好：

  • Create React App
  • Vue CLI / Vite
  • Next.js
  • Angular CLI

它们内部通常已经集成了 Babel + core-js，开发者一般不用手动写 polyfill。

4.4 CDN 服务

以前流行过 polyfill.io：根据浏览器 UA 动态返回需要的 polyfill。

但 2024 年 polyfill.io 域名被转手后出过供应链安全事件，被注入恶意代码，影响了很多网站。所以现在一般不建议直接引用公共 CDN 的 polyfill 服务。

4.6 为什么不是浏览器厂商做？

浏览器厂商只会在 新版本浏览器 里实现新标准。
旧版本浏览器不会回头补新 API，所以只能靠社区写 polyfill 来兼容旧环境。

5. 无法 polyfill 的情况：Proxy

结合前面 Object.defineProperty 和 Proxy 的区别，这里很关键：

Proxy 无法被真正 polyfill。

原因：

  • Proxy 不是普通 API，而是 JS 引擎层面的元编程能力。
  • 它能拦截对象的基本操作：
    • 读取属性 get
    • 设置属性 set
    • in 操作符 has
    • delete 删除 deleteProperty
    • Object.keys ownKeys
    • 函数调用 apply
    • new 构造 construct
    • 等等

而 ES5 里根本没有机制去拦截这些底层操作。
Object.defineProperty 只能模拟一部分 get / set，而且必须提前知道属性名，也拦截不了 in、delete、Object.keys、函数调用等。

所以：

有些库叫 proxy-polyfill，但它只能模拟非常有限的一部分功能，不能完整替代原生 Proxy。
所以通常说：Proxy 无法被真正 polyfill。

这也直接影响框架选型：

  • Vue2 用 Object.defineProperty，兼容 IE。
  • Vue3 用 Proxy，不兼容 IE，且无法通过 polyfill 解决。

7. 注意事项与最佳实践

  1. polyfill 补 API，Babel 转语法，两者配合使用。
  2. 优先用 core-js + @babel/preset-env 自动按需引入，不要全量引入。
  3. 用 browserslist 明确目标浏览器，避免引入无用 polyfill。
  4. 不要直接依赖公共 CDN 的 polyfill 服务，尤其 polyfill.io 出过安全事件。
  5. Proxy 无法 polyfill，需要兼容 IE 时不能用 Proxy，只能用 Object.defineProperty。
  6. 复杂 polyfill 不要自己写，规范细节多，容易出错，直接用 core-js 等成熟库。
  7. polyfill 会增加包体积和运行时开销，能不用就不用，目标环境支持就移除。

8. 总结

polyfill 是给旧环境补缺失运行时 API 的垫片代码，主要由 core-js 等开源库和 Babel 工具链实现与引入；它解决 API 缺失，不解决语法问题；而像 Proxy 这种引擎级能力无法被真正 polyfill，所以兼容 IE 时只能用 Object.defineProperty。
