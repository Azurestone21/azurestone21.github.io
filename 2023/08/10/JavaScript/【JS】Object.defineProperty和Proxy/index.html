JS Object.defineProperty和Proxy

Object.defineProperty 是“属性级”劫持，只能针对单个属性定义 getter/setter；Proxy 是“对象级”代理，能拦截整个对象的多种操作。 这也是 Vue2 和 Vue3 响应式原理的核心差异。

对比表格

维度 Object.defineProperty Proxy
版本 ES5 ES6
拦截粒度 单个属性 整个对象
拦截操作 主要是 get / set get、set、has、deleteProperty、ownKeys、apply、construct 等 13 种
新增属性 不能直接监听，需手动再 defineProperty 可以监听
删除属性 不能监听 可以监听 deleteProperty
数组索引/length 不能直接监听，Vue2 需重写数组方法 可以直接监听
in 操作符 不能拦截 可以拦截 has
Object.keys 不能拦截 可以拦截 ownKeys
函数调用/构造 不能拦截 可以拦截 apply / construct
初始化方式 需要遍历对象所有属性，递归定义 直接代理整个对象，访问到嵌套对象时再懒代理
兼容性 IE9+ 不支持 IE，且无法 polyfill
性能 初始化开销大，访问时 getter/setter 开销小 初始化开销小，每次访问有 trap 开销
典型应用 Vue2 响应式 Vue3 响应式

3. 初始化与性能

Object.defineProperty 需要递归遍历对象的所有属性，逐个转换成 getter/setter。如果对象层级很深，初始化开销很大。

Proxy 不需要遍历，直接代理整个对象。只有访问到某个嵌套对象时，才需要递归代理（懒代理）。所以 Vue3 初始化更快。

但 Proxy 每次属性访问都要走 trap，有一定运行时开销。现代 JS 引擎优化后差距不大。

4. 兼容性

  • Object.defineProperty：IE9+ 支持，兼容性好。
  • Proxy：IE 完全不支持，且无法 polyfill。因为 Proxy 拦截的是语言层面的基本操作，无法用 ES5 模拟。

所以如果项目需要兼容 IE，只能用 Object.defineProperty。

为什么说 Proxy 无法 polyfill？

Proxy 不是普通 API，它是 JS 引擎层面的元编程能力。它能拦截对象的基本操作：

  • 读取属性 get
  • 设置属性 set
  • in 操作符 has
  • delete 删除 deleteProperty
  • Object.keys ownKeys
  • 函数调用 apply
  • new 构造 construct
  • 等等

而 ES5 里根本没有机制去拦截这些底层操作。
Object.defineProperty 只能模拟一部分 get / set，而且必须提前知道属性名，也拦截不了 in、delete、Object.keys、函数调用等。

有些库叫 proxy-polyfill，但它只能模拟非常有限的一部分功能，不能完整替代原生 Proxy。
所以通常说：Proxy 无法被真正 polyfill。

总结

  • Object.defineProperty：属性级劫持，兼容性好，但只能监听已有属性的读写，新增/删除/数组变化需要额外处理。Vue2 用它。
  • Proxy：对象级代理，能拦截 13 种操作，天然支持新增、删除、数组、in、Object.keys 等。功能更强，但兼容性差，无法 polyfill。Vue3 用它。

现代项目如果没有 IE 兼容需求，优先用 Proxy；如果需要兼容旧浏览器，只能用 Object.defineProperty。
