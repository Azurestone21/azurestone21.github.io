【JS】防抖和节流

1. 概念

防抖（debounce）

事件触发后，等待 delay 毫秒。如果期间没有再次触发，才执行；如果再次触发，就重新计时。

频繁触发，只执行最后一次（或首次）。

节流（throttle）

固定时间间隔内最多执行一次。无论触发多频繁，都按固定频率执行。

频繁触发，每隔 wait 毫秒执行一次。

2. 区别

维度 防抖 节流
执行时机 停止触发后 delay 执行 固定间隔执行
执行次数 频繁触发只执行一次 固定频率执行多次
关注点 最终状态 过程均匀
比喻 电梯等人 水龙头滴水
典型场景 搜索、resize、表单验证 滚动、拖拽、mousemove

5. 应用场景

防抖

  • 搜索框输入联想
  • 表单验证
  • 窗口 resize 结束后计算布局
  • 按钮点击防重复提交
  • 自动保存草稿

节流

  • 滚动加载更多
  • 滚动监听、吸顶效果
  • mousemove 绘制、拖拽
  • 游戏循环、动画
  • resize 节流

6. 注意事项

  1. this 和参数
    包装函数内部要用 fn.apply(context, args)，否则丢失 this 和参数。

  2. 不要用箭头函数做包装函数

    普通函数才能拿到调用时的 this。

  3. 返回值
    防抖和节流通常是异步执行，无法直接返回原函数结果。需要返回值时可以用 Promise 包装。

  4. 取消
    组件卸载、页面切换时调用 cancel()，避免定时器泄漏。

  5. 首次/最后一次执行

    • 防抖：immediate 控制首次是否执行。
    • 节流：时间戳版首次立即执行，定时器版首次延迟执行。
    • 需要“首次立即 + 最后一次也执行”，用完整版节流或 lodash。

  6. lodash 可用

7. 选择建议

  • 只关心最后一次结果 → 用防抖。
  • 需要按固定频率均匀执行 → 用节流。
  • 既要首次立即，又要最后一次 → 节流配置 leading + trailing。
  • 搜索输入、按钮提交 → 防抖。
  • 滚动、拖拽、mousemove → 节流。

防抖是“等你停下来再执行”，节流是“每隔一段时间执行一次”。
