【JS】call、apply、bind的实现原理

call、apply、bind 的实现原理是前端面试的高频考点。理解它们的关键在于搞清楚 「如何让函数在执行时 this 指向指定对象」。下面从原理到手写实现，逐层拆解。

一、核心原理一句话

把函数临时挂到目标对象上，作为该对象的方法调用，这样 this 自然指向目标对象，调用完再删掉。

这是 call 和 apply 的通用套路。bind 在此基础上还要返回新函数、支持参数预设、处理 new 调用。

七、V8 引擎的实际实现思路

虽然手写版能工作，但 V8 的实现更复杂，主要优化点：

1. call / apply：不真正挂载属性

手写版会往 context 上挂临时属性，V8 不会。它通过内部机制直接设置 this 绑定，避免属性操作开销。

2. apply 对数组的特殊优化

历史上 apply 传数组在某些引擎有专门优化（如展开数组调用），但现代引擎中 call 和 apply 性能差异可忽略。

3. bind 的 BoundFunction

V8 内部有专门的 BoundFunction 类型，存储：

  • 目标函数
  • 绑定的 this
  • 预设参数

调用时直接组合参数执行，比手写闭包更高效。

4. 严格模式的影响

严格模式下，call(null) 保持 null；非严格模式下会替换为全局对象。V8 根据函数是否严格模式走不同路径。

八、常见面试追问

追问 1：「为什么 call 能改变 this？」

因为它把函数挂到目标对象上作为方法调用，触发隐式绑定规则，this 自然指向目标对象。

追问 2：「手写 call 为什么要用 Symbol？」

避免属性名冲突。如果目标对象本来就有同名属性，会被覆盖；用 Symbol 保证 key 唯一。也可以用随机字符串或 delete 前先保存原值。

追问 3：「bind 返回的函数用 new 调用，this 是谁？」

指向新创建的对象，不是 bind 时传入的 context。因为 new 绑定优先级高于显式绑定。实现上用 this instanceof bound 或 new.target 判断。

追问 4：「bind 为什么要维护原型链？」

因为 new bound() 创建的对象应该继承 fn.prototype，否则访问不到原函数原型上的方法。用 bound.prototype = Object.create(fn.prototype) 建立继承关系。

追问 5：「bind 多次调用，this 以哪个为准？」

第一次。因为 bind 是硬绑定，第一次绑定后 this 被永久固定，后续 bind 无法覆盖。

追问 6：「箭头函数能用手写的 call/apply/bind 改变 this 吗？」

不能。箭头函数没有自己的 this，它继承定义时外层的 this。手写实现里的 context[key] = this 对箭头函数无效，因为箭头函数的 this 不参与绑定。

追问 7：「apply 和展开运算符 ... 有什么区别？」

功能上类似，都能展开数组传参。区别：

  • apply 是方法调用，能同时指定 this。
  • ... 只是展开语法，不涉及 this。
  • apply 能接收类数组（如 arguments），... 需要可迭代对象。
