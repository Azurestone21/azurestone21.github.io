TCPIP协议

TCPIP协议

TCP/IP 不是单个协议，而是一整套互联网通信协议族，是互联网的基石。核心思想是“分层”：每层各司其职，上层依赖下层，最终把数据从一台机器送到另一台机器上的某个应用。

1. TCP/IP 四层模型

层次 作用 常见协议
应用层 面向具体应用，定义数据格式和交互规则 HTTP/HTTPS、DNS、SMTP、FTP、SSH、DHCP
传输层 端到端通信，区分不同应用 TCP、UDP
网际层 逻辑寻址和路由，把数据包送到目标网络 IP、ICMP、ARP、IGMP
网络接口层 在物理网络上传输帧 以太网、Wi-Fi、PPP

2. 核心协议

IP 协议

负责“送到哪”。无连接、尽力而为，不保证可靠。IPv4 是 32 位地址，IPv6 是 128 位地址。负责寻址、路由、分片等。

TCP 协议（传输控制协议）

负责“可靠地送”。面向连接、可靠、有序、全双工、字节流。通过序列号、确认应答、超时重传、校验和、滑动窗口、拥塞控制等保证可靠性。

UDP 协议（用户数据报协议）

负责“快速地送”。无连接、不保证可靠和顺序，首部小，适合 DNS、音视频、游戏等实时场景。

ICMP 协议（互联网控制消息协议）

用于网络诊断和错误报告，比如 ping、traceroute。

ARP 协议（地址解析协议）

把 IP 地址解析成 MAC 地址，主要用于 IPv4 局域网。

应用层协议

HTTP 浏览网页，DNS 域名解析，SMTP 发邮件，FTP 传文件，SSH 远程登录，DHCP 自动分配 IP 等。

3. TCP 的关键过程

三次握手建立连接：

  1. 客户端发 SYN
  2. 服务器回 SYN + ACK
  3. 客户端再发 ACK

目的是同步双方序列号，确认双方收发能力正常。

四次挥手断开连接：

  1. 主动方发 FIN
  2. 被动方回 ACK
  3. 被动方发 FIN
  4. 主动方回 ACK

因为 TCP 是全双工，双方需要分别关闭自己的发送方向。主动关闭方最后会进入 TIME_WAIT，等待 2MSL，确保对方能收到最后的 ACK，并让旧连接的数据包在网络中消失。

4. TCP 与 UDP 对比

特性 TCP UDP
连接 面向连接 无连接
可靠性 可靠，有确认重传 不可靠，不保证到达
顺序 保证有序 不保证
速度 较慢，开销大 较快，开销小
首部 至少 20 字节 8 字节
场景 网页、文件、邮件 DNS、视频、游戏

5. 数据传输过程

发送时，数据会逐层封装：

应用数据 → 加 TCP/UDP 头变成传输层报文 → 加 IP 头变成 IP 数据包 → 加帧头帧尾变成数据帧 → 转成比特在物理网络传输。

接收时反过来逐层解封装，最终交给目标应用。

总结

TCP/IP 通过分层和协议协作，实现了不同网络、不同设备之间的互联。
一句话概括：IP 负责把数据包送到目标主机，TCP/UDP 负责在主机上的应用之间传输数据，应用层协议负责具体业务。
