HTTP 和 HTTPS

HTTP 和 HTTPS

1. 概述

  • HTTP：HyperText Transfer Protocol，超文本传输协议，浏览器和服务器之间传网页、图片、API 数据的应用层协议，默认端口 80，明文传输。
  • HTTPS：Hypertext Transfer Protocol Secure：超文本传输安全协议，HTTP over TLS/SSL，在 HTTP 和传输层之间加了一层 TLS，默认端口 443，提供加密、完整性校验和身份认证。

HTTPS 不是独立的新协议，本质是 HTTP + TLS。

2. HTTP 基础

2.1 特点

  • 应用层协议，常用于浏览器、App、API 通信。
  • HTTP/1.1、HTTP/2 基于 TCP；HTTP/3 基于 QUIC/UDP。
  • 默认端口：80。
  • 传统 HTTP 是明文传输，不加密、不验证服务器身份、不能防篡改。
  • 优点：简单、开销小、兼容性好。
  • 缺点：容易被窃听、篡改、冒充。

2.2 常见方法

方法 作用
GET 获取资源
POST 提交数据
PUT 更新资源
DELETE 删除资源
HEAD 只获取响应头
PATCH 部分更新

2.3 常见状态码

状态码 含义
200 成功
301 / 302 重定向
304 资源未修改，走缓存
400 请求错误
401 未认证
403 无权限
404 资源不存在
500 服务器内部错误
502 网关错误
503 服务不可用

3. HTTPS 基础

3.1 定义

HTTPS = HTTP + TLS，旧称 HTTP + SSL，现在实际使用的是 TLS。

默认端口：443。

3.2 三大安全能力

  1. 机密性：数据加密，抓包也看不懂。
  2. 完整性：数据被篡改能被发现。
  3. 身份认证：通过 CA 证书验证服务器域名身份。

这三大安全能力依靠 TLS 完成**。**

TLS：Transport Layer Security，传输层安全协议。它位于 应用层和传输层之间 ，为 HTTP、SMTP、FTP 等应用层协议提供一条加密、防篡改、可验证身份的安全通道。

TLS 本身不负责传输，它依赖下层 TCP/UDP 来传数据，自己负责“把数据变安全”。

3.3 加密方式

  • 非对称加密：用于 TLS 握手、身份认证、密钥交换。
  • 对称加密：用于后续 HTTP 数据传输，因为速度更快。
  • 证书：由可信 CA 签发，包含公钥、域名、有效期、签名等信息。

4. HTTP 与 HTTPS 对比

对比项 HTTP HTTPS
安全性 明文 加密、防篡改、认证
默认端口 80 443
传输层 TCP / QUIC TLS over TCP / QUIC
证书 不需要 需要 CA 证书
身份验证 无 有
性能 无 TLS 开销 有握手和加解密开销，现代优化后影响小
浏览器显示 标记“不安全” 显示安全锁
SEO 不占优 通常有加分
现代 API 部分可用 HTTP/2、Service Worker、摄像头等常要求 HTTPS

5. HTTPS 工作流程（以 TLS 1.2 为例）

TLS 1.2 完整握手通常需要 2-RTT。下面用 Mermaid 时序图和 ASCII 简图表示。

5.2 阶段说明

阶段 做什么
TCP 三次握手 建立可靠传输连接；HTTP/3 则改为 QUIC 握手
ClientHello 客户端发送支持的 TLS 版本、密码套件、随机数、SNI 等
ServerHello 服务器选定 TLS 版本、密码套件、随机数、会话 ID
Certificate 服务器发送证书链，供客户端验证身份
ServerKeyExchange 使用 ECDHE 等算法时发送密钥交换参数，并用私钥签名
ServerHelloDone 服务器握手第一阶段结束
证书验证 客户端检查 CA 签名、域名匹配、有效期、吊销状态
ClientKeyExchange 客户端发送密钥交换材料，双方算出 pre-master secret
ChangeCipherSpec 通知对方：后续消息开始用协商好的密钥加密
Finished 第一个加密握手消息，用于校验整个握手过程
加密 HTTP 之后 HTTP 请求和响应都走 TLS 加密通道
关闭连接 发送 close_notify，再关闭 TCP/QUIC 连接

5.3 TLS 1.3 的差异

对比项 TLS 1.2 TLS 1.3
完整握手延迟 2-RTT 1-RTT
会话恢复 通常 1-RTT 0-RTT
握手流程 消息更多 大幅简化
安全性 可配置旧算法 只保留现代安全算法
HTTPS 性能 较好 更快、更安全

一句话：TLS 1.2 完整握手是 2-RTT；TLS 1.3 压缩到 1-RTT，会话恢复可 0-RTT。

6.2 各版本要点

  • HTTP/0.9：只有 GET，只能返回 HTML，无请求头、响应头。
  • HTTP/1.0：引入请求头、响应头、状态码、多种文件格式；默认短连接，效率低。
  • HTTP/1.1：默认持久连接，减少 TCP 建连开销；但存在应用层队头阻塞。
  • HTTP/2：二进制分帧、多路复用、HPACK 头部压缩、服务器推送；解决了应用层队头阻塞，但 TCP 丢包仍会阻塞所有流。
  • HTTP/3：基于 QUIC/UDP，独立流控制，彻底解决队头阻塞；握手更快，支持连接迁移。

6.3 当前使用情况

  • HTTP/2 仍是当前主力，大量网站和 CDN 默认启用。
  • HTTP/3 增长很快，尤其在 CDN、移动端、海外服务中普及。
  • 内网微服务等场景，HTTP/2 仍很务实；对外服务可通过 CDN 逐步启用 HTTP/3。

7. 常见误区

  • HTTPS 不等于网站绝对安全。它只保护传输过程，服务器被入侵、XSS、SQL 注入、钓鱼网站仍可能发生。
  • HTTPS 不是新协议，本质是 HTTP 跑在 TLS 上。
  • 证书只证明域名身份，不证明网站内容一定可信。
  • HTTP/3 不是简单的 HTTP over UDP，而是 HTTP over QUIC，QUIC 内建 TLS 1.3。
  • HTTPS 也会泄露部分元数据，如 IP、端口；ECH 等技术可缓解 SNI 暴露问题。

8. 总结

  • HTTP：明文、简单、默认 80。
  • HTTPS：HTTP + TLS，加密、防篡改、身份认证，默认 443。
  • HTTPS 工作流程以 TLS 1.2 为例：TCP 握手 → ClientHello/ServerHello → 证书验证 → 密钥协商 → ChangeCipherSpec → Finished → 加密 HTTP 通信。
  • HTTP 版本演进主线：减少延迟、提升并发、解决队头阻塞。
  • 现代 Web 建议：全站 HTTPS，HTTP 重定向到 HTTPS；对外服务可逐步启用 HTTP/2 和 HTTP/3。
