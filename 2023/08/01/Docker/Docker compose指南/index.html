Docker compose 指南

什么是 Docker Compose？

简单来说，Docker Compose 是一个用于定义和运行多容器 Docker 应用程序的工具。它让你能够通过一个统一的配置文件（docker-compose.yml）来声明应用所需的所有服务、网络和存储卷，然后用一条命令完成所有容器的启动、停止和重建。

如果把 Docker 比作“单兵作战工具”，那么 Docker Compose 就是“指挥官”，它能协调多个容器协同工作，让复杂的分布式应用本地运行变得像喝水一样简单。

为什么需要它？

痛点回顾

Compose 的价值

  • 环境一致性：docker-compose.yml 就是你的“基础设施即代码”，开发、测试、预发布环境可以使用完全相同的配置，彻底终结“在我电脑上明明能跑啊”的甩锅大会。
  • 极简操作：将复杂的多步启动简化为 docker compose up，停止和清理用 docker compose down，让新手也能轻松上手。
  • 团队协作：配置文件可以纳入 Git 版本管理，团队成员拉取代码后一条命令即可启动全部依赖，极大降低了新成员的上手成本。
  • 依赖管理：Compose 支持服务依赖声明（depends_on），能自动控制启动顺序，比如数据库启动后再启动应用服务。

核心概念详解

服务（Services）

一个服务对应一个容器（或一组相同配置的容器），在 docker-compose.yml 中定义。常见的配置项包括：

  • image：使用的镜像名
  • build：从 Dockerfile 构建
  • ports：端口映射（宿主机:容器）
  • volumes：数据卷挂载
  • environment / env_file：环境变量
  • networks：指定加入的网络
  • depends_on：依赖的其他服务

网络（Networks）

默认情况下，Compose 会为项目创建一个独立的网络，所有服务自动加入，可以通过服务名互相访问（如示例中 web 通过 redis 这个主机名连接 Redis）。你也可以自定义网络，比如实现隔离或连接外部网络。

存储卷（Volumes）

用于持久化数据或共享代码。推荐使用命名卷（volumes: 顶层定义）来管理数据，避免数据丢失。

常用命令速查

命令 说明
docker compose up 启动所有服务（添加-d 后台运行）
docker compose down 停止并删除容器、网络（默认不删除卷，加-v 删除卷）
docker compose ps 查看当前项目的容器状态
docker compose logs -f 跟踪所有服务的日志输出
docker compose exec <service> <command> 在运行中的服务内执行命令（如docker compose exec web bash）
docker compose build 重新构建服务的镜像
docker compose pull 拉取所有服务的最新镜像
docker compose restart 重启所有服务
docker compose config 验证并查看 Compose 文件的最终配置（合并环境变量后）

进阶技巧与最佳实践

1. 使用 .env 文件管理敏感信息

在 Compose 文件所在目录创建 .env 文件，写入 MYSQL_PASSWORD=123456，然后在 docker-compose.yml 中通过 ${MYSQL_PASSWORD} 引用，避免将密码写死在配置文件中。

2. 多环境配置（开发/生产）

3. 控制启动顺序

虽然 depends_on 只能保证启动顺序，但不能等待服务完全就绪。更可靠的方式是在应用代码中添加重试逻辑，或使用 wait-for-it 等脚本。

4. 清理未使用的资源

定期执行 docker system prune 来释放磁盘空间，尤其当频繁构建和启动 Compose 项目时。

总结

Docker Compose 并非复杂的技术，它本质上是一个编排工具，将声明式配置和自动化执行结合起来，让多容器应用的管理变得轻松、可靠。
