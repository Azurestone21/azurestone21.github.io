什么是 Dockerfile？

Dockerfile 是一个包含一系列指令的纯文本文件，用于自动化构建 Docker 镜像。它就像一张自动化的“安装说明书”——告诉 Docker 如何一步步地把你的应用打包成一个可移植的镜像。

最大特点：文件名为 Dockerfile（无后缀），通过 docker build 命令执行：

  • -t：指定镜像名称和标签
  • .：指定构建上下文（通常是 Dockerfile 所在目录）

核心指令详解

FROM —— 指定基础镜像

  • FROM 是 Dockerfile 的第一条指令，指定基础镜像
  • node:20.18.0 选择了 Node.js 的特定版本（而非 latest），确保环境一致性
  • as build 为这个阶段命名为 build，这是多阶段构建的用法（下文会详解）

最佳实践：始终指定明确版本号，避免使用 latest。

WORKDIR —— 设置工作目录

相当于在容器内执行 mkdir -p /usr/src/app && cd /usr/src/app。后续的 COPY、RUN、CMD 都会以此目录为基准。

最佳实践：使用绝对路径，不要把 WORKDIR 放在 RUN 里用 cd 代替。

COPY —— 复制文件

  • 第一行：只复制 package.json（利用构建缓存的关键）
  • 第二行：在依赖安装完成后，再复制全部源代码

为什么分两步？ 因为 package.json 的改动频率远低于源代码。只要 package.json 没变，Docker 就会复用缓存的依赖安装层，构建速度飞起。

RUN —— 执行构建命令

  • 每一条 RUN 都会创建一个新的镜像层
  • 这里用 && 将多个命令串联在一条 RUN 中，减少层数
  • 先设置 npm 镜像源（国内加速），再全局安装 pnpm，最后安装项目依赖
  • 第一行打印版本信息（便于调试）
  • 第二行执行 Taro 项目的构建命令，${PROJECT_ENV} 是构建参数
  • 进入 ci 目录安装依赖
  • 执行 CI 脚本，上传构建产物或执行后续流程
  • export no_proxy=servicewechat.com 绕过代理，确保微信相关服务可访问

ARG —— 构建参数

ARG 用于定义在 docker build 时传入的变量：

这些参数不会保留在最终镜像的环境变量中（除非用 ENV 转发）。

ENV —— 环境变量

ENV 定义的变量会保留在镜像中，在容器运行时依然可用。这里将构建参数 VERSION 转存为环境变量 TARO_APP_VERSION，供应用在运行时读取。

最佳实践：ARG 用于构建时传参，ENV 用于运行时配置。如需在运行时使用构建参数，用 ENV 做一次转发。

深入理解分层构建与缓存

Docker 镜像由多个只读层堆叠而成。Dockerfile 中的每条指令都生成一个新层。构建时，Docker 会检查每一层是否变化：

  • 如果没变化 → 直接复用缓存（秒过）
  • 如果变化 → 该层及后续所有层重新构建

常用指令速查表

指令 用途 示例
FROM 指定基础镜像 FROM node:20.18.0
WORKDIR 设置工作目录 WORKDIR /app
COPY 复制文件/目录 COPY package.json ./
ADD 复制 + 自动解压 + URL 下载 ADD app.tar.gz /
RUN 构建时执行命令 RUN npm install
ARG 构建时传入参数 ARG VERSION

EXPOSE 声明容器监听端口（仅声明） EXPOSE 3000

最佳实践总结

基于这份 Dockerfile，我们总结出 5 条核心原则：

1. 利用缓存，先拷依赖文件

2. 合并 RUN 命令，减少层数

合并后镜像更小，构建更快。

3. 使用 ARG 实现参数化构建

同一个 Dockerfile 可构建不同环境（dev/test/prod）。

4. 用 ENV 转发 ARG，实现运行时可用

这样应用在容器内可以通过 process.env.TARO_APP_VERSION 读取版本号。

进阶优化建议

针对当前的 Taro Dockerfile，还可以进一步优化：

优化一：使用 pnpm 官方镜像（更小更快）

优化二：拆分 CI 步骤为独立阶段（提高可读性）

优化三：将敏感信息通过环境变量注入，而非 ARG

ARG 会在镜像历史中暴露（docker history 可见），敏感信息（如密钥）应通过运行时环境变量或 Docker Secret 传递。

总结

Dockerfile 是 Docker 生态中最基础也最重要的文件之一。一个好的 Dockerfile 应该具备：

  • 可读性：清晰的指令顺序和注释
  • 高效性：充分利用构建缓存
  • 安全性：避免暴露敏感信息
  • 灵活性：通过 ARG/ENV 支持多环境
