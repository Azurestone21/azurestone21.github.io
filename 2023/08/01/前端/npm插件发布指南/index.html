npm插件发布指南

npm 插件发布指南

一、先厘清几个关键概念

概念 含义
"private": true npm 的禁止发布开关。设置后执行 npm publish 会直接报错 EPRIVATE，无法发布到任何 registry。
私有 registry 上的私有包 指发布到 Verdaccio、GitHub Packages 等私有仓库的包。要发布，private 必须为 false 或删除。
--access public 只对scoped 包（如 @scope/pkg）有意义，用于将包设为公开。非 scoped 包默认就是公开。
npm pack --dry-run 只预览即将打包的文件，不生成 .tgz，也不上传。
npm publish 自动打包当前目录并上传，不需要先手动 npm pack。

二、发布前准备

1. 登录 npm

按提示输入用户名、密码、邮箱。如果开启 2FA，还需输入一次性验证码。

2. 初始化项目

按提示填写信息，或手动编辑 package.json。

3. 配置 package.json

关键字段：

说明：

  • name：包名，必须唯一。可用 npm view <包名> 检查是否被占用。
  • version：遵循语义化版本 主版本.次版本.修订号。
  • main：入口文件。
  • types：TypeScript 类型声明入口。
  • files：白名单，只发布这里列出的文件和目录。不设置可能导致源码、测试文件、敏感配置被上传。
  • prepublishOnly：发布前自动执行构建。
  • publishConfig.access：可替代命令行 --access public。

4. 确保 private 不为 true

要发布，必须删除 "private": true 或改为 "private": false。

四、发布到公共 npm

非 Scoped 包（如 my-plugin）

非 scoped 包默认公开，--access public 可加可不加，效果相同。

Scoped 包（如 @yourname/my-plugin）

Scoped 包默认是 restricted（私有）。免费账户不设置 --access public 会发布失败；付费账户会发布为私有包。要发布公共包，必须加 --access public。

七、团队内部使用但不发布到 Registry

如果只是内部使用，不想发布到任何 registry，可以保留 "private": true，然后通过以下方式使用：

1. npm link（本地实时调试）

2. npm pack 生成 tarball 分发

3. 通过 Git 仓库安装

八、常见错误与处理

错误码 原因 解决
EPRIVATE package.json 中有 "private": true 删除或改为"private": false
E402 Scoped 包未加--access public，且账户无权创建私有包 加--access public
403 Forbidden 包名已被占用，或无权限发布 更换唯一包名，或检查账户权限
401 Unauthorized 登录凭证无效 重新npm login

九、发布速查清单

  1. 确认 package.json 中没有 "private": true。
  2. 配置 files 白名单，避免上传敏感文件。
  3. 运行 npm pack --dry-run 检查打包内容。
  4. 执行 npm version patch/minor/major 更新版本。
  5. 公共包：
    • 非 scoped：npm publish
    • scoped：npm publish --access public
  6. 私有 registry：配置 .npmrc 和 publishConfig，登录后 npm publish。
  7. 发布后可在 npm 或私有 registry 页面确认。

十、关键要点回顾

  • npm publish 自己会打包上传，不需要先 npm pack。
  • npm pack --dry-run 只预览，不生成文件。
  • "private": true 是禁止发布，不是私有发布。
  • --access public 只对 scoped 包必要。
  • npm version patch 会改 package.json 的 version，默认还会 Git 提交和打标签。
  • 私有包发布到私有 registry，也必须移除 "private": true。
