【Web API】DOM——文档对象模型

DOM 是什么？一篇讲透文档对象模型

DOM，全称 Document Object Model，文档对象模型。它是浏览器把 HTML 或 XML 文档解析后，在内存中构建的一棵节点树，并提供给脚本操作这棵树的编程接口。

一句话理解：HTML 是文本，DOM 是浏览器读出来的“对象树”，JavaScript 通过这棵树来读写页面。

DOM 不是 JavaScript 语言的一部分，而是一套与语言无关的 Web API。浏览器用 JavaScript 实现它，我们才能在 JS 里通过 document 操作页面。

六、性能：为什么直接操作 DOM 要谨慎

DOM 操作本身不慢，慢的是它可能触发回流和重绘。

  • 回流 / 重排：元素几何属性变化，如宽高、位置、display。浏览器需要重新计算布局。
  • 重绘：外观变化，如颜色、背景、阴影。布局不变。

回流一定引起重绘，重绘不一定引起回流。

常见优化：

  1. 批量修改 DOM，不要频繁读写交替。
  2. 使用 DocumentFragment 或离线节点。
  3. 读写分离：先集中读 offsetWidth，再集中写样式。
  4. 用 class 切换样式，而不是逐条改 style。
  5. 用事件委托减少监听器。
  6. 动画优先用 requestAnimationFrame 或 CSS transform / opacity。
  7. 滚动监听加 passive: true。

七、DOM 与 BOM、虚拟 DOM 的关系

DOM 管文档内容，入口是 document。
BOM 管浏览器窗口和浏览器能力，核心是 window，包括 location、navigator、history、screen 等。

document 本身也是 window 的属性，所以两者有包含关系，但职责不同。

虚拟 DOM 不是真实 DOM 的替代品，而是用 JavaScript 对象描述 UI 结构。React、Vue 等框架通过虚拟 DOM 做 diff，算出最小变更，再批量更新真实 DOM。

它解决的核心问题不是“真实 DOM 一定慢”，而是：

  • 让开发者用声明式方式描述 UI
  • 减少手动 DOM 操作和状态同步成本
  • 在复杂应用中提供更可控的更新策略

即使使用框架，最终仍然会落到真实 DOM，只是操作时机和方式被框架封装了。

另外，Web Components 中的 Shadow DOM 提供了 DOM 和样式的封装能力，也是现代 DOM 体系的一部分。

总结

DOM 是浏览器对文档的抽象，是一棵可编程的节点树。理解 DOM，重点掌握：

  • DOM 是 Web API，不是 JavaScript 语法本身
