CSS 命名规范——BEM

BEM 是一种 CSS 类名命名规范（方法论），全称 Block-Element-Modifier（块-元素-修饰符）。它通过统一的命名约定，让类名自解释、无冲突、优先级扁平，从而解决大型项目里 CSS 难以维护的问题。

三个核心概念

概念 含义 命名格式 示例
Block 块 独立的功能单元/组件 block .card、.menu、.button
Element 元素 块内部的组成部分，依赖块存在 block__element .card__title、.menu__item
Modifier 修饰符 块或元素的状态/变体 block--modifier 或 block__element--modifier .button--primary、.card__title--large

分隔符约定（最常见的一种）：

  • __ 双下划线连接 块 与 元素
  • -- 双连字符连接 修饰符

BEM 的核心原则

  1. 类名即结构：看类名就知道它属于哪个组件、是什么角色、处于什么状态。
  2. 不依赖标签选择器和后代选择器：所有样式都通过类名命中，权重统一为 (0,1,0)。
  3. 元素不能脱离块使用：.card__title 只在 .card 内部有意义。
  4. 元素之间不嵌套命名：不写 .card__header__title，而是把 header 也当成块，或用 .card__title 直接表达。
  5. 修饰符只改必要属性：基于基础类做小幅调整，不重写整套样式。

优缺点

优点：

  • 权重扁平，几乎不用 !important，样式易覆盖。
  • 类名自解释，团队协作和重构更安全。
  • 组件化思维，天然契合 React/Vue 等组件开发。
  • 全局作用域下也不会命名冲突。

缺点：

  • 类名冗长：card__title--large 读起来啰嗦。
  • HTML 中类名较多，视觉噪音大。
  • 小项目里显得”过度设计”。
  • 严格 BEM 不鼓励用标签/后代选择器，有人觉得不够灵活。

总结

BEM 就是用 block__element--modifier 这种固定格式给类名起名，让每个类名只属于一个组件、权重都保持扁平，从而写出不冲突、易维护、易覆盖的 CSS。 它不强制代码语法，而是一套团队约定；大项目收益最大，小项目可按需简化。
