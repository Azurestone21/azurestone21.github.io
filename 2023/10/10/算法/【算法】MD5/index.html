MD5 是什么？

MD5（Message Digest Algorithm 5）是一种哈希/摘要算法，不是加密算法。它把任意长度的输入，计算成固定 128 位的输出，通常写成 32 位十六进制字符串，例如：

核心特点

  • 固定长度：不管输入多大，输出都是 128 位。
  • 确定性：同一输入永远得到同一结果。
  • 单向性：理论上不能从摘要反推原文。
  • 雪崩效应：输入改一点，输出差异很大。
  • 速度快：适合做校验、缓存键、去重。
  • 已不安全：存在严重碰撞问题，不能用于安全场景。

为什么说 MD5 不安全？

  1. 碰撞攻击：不同内容可以算出相同 MD5。2004 年王小云团队已证明可高效构造碰撞，后来实际碰撞证书也出现过。
  2. 彩虹表：MD5 无盐时，常见密码可直接查表还原。
  3. 暴力破解快：GPU 每秒可算数十亿次 MD5，弱密码很容易被爆破。
  4. 不能防篡改：攻击者可以同时替换文件和 MD5 值，所以 MD5 校验不能防恶意篡改。

常见用途

  • 文件完整性校验：如下载文件后比对 MD5，但只能防传输错误，不能防恶意替换。
  • 缓存键、去重、短 ID：非安全场景可用。
  • 旧系统密码哈希：非常不推荐，必须加盐，最好迁移到 bcrypt/Argon2。
  • 接口签名：旧系统可能用 MD5 加盐签名，但新系统不推荐。

前端使用 MD5 的典型场景：

  • 文件上传“秒传”：计算文件 MD5 作为唯一标识。
  • 分片上传：计算分片摘要。
  • 缓存键：本地数据索引。
  • 旧接口签名：md5(params + secret)。
  • 密码哈希：错误做法。前端 MD5 后传密码，哈希值等于“等价密码”，攻击者拿到后可重放；加盐也没用，因为盐和算法都在前端可见。

注意

浏览器原生 Web Crypto API 不支持 MD5，因为不安全。如果非要用，需要第三方库，如 crypto-js、spark-md5、blueimp-md5。但安全场景应避免。

替代方案

  • 完整性校验：SHA-256 / SHA-3 / BLAKE3
  • 密码存储：Argon2id / bcrypt / scrypt + 随机盐（后端做）
  • 消息认证：HMAC-SHA256
  • 数字签名：Ed25519 / RSA-PSS / ECDSA
  • 加密：AES-GCM / RSA-OAEP / ECDH

总结

MD5 是快速、过时的哈希算法，适合非安全的校验、缓存、去重；绝不能用于密码、签名、防篡改等安全场景。前端安全里，它基本只能当“指纹”用，不能当“锁”用。
