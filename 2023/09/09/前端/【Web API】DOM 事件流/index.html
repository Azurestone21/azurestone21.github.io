DOM 事件流

深入理解 DOM 事件流：从捕获到冒泡

引言

在网页中，用户的一次点击、一次滚动、一次键盘输入，都会触发 DOM 事件。但事件并不是凭空发生在某个元素上就结束了，它会沿着 DOM 树经历一段完整的“传播旅程”。这段旅程，就是我们常说的 DOM 事件流。

理解事件流，不仅能帮你写出更健壮的事件处理代码，也是面试中高频考察的基础知识点。本文将从事件流的三个阶段讲起，逐步深入到事件委托、阻止传播、性能优化以及常见误区。

一、什么是 DOM 事件流

DOM 事件流描述的是：当一个事件发生时，它在页面中传播的过程。

早期浏览器对事件传播的理解并不一致。IE 认为事件应该从目标元素向上冒泡，网景认为事件应该从顶层向下捕获。后来 W3C 在 DOM2 规范中统一了两种模型，规定事件流包含三个阶段：

  1. 捕获阶段（Capture Phase）
  2. 目标阶段（Target Phase）
  3. 冒泡阶段（Bubble Phase）

现代浏览器都遵循这个标准。

二、事件流的三个阶段

假设页面结构如下：

当点击 button 时，事件的传播路径是：

1. 捕获阶段

事件从 window 开始，自上而下向目标元素传播，途经所有祖先元素。

默认情况下，捕获阶段的监听器不会触发，除非你在 addEventListener 中显式设置 capture: true。

2. 目标阶段

事件到达目标元素，也就是实际被点击的那个元素。

在这个阶段，绑定在目标元素上的监听器会被触发。无论 capture 是 true 还是 false，目标元素上的监听器都会执行，顺序通常按注册顺序。

3. 冒泡阶段

事件从目标元素开始，自下而上向祖先元素传播，直到 window。

默认情况下，我们通过 addEventListener 添加的监听器都在冒泡阶段触发。这也是为什么父元素能通过事件委托感知到子元素的点击。

四、事件对象关键属性

1. event.target 与 event.currentTarget

  • target：事件实际发生的元素，可能是子元素。
  • currentTarget：当前正在处理事件的元素，始终是绑定监听器的那个。

事件委托正是利用了两者的区别。

2. event.eventPhase

返回当前所处阶段：

  • 1：捕获阶段
  • 2：目标阶段
  • 3：冒泡阶段

3. event.composedPath()

返回事件传播的完整路径数组，包括 Shadow DOM 内部节点。

五、阻止传播与默认行为

1. stopPropagation()

阻止事件继续传播。

  • 在捕获阶段调用，会阻止后续捕获和冒泡。
  • 在冒泡阶段调用，会阻止后续冒泡。

2. stopImmediatePropagation()

比 stopPropagation 更强：不仅阻止传播，还阻止当前元素上其他同类型监听器执行。

3. preventDefault()

阻止事件的默认行为，比如链接跳转、表单提交、复选框选中。

注意：preventDefault 不会阻止事件传播，和 stopPropagation 是两回事。

4. return false 的区别

在 addEventListener 的回调中，return false 不会阻止默认行为，也不会阻止传播。

六、事件委托

事件委托是事件流最经典的应用。

原理

利用冒泡机制，把监听器绑定在父元素上，通过 event.target 判断实际触发的是哪个子元素。

示例

优点

  • 减少监听器数量：一个父元素监听器代替多个子元素监听器。
  • 动态元素自动生效：新增的子元素不需要重新绑定。
  • 内存占用更少：监听器少，性能更好。

适用场景

  • 列表、表格、菜单等大量同类子元素。
  • 动态增删元素的场景。
  • 需要统一管理事件的场景。

不适用场景

  • 不冒泡的事件，如 focus、blur、mouseenter、mouseleave。
  • 需要精确控制每个子元素独立行为的场景。

七、哪些事件不冒泡

以下事件不冒泡，不能直接用于事件委托：

  • focus、blur
  • mouseenter、mouseleave
  • load、unload、abort、error
  • reset（部分浏览器不冒泡）

替代方案：

  • focus / blur → 使用 focusin / focusout（冒泡）
  • mouseenter / mouseleave → 使用 mouseover / mouseout（冒泡）
  • 或者在捕获阶段监听，因为捕获阶段仍然会经过祖先元素。

八、实际应用与最佳实践

1. 捕获阶段拦截

适合做全局权限控制、遮罩层拦截。

2. 优化滚动性能

告诉浏览器不会调用 preventDefault，浏览器可以立即滚动，不用等待 JS 执行。

4. 避免滥用 stopPropagation

stopPropagation 会破坏事件委托和全局监听，导致难以排查的 bug。优先通过条件判断、closest 等方式处理，而不是直接阻止传播。

九、常见误区与面试题

误区一：事件只有冒泡阶段

不是。完整事件流有捕获、目标、冒泡三个阶段，只是默认监听器在冒泡阶段触发。

误区二：stopPropagation 能阻止默认行为

不能。它只阻止事件传播，阻止默认行为要用 preventDefault。

误区三：event.target 始终等于 event.currentTarget

不一定。在事件委托中，target 是实际触发的子元素，currentTarget 是绑定监听器的父元素。

误区四：事件委托只能用于点击事件

不是。只要事件支持冒泡，都可以用事件委托，比如 input、change、keydown 等。

十、总结

DOM 事件流是前端开发中非常基础但极其重要的概念。记住三个关键词：

  • 捕获：从外到内，默认不触发。
  • 目标：事件到达实际元素。
  • 冒泡：从内到外，默认触发。

掌握事件流，你就能理解事件委托、阻止传播、性能优化等一系列实践。写代码时，优先使用事件委托减少监听器，谨慎使用 stopPropagation，在滚动等场景使用 passive，并注意 target 与 currentTarget 的区别。
