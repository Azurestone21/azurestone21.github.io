Dom Clobbering

Dom Clobbering

一、概述

DOM Clobbering（DOM 覆盖） 是一种前端攻击技术：攻击者通过注入 HTML 元素，利用元素的 id 或 name 属性，覆盖 JavaScript 中的全局变量或 DOM 属性，从而干扰页面原有 JS 逻辑，甚至升级为 XSS。

一句话：

不执行 JS，只靠 HTML 的 id/name，就能把 JS 里的变量“顶掉”。

它通常出现在允许用户注入 HTML 的场景，比如富文本、评论、自定义 HTML 片段。

二、原理

浏览器为了方便，会把某些 HTML 元素的 id 或 name 暴露为全局变量或 DOM 属性：

  • 具有 id 的元素会成为 window[id]
  • 具有 name 的某些元素（form、img、iframe、embed、object 等）也会成为 window[name]
  • form 元素的 id 或 name 会成为 document 的属性
  • form 内子元素的 name 会成为该 form 元素的属性

如果 JS 代码直接依赖这些隐式变量，攻击者就能用注入的 HTML 覆盖它们。

关键点：攻击者不需要执行 JS，只需要能注入 HTML。

三、常见形式

1. 覆盖全局变量

2. 覆盖 document 属性

3. 覆盖 form 子属性

4. 利用 window.name

五、危害

  • 篡改 JS 逻辑，绕过安全检查
  • 覆盖配置对象，改变请求地址、跳转目标
  • 配合已有 JS 升级为 XSS
  • 绕过基于全局变量的防御
  • 影响第三方库、分析脚本、广告脚本

特点：

  • 不直接执行脚本，隐蔽性强
  • 常作为 XSS 的绕过或升级手段
  • 需要 HTML 注入点，但不一定需要 JS 执行权限

六、防御方法

1. 避免依赖全局变量

2. 使用 let / const，避免隐式全局

3. 获取 DOM 后校验类型

4. 不要用 window.name 存敏感数据

5. 使用 dataset 或 Map 存储配置

6. 对注入 HTML 进行消毒

7. 开启 CSP 和 Trusted Types

8. 使用严格模式

减少隐式全局变量。

七、和原型污染的区别

DOM Clobbering 原型污染
攻击对象 全局变量 / DOM 属性 Object.prototype
注入方式 HTML 元素id/name 修改对象属性__proto__
是否需要 JS 不一定 通常需要 JS
防御 避免全局变量、类型校验、消毒 过滤__proto__、冻结原型

两者可以结合，扩大攻击面。

八、总结

DOM Clobbering 是一种前端攻击技术，攻击者通过注入带 id 或 name 的 HTML 元素，覆盖 JS 中的全局变量或 DOM 属性，从而干扰页面逻辑，甚至升级为 XSS。
比如 <img name="config"> 会让 window.config 变成这个 img 元素；<form id="config"><input name="url" value="javascript:..."> 会让 document.config.url 变成 input 元素。
它不需要执行 JS，只需要能注入 HTML，所以常用来绕过过滤。
防御核心是：不要依赖全局变量，用 let/const 和模块作用域；获取 DOM 后校验类型；不要用 window.name 存数据；对用户 HTML 用 DOMPurify 消毒；开启 CSP 和 Trusted Types。
它和原型污染不同，DOM Clobbering 覆盖的是变量，原型污染改的是 Object.prototype。
