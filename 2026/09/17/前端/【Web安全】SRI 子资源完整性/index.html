【Web安全】SRI 子资源完整性

一、SRI 是什么？

SRI（Subresource Integrity，子资源完整性） 是一种浏览器安全机制，用来确保通过 <script> 或 <link rel="stylesheet"> 加载的外部资源（如 CDN 上的 JS、CSS）没有被篡改。

一句话：

浏览器加载资源后，用你提前写好的哈希值校验内容，不一致就拒绝执行。

二、为什么需要 SRI？

前端经常从第三方 CDN 加载资源：

如果 CDN 被入侵、DNS 被劫持、中间人篡改，攻击者就能往这个 JS 里注入恶意代码。
你的页面会毫无防备地执行它，导致用户数据泄露、会话被劫持。

SRI 就是让浏览器帮你验证：“这个文件的内容，还是不是我当初信任的那份？”

三、工作原理

  1. 你为资源计算一个密码学哈希，比如 SHA-384。
  2. 把哈希写进 integrity 属性。
  3. 浏览器加载资源后，自己再算一遍哈希。
  4. 如果和 integrity 里的值一致，就执行/应用。
  5. 不一致，浏览器拒绝执行，并在控制台报错。

六、使用注意事项

  1. 必须全站 HTTPS否则中间人可以同时篡改 HTML 里的 integrity 值，SRI 就失效了。
  2. 跨域资源需要 CORS加 crossorigin="anonymous"，CDN 要返回 Access-Control-Allow-Origin: *。
  3. 资源更新要同步更新哈希适合固定版本库，比如 jquery@3.6.0。如果资源频繁更新，维护成本较高。
  4. 不能防服务器被攻陷如果攻击者能改你的 HTML，他也能改 integrity 值。
  5. 不能防 XSSSRI 只保证第三方资源没被篡改，不解决自身代码的 XSS 漏洞。
  6. 不是所有资源都支持
    主要用于 <script> 和 <link rel="stylesheet">，不适用于 <img>、<iframe> 等。

七、和 CSP 的关系

  • CSP：限制资源从哪些源加载，管“来源”。
  • SRI：保证加载的内容没被改，管“完整性”。

两者互补：

CSP 说“只能从这些地方加载”，SRI 说“加载的内容必须是这个哈希”。

八、总结

SRI 是子资源完整性，用来防止第三方 CDN 或外部资源被篡改。
通过在 <script> 或 <link> 上加 integrity 属性，写入资源的哈希值，浏览器加载后自己计算哈希并比对，不一致就拒绝执行。
它通常需要搭配 crossorigin="anonymous" 和 HTTPS，因为跨域资源要 CORS 才能读取内容校验，而且 HTTP 下中间人可以同时改 HTML 和哈希。
SRI 不能防 XSS，也不能防服务器被攻陷，但能有效防供应链攻击和 CDN 篡改。它和 CSP 互补：CSP 管来源，SRI 管完整性。
