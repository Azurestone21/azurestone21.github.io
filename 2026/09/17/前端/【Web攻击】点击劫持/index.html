【Web攻击】点击劫持

【Web攻击】点击劫持

一、概述

点击劫持是一种视觉欺骗攻击：攻击者把目标网站用透明 iframe 覆盖在一个诱导页面上，让用户以为点击的是当前页面的按钮，实际上点击的是 iframe 里目标网站的敏感操作。

一句话：

用户看到的是 A 页面，点到的却是 B 页面的按钮。

二、攻击原理

  1. 攻击者创建一个诱导页面，放上“点击领奖”“播放视频”等按钮。
  2. 用 <iframe> 加载目标网站（如银行转账页）。
  3. 把 iframe 设为透明，并定位到按钮上方。
  4. 用户点击诱导按钮时，实际点击的是 iframe 里的目标按钮。
  5. 因为用户已登录目标网站，浏览器自动携带 Cookie，操作被服务器执行。

核心条件：

  • 目标网站允许被 iframe 嵌入。
  • 用户已登录目标网站。
  • 攻击者能诱导用户点击。

三、攻击示例

用户以为点的是“领奖”，实际点到的是转账按钮。

四、常见变种

  • Likejacking：诱导点赞、关注。
  • Cursorjacking：篡改鼠标光标位置，误导点击。
  • Filejacking：诱导选择文件。
  • 双击劫持：诱导双击执行敏感操作。
  • 移动端点击劫持：利用触摸事件和透明层。

五、危害

  • 以用户身份转账、发帖、改密码、删数据
  • 诱导授权 OAuth、开启摄像头/麦克风
  • 点赞、关注、分享等社交操作
  • 配合 CSRF 扩大攻击

六、防御方法

1. X-Frame-Options（传统响应头）

可选值：

  • DENY：禁止任何页面嵌入。
  • SAMEORIGIN：只允许同源页面嵌入。
  • ALLOW-FROM：已废弃，不推荐。

3. JS Frame Busting（不推荐单独使用）

缺点：

  • 可被 sandbox 属性绕过。
  • 可被 onbeforeunload 阻止跳转。
  • 可被条件注释、XSS 过滤绕过。
  • 不适合作为唯一防御。

4. SameSite Cookie（辅助）

SameSite 可以阻止跨站 iframe 携带 Cookie，降低点击劫持成功率，但不能完全替代 frame-ancestors。

5. 关键操作二次确认

  • 输入密码
  • 短信验证码
  • 图形验证码
  • 明确提示操作内容

七、防御总结

方法 作用 推荐度
X-Frame-Options: DENY/SAMEORIGIN 禁止/限制 iframe 嵌入 高
CSP: frame-ancestors 现代替代方案，更灵活 最高
JS Frame Busting 前端跳转，易绕过 低
SameSite Cookie 减少跨站携带凭证 辅助
二次确认 关键操作保护 辅助

八、总结

点击劫持是一种视觉欺骗攻击。攻击者用透明 iframe 覆盖目标网站，诱导用户点击，实际点击的是目标网站的敏感按钮。因为用户已登录，浏览器自动带 Cookie，操作就被执行了。
防御核心是禁止页面被 iframe 嵌入：设置 X-Frame-Options: DENY 或 SAMEORIGIN，现代方案用 CSP: frame-ancestors 'none' 或 'self'。
JS frame busting 容易被绕过，不推荐单独使用。SameSite Cookie 可以辅助，关键操作还应加二次确认。
注意点击劫持和 CSRF 的区别：点击劫持是诱导用户真实点击，CSRF 是伪造请求。
