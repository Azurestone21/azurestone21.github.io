MobX 类注解：makeObservable / makeAutoObservable / override

MobX 类注解：makeObservable / makeAutoObservable / override

一句话理解：这三个 API 是 MobX 将普通类”激活”为响应式数据源的入口。makeObservable 是显式手动挡，makeAutoObservable 是自动挡，override 是继承场景下的专用注解。

1. 三者总览对比

特性 makeObservable makeAutoObservable override
核心作用 显式指定每个成员的 MobX 角色 自动推断成员角色 标记子类重写了父类的成员
代码量 较多 最少（无需写注解） 仅在继承重写时使用
是否必须 是（可选装饰器替代） 是（makeObservable 的语法糖） 是（继承重写时必须）
适用场景 精确控制、继承场景 无继承关系的类 子类重写父类computed/action
支持子类继承 ✅ 支持（配合override） ❌ 不支持 ✅ 是makeObservable 的一部分

2. makeObservable（显式注解）

特点：手动为每个成员指定注解，意图最清晰，适合需要精确控制的场景，也是处理继承时唯一可用的方式。

何时使用：

  • 需要精确控制每个成员的行为。
  • 类存在继承关系（子类需要 override）。
  • 团队成员偏好显式优于隐式。

3. makeAutoObservable（自动推断）

特点：MobX 自动推断成员角色，代码最简洁，适合绝大多数无继承关系的类。

自动推断规则：

成员类型 自动推断为
普通属性（todos = []） observable
Getter（get completedTodos()） computed
方法（addTodo()） action
Setter（set value(val)） action
箭头函数属性（increment = () => {}） action.bound

何时使用：

  • 新项目、无继承关系的类（首选）。
  • 追求代码简洁和开发效率。

4. override（继承场景的关键注解）

核心问题：子类重写父类的 computed 或 action 时，必须使用 override 注解，否则 MobX 会报错或行为异常。

override 的核心作用：

  1. 明确语义：告诉 MobX 和代码阅读者：”我故意重写了父类的方法”。
  2. 安全保护：如果父类没有同名的 computed/action，MobX 会报错，防止你写错方法名。
  3. 内部处理：让 MobX 正确处理继承链中的依赖追踪和缓存。

6. 选型决策指南

快速决策表：

场景 推荐方案
新项目，无继承 makeAutoObservable
需要继承（extends） makeObservable + override
需要精细控制（如排除某些属性） makeObservable
使用装饰器语法（@observable） 不需要调用任何make* 函数

7. 常见错误与陷阱

❌ 错误 1：在 observable 工厂函数中混用 makeAutoObservable

正确做法：observable 工厂已自动处理，不需要再调用任何 make* 函数。

❌ 错误 2：有继承关系却使用 makeAutoObservable

正确做法：父类和子类都使用 makeObservable。

❌ 错误 3：重写父类方法但忘记加 override

正确做法：用 override 替换 computed/action。

❌ 错误 4：忘记在构造函数中调用 super()

正确做法：子类构造函数中必须先调用 super()，再调用 makeObservable。

💡 核心原则：无继承用 makeAutoObservable，有继承用 makeObservable + override。
