跨站请求伪造 CSRF

CSRF 是什么？

一句话：CSRF（Cross-Site Request Forgery，跨站请求伪造）是攻击者诱导用户在已登录的网站上，以用户身份执行非本意操作的攻击。

它利用的是：浏览器会自动携带目标站点的 Cookie，而服务器无法区分这个请求是用户主动发的，还是被攻击者诱导发的。

一、攻击原理

  1. 用户登录了 bank.com，浏览器保存了 bank.com 的会话 Cookie。
  2. 用户在不登出的情况下，访问了攻击者的页面 evil.com。
  3. evil.com 里藏了一个自动提交的表单或图片请求，指向 bank.com/transfer。
  4. 浏览器发送请求时，自动带上 bank.com 的 Cookie。
  5. bank.com 服务器看到 Cookie 有效，以为是用户本人操作，于是执行转账。

核心公式：

用户已登录 → 浏览器自动带 Cookie → 攻击者诱导发请求 → 服务器误认为是用户操作

二、和 XSS 的区别

XSS CSRF
本质 在目标站点执行恶意脚本 借用户身份发请求
信任利用 浏览器信任页面脚本 服务器信任浏览器 Cookie
是否需要脚本 需要 不一定，表单/图片即可
防御重点 输出编码、CSP CSRF Token、SameSite

关键区别：
XSS 是“攻击者能执行代码”，CSRF 是“攻击者能借用户的手发请求”。

三、攻击条件

  1. 用户已登录目标站点，且会话 Cookie 有效。
  2. 目标站点没有对请求做 CSRF 防护。
  3. 攻击者能诱导用户访问恶意页面或点击链接。
  4. 请求的参数可预测或可构造。

四、常见攻击方式

  • 自动提交表单

  • 图片请求

  • 链接触发
    诱导用户点击 https://bank.com/transfer?to=hacker&amount=10000。

五、危害

  • 以用户身份转账、发帖、改密码、删数据
  • 盗取用户权限
  • 配合 XSS 扩大攻击
  • 蠕虫传播

七、总结

CSRF 是跨站请求伪造，攻击者诱导用户在已登录的网站上，以用户身份执行非本意操作。它利用浏览器自动携带 Cookie 的机制。和 XSS 的区别是：XSS 是执行恶意脚本，CSRF 是借用户身份发请求。
防御核心是：CSRF Token、SameSite Cookie、校验 Origin/Referer、关键操作二次验证、敏感操作不用 GET。
注意：CORS 不是 CSRF 防御，因为简单请求即使跨源也会发送。
