Taro 中使用 Tailwind CSS（v3 版本实践指南）

Tailwind CSS 的原子化类名能大幅提升开发效率，但在 Taro 小程序环境中直接使用会遇到类名转义、选择器兼容、PostCSS 版本冲突等一系列问题。本文以 Tailwind CSS v3 为例，梳理一套经过验证的配置方案，并说明 weapp-tailwindcss 版本选择的关键注意事项。

为什么 Tailwind 需要 PostCSS

Tailwind 本身不是浏览器能直接识别的 CSS，而是一个构建时的 CSS 生成器。它需要挂载到 PostCSS 管道上，才能把 @tailwind 指令替换成真实的工具类。Taro 内置了 PostCSS 和 autoprefixer，因此你只需要注册 Tailwind 插件即可，不需要额外安装这两个依赖。

版本兼容性：Tailwind v3 搭配哪个 weapp-tailwindcss

weapp-tailwindcss 的版本与 Tailwind CSS 的对应关系如下：

weapp-tailwindcss 版本 Tailwind v3 支持状态
2.x / 3.x ✅ 原生支持
4.x ✅ 完整支持
5.x ❌ 不兼容 Tailwind v3

weapp-tailwindcss@5 已移除对 Tailwind v3 的兼容链路。该版本的核心目标已全面转向 Tailwind v4，5.0 的发布摘要中明确将“移除 Webpack4、PostCSS7、Tailwind CSS v2 兼容链路”列为重大变更，同时围绕 v4 的 Oxide 引擎重构了生成逻辑。因此，如果你使用 Tailwind v3，必须选择 weapp-tailwindcss@4.x 或更早的 3.x/2.x 版本。

对于 Taro 4 + Webpack5 项目，推荐使用 weapp-tailwindcss@4.x；如果项目较旧或依赖特定版本，3.x 同样可以正常工作。

第一步：安装依赖

关于 PostCSS 和 autoprefixer 的说明
Taro 官方文档明确指出，Taro 内部已经内置了 PostCSS 和 autoprefixer。因此在实际项目中，你通常不需要额外安装 postcss 和 autoprefixer，只安装 tailwindcss 即可。
但官方安装命令中仍然包含了这两个包，这是一个“保险”做法：如果你的项目使用了 monorepo 结构，或者 PostCSS 配置需要显式引用 autoprefixer 包时，没有安装可能会报模块找不到的错误。因此，你可以根据项目实际情况决定是否保留它们。保留安装命令不会有副作用，只是多下载两个包而已。

注意版本对应关系：Tailwind CSS v3 要求 PostCSS 8+，而 Taro 4 底层依赖的 PostCSS 版本需要确认是否满足此条件。如果你的项目 PostCSS 版本较低，需要通过 weapp-tailwindcss 的兼容链路来处理。

常见问题排查

类名转义失败

weapp-tailwindcss 只能转义 Tailwind 已提取到的类名。如果某个页面或组件中的 Tailwind 类名没有被转义，首先检查 tailwind.config.js 的 content 字段是否覆盖了该文件。

总结

在 Taro 4 中使用 Tailwind CSS v3 的核心配置要点：

  1. Tailwind v3 可搭配 weapp-tailwindcss 的 2.x、3.x、4.x 版本，5.x 已不再兼容 v3。
  2. preflight 必须在小程序端关闭，否则 WXSS 编译报错。
  3. v3 不需要 cssEntries，那是 v4 的配置项。
  4. content 配置必须覆盖所有使用 Tailwind 类名的文件。
  5. PostCSS 注册方式二选一：postcss.config.js 或 config/index.js 内联，Vite 版本优先选内联。
  6. Taro 内置了 PostCSS 和 autoprefixer，通常不需要额外安装，但保留官方安装命令作为兼容性保险是可行的。

如果未来计划迁移到 Tailwind v4，届时需要同步升级 weapp-tailwindcss 到 5.x，并补充 cssEntries 配置。但在 v3 项目稳定运行期间，锁定 weapp-tailwindcss@4（或 3.x）是更稳妥的选择。
