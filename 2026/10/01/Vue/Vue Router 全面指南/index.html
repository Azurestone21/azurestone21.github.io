Vue Router 全面指南（V4）

Vue Router 是 Vue.js 官方的路由管理器，用于构建单页应用（SPA）。它的核心作用是将浏览器的 URL 与用户看到的组件视图绑定起来，让你在切换页面时无需重新加载整个页面，从而获得更流畅的体验。

本文从 Vue Router 4 的基础写法讲起，覆盖参数获取、带参跳转、路由守卫等核心场景，再过渡到 Vue Router 5 的新特性与迁移路径，形成完整的版本脉络。

一、核心功能与特性

Vue Router 深度集成在 Vue 中，提供了构建复杂应用所需的路由能力：

  • 嵌套路由映射：支持复杂页面布局，父组件内可渲染子组件。
  • 动态路由：支持带参数的路径（如 /user/:id），根据 ID 渲染不同内容。
  • 导航控制：提供细粒度的导航守卫，可在路由跳转前后执行逻辑（如登录验证）。
  • 多种模式：支持 HTML5 History 模式（URL 更美观）或 Hash 模式（兼容性更好）。
  • 过渡效果：可方便地为路由切换添加 Vue 过渡动画。

版本脉络

版本 定位
Vue Router 4 配合 Vue 3 的稳定路由方案，createRouter + Composition API 的标准写法

四、带参数跳转

带参数跳转主要分两种场景：动态路由参数（params） 和查询参数（query）。最推荐使用命名路由 + params，能自动处理 URL 编码，最稳妥。

方式一：传递动态路由参数（params）

适用于 /user/:id 这种路径，参数是 URL 的一部分。前提：路由配置必须有 name，且路径中定义了占位符。

⚠️ 关键避坑：不要把 params 和 path 混用。router.push({ path: '/user', params: { id: 123 } }) 中 params 会被直接忽略，URL 只会变成 /user，参数丢失。一定要用 name。

方式二：传递查询参数（query）

适用于可选参数、筛选条件，或不想在路由配置里预先定义占位符的场景。参数以 ?key=value 形式出现在 URL 中。

2. 全局解析守卫（数据预取）

router.beforeResolve 在导航被确认之前、所有组件内守卫和异步组件解析之后调用。这是获取页面所需数据的理想时机——若用户无权访问，就不必浪费请求。

3. 全局后置钩子（分析统计）

router.afterEach 在导航完成后调用，不能改变导航结果。适合更新页面标题、发送统计数据。

4. 关于 next 的提醒

虽然 v5 仍兼容第三个参数 next，但官方已明确不推荐。维护旧代码时，务必确保 next 在所有逻辑分支中只被调用一次，否则会导致钩子无法解析或报错。

六、Vue Router 5 新特性：基于文件的路由

Vue Router 5 将 unplugin-vue-router 整合进核心包，不再需要手动维护 routes 数组，只需在 src/pages 目录下创建 .vue 文件，路由自动生成，并带有完整 TypeScript 支持。此外还引入了实验性的数据加载器（Data Loaders）。

七、从 Vue Router 4 到 Vue Router 5 的迁移

核心结论：几乎零成本

根据官方迁移指南，如果你使用 Vue Router 4 且没有使用 unplugin-vue-router 插件，升级到 v5 没有任何破坏性变更，只需更新依赖版本：

v5 被官方定义为过渡版本，核心目标是将 unplugin-vue-router 合并进核心包，同时为未来的 v6（仅 ESM、移除废弃 API）铺路。

如果你之前用了 unplugin-vue-router

迁移主要是更换导入路径，功能本身不变：

原导入路径（v4 + 插件） v5 导入路径
unplugin-vue-router/vite vue-router/vite
unplugin-vue-router（类型/工具） vue-router/unplugin
unplugin-vue-router/data-loaders/basic vue-router/experimental

升级后，之前用插件实现的文件路由能力会保留，只是包来源变了。

唯一需要注意的例外

v5 的 IIFE 构建版本不再包含 @vue/devtools-api（该依赖升级到 v8 后不再提供 IIFE 构建）。如果你的项目通过 CDN 方式直接加载 IIFE 版本的 Vue Router 并使用 DevTools，需要留意。对于绝大多数通过构建工具使用的项目，这没有影响。
