React Router 全面指南

React Router 全面指南：从 v6 基础到 v7 数据路由实战

React Router 是 React 生态中官方推荐的路由解决方案，用于在单页应用（SPA）中根据 URL 动态渲染组件，实现不刷新页面的”页面”跳转。它的核心机制是将 URL 与路由配置进行匹配，并渲染对应的组件树。

本文从 v6 的基础写法讲起，覆盖参数获取、列表翻页、表单提交、权限控制等核心场景，再过渡到 v7 的数据路由范式与迁移路径，形成完整的版本脉络。

一、核心概念与版本脉络

基础概念

  • 路由配置：将路径（path）映射到组件（element / Component）。
  • 动态段：路径中的 :id 占位符，匹配 URL 中的实际值。
  • 嵌套路由：父路由通过 <Outlet /> 渲染子路由，实现布局复用。
  • 导航：<Link> / <NavLink> 声明式跳转，useNavigate() 编程式跳转。

版本脉络

版本 定位
v6 引入 <Routes> / <Route> JSX 写法与 useRoutes 对象配置；后期（v6.4+）引入 createBrowserRouter 数据路由与 loader / action
v7 数据路由成为默认范式；所有功能合并进 react-router 包；移除 json / defer 等废弃 API；要求 Node 20+、React 18+

v7 并非颠覆性重写，而是把 v6 后期以”未来标志（Future Flags）”形式释放的变更正式转正。在 v6 中启用所有 future flags 后，升级到 v7 几乎无感。

三、useRoutes：对象化的路由声明

useRoutes 是 <Routes> 的 Hook 化写法，用对象数组定义路由，返回可渲染的元素。它必须运行在 <BrowserRouter> 等路由上下文内部。

useRoutes 只解决”URL 匹配 → 渲染哪个组件”，不具备数据路由的 loader、action、errorElement、useNavigation、useFetcher 等能力。适合静态页面或数据逻辑极简的场景。

四、动态参数与查询参数

动态参数（/user/:id）

在 loader / action 中：入参直接有 params 对象。

在组件中：用 useParams()。

查询参数（?page=2&keyword=vue）

在 loader / action 中：从 request.url 解析。

在组件中：用 useSearchParams()。

对照速查

参数类型 loader / action 中 组件中
动态参数 ({ params }) => params.id useParams().id
查询参数 new URL(request.url).searchParams.get("key") useSearchParams()[0].get("key")

注意：两者取出的值都是字符串，数字运算前务必 Number() 并给默认值。

五、列表翻页：URL 作为唯一数据源

翻页的核心是把页码和筛选条件放进 URL 的 search params，让 loader 直接读取，翻页即一次导航，React Router 自动重跑 loader。

原则：页码不要用 useState 存，URL 是唯一数据源；改筛选条件时把 page 重置为 1；加载态用 useNavigation().state 驱动。

六、数据路由实战：loader / action 与 Antd 配合

loader / action 是数据层，Antd 是 UI 层，两者完全兼容。以”用户列表 + 添加表单”为例。

关键点：Antd 表单负责 UI 和校验，onFinish 里用 useSubmit() 触发 action；action 执行后 React Router 自动重新执行 loader，列表自动刷新，组件里不需要任何手动状态管理。

七、Outlet 的渲染机制

<Outlet> 是布局组件里的”内容插槽”，它渲染的是当前 URL 匹配链中、自己下一层的路由元素。

访问 /users/123 时：匹配链为 / → users → :id，渲染 BasicLayout，其 <Outlet /> 渲染下一层，逐层嵌套到 UserDetail。布局（侧边栏、顶栏）保持不变，只替换 Outlet 内容。

无 path 的路由（如 { Component: Layout, children: [...] }）不贡献 URL 段，只做布局包装或统一守卫分组，是常见写法。需要编程控制时可用 useOutlet() 获取子元素。

八、代码分割：Component + lazy() 与路由级 lazy

两种懒加载方式职责不同：

维度 Component: lazy() 路由级 lazy
加载控制方 React（渲染阶段） React Router（导航阶段）
是否需要 <Suspense> 需要 不需要
能否懒加载 loader / action 不能 能，一起返回
加载失败错误归属 React 渲染错误 路由错误，走 errorElement
加载态展示 各布局套 <Suspense> useNavigation().state 统一处理

数据路由项目建议统一用路由级 lazy：loader 与组件同 chunk 按需加载，错误能走 errorElement 兜底，布局无需为每个页面包 <Suspense>。

九、菜单权限控制

核心思路：权限数据决定”能进哪些路由”，路由配置决定”能渲染什么”，菜单从路由表派生。

1. 路由配置挂权限标识

React Router 用 handle 字段（非 Vue 的 meta）挂自定义数据，通过 useMatches() 读取。

2. 全局认证 Context

3. 路由守卫（loader 拦截）

无权限时 loader 抛 403，由 errorElement 统一渲染。不要只靠菜单隐藏——手动输入 URL 也必须被拦截。

4. 菜单从路由表派生

菜单、路由守卫、按钮显隐共用同一个 hasPermission，保证权限逻辑只有一处来源。前端权限只控制体验，真正的安全必须由后端校验。

十、从 v6 到 v7 的迁移

核心结论：渐进升级，风险可控

v7 的主要变化：

  • 包合并：所有功能整合进 react-router，react-router-dom 仅作兼容导出。迁移时卸载 react-router-dom，安装 react-router，修改导入路径。
  • 数据路由成为默认范式：推荐 createBrowserRouter + RouterProvider；JSX 写法仍可用但功能冻结。
  • 移除废弃 API：json 和 defer 被移除，改用普通对象或 Response.json()。
  • 版本要求：Node 20+、React 18+。

推荐迁移路径

  1. 先升级到 v6 最新小版本，确保无弃用警告；
  2. 逐个开启 Future Flags（如 v7_startTransition、v7_relativeSplatPath），每开一个测试并提交，精确定位问题；
  3. 在 v6 阶段替换 json() / defer()；
  4. 全部开启且测试通过后，升级到 v7 并修正导入路径。

场景 推荐做法 避坑要点
获取动态参数 useParams() / loader 的 params 值是字符串，需 Number()
获取查询参数 useSearchParams() / new URL(request.url).searchParams 给默认值，注意 null
列表翻页 页码放 URL，setSearchParams 触发 loader 重跑 不要用 useState 存页码
表单提交 Antd onFinish + useSubmit() action 后自动重跑 loader
提交加载态 useNavigation().state === "submitting" 不要用组件自己的 loading 状态

权限守卫 loader 校验 + errorElement 兜底 不能只靠菜单隐藏
