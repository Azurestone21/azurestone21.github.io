浏览器五大 Observer API

浏览器五大 Observer API 详解与实战

引言

浏览器提供了一组以 Observer 结尾的 API，它们共享同一套设计哲学：创建观察者 → 观察目标 → 异步回调通知。这种模式让开发者无需轮询或监听高频事件，就能高效地感知页面状态的变化。

目前主流的 Observer API 有五个：

API 监听对象 典型场景
IntersectionObserver 元素可见性交叉 懒加载、无限滚动、曝光统计
ResizeObserver 元素尺寸变化 图表自适应、响应式布局
MutationObserver DOM 变动 水印监控、动态内容处理
PerformanceObserver 性能条目 性能监控、长任务检测
ReportingObserver 浏览器警告 废弃 API 追踪、质量监控

下面逐一介绍它们的原理、配置和实战用法。

一、IntersectionObserver：监听可见性

IntersectionObserver 异步监听目标元素与视口（或指定祖先元素）的交叉状态，用来判断”元素是否可见、可见了多少”。

关键配置

  • root：参照区域，默认为视口，也可以指定任意祖先元素。
  • rootMargin：像 CSS margin 一样扩大或缩小判定区域。例如 '200px' 让元素距离视口还有 200px 时就提前触发。
  • threshold：触发阈值。0 表示一个像素可见就触发，1 表示完全可见才触发，也可以传数组如 [0, 0.5, 1]。

需要注意：调用 observe() 后回调会立即执行一次，不管元素是否可见。所以如果只想处理”进入视口”的逻辑，必须判断 entry.isIntersecting。

二、ResizeObserver：监听尺寸变化

ResizeObserver 监听元素自身尺寸的变化，回调在布局之后、绘制之前触发，同一帧内多个元素的尺寸变化会被合并成一次回调。

观测盒模型

通过 observe(target, { box: 'content-box' }) 指定，默认是 content-box，还可选 border-box 或 device-pixel-content-box（物理像素，适合 Canvas 高 DPI 绘制）。

最需要注意的坑

回调里修改被观察元素自身的尺寸会触发死循环。比如观察一个 div 的宽度，又在回调里改它的 padding，padding 变化又改变尺寸，再次触发回调。浏览器会报 ResizeObserver loop completed with undelivered notifications 错误。

三、MutationObserver：监听 DOM 变动

MutationObserver 异步监听 DOM 节点的增删、属性变化和文本内容变化，是已废弃的 Mutation Events 的现代替代品。

配置项

observe(target, config) 中 config 必须至少包含 childList、attributes、characterData 中的一个，否则抛出 TypeError。

  • childList：监听子节点添加和删除
  • attributes：监听属性变化，可配合 attributeFilter 只监听特定属性
  • subtree：是否观察所有后代节点
  • attributeOldValue / characterDataOldValue：记录变化前的旧值

四、PerformanceObserver：监听性能条目

PerformanceObserver 订阅性能时间线上的条目，比如 mark、measure、resource、longtask、event 等类型。

关键配置

  • entryTypes：数组，指定要观察的性能条目类型
  • type：单字符串，指定一种类型
  • buffered：是否获取观察器创建之前已经产生的条目。注意 buffered 只能和 type 配合使用，不能和 entryTypes 同时用

五、ReportingObserver：监听浏览器警告

ReportingObserver 程序化地获取浏览器发出的废弃警告（deprecation）和干预报告（intervention）。以前这些信息只在开发者工具控制台里出现，线上用户遇到问题时无从得知。

关键配置

  • types：数组，可选 'deprecation'、'intervention'，不传则收集所有支持的类型
  • buffered：true 时能拿到观察器创建之前已产生的报告，适合延迟加载监控脚本的场景

它的价值在于：window.onerror 只捕获 JS 运行时错误，捕获不到浏览器自身发出的警告。ReportingObserver 填补了这个空白。

兼容性提醒：这个 API 目前不是 Baseline 特性，在部分浏览器中不可用，更适合作为渐进增强的监控手段。

七、小程序场景的补充

小程序中同样可以使用 IntersectionObserver，但不能直接照搬 Web 端写法。

微信小程序提供了 wx.createIntersectionObserver，基础库 1.9.3 开始支持。核心差异：

  • 不能用 new IntersectionObserver()，必须通过 wx.createIntersectionObserver() 创建
  • 观察目标用选择器字符串，不是 DOM 节点：observer.observe('.target-class', callback)
  • 参照区域设置方式不同：用 .relativeToViewport() 或 .relativeTo(selector) 指定

其他平台：支付宝小程序用 my.createIntersectionObserver，uni-app、Taro、Mpx 等跨端框架也都做了封装。另外，uni-app 还封装了 MediaQueryObserver，用来监听页面媒体查询状态的变化。

总结

五个 Observer API 的共同哲学是：异步、批量、不阻塞主线程。它们替代了过去的轮询、高频事件监听和手动计算，性能和代码简洁度都更好。

实际项目中：

  • IntersectionObserver 最常用，懒加载、曝光统计、无限滚动都靠它
  • ResizeObserver 是响应式布局和图表自适应的利器，但要注意死循环问题
  • MutationObserver 多用于监控和自动化处理
  • PerformanceObserver 和 ReportingObserver 偏性能与质量监控，是线上问题排查的重要补充

理解每个观察器”观察什么”以及”配置如何影响触发时机”，就能在合适的场景选对工具。
