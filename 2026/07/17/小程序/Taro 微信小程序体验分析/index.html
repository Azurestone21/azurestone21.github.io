Taro微信小程序体验分析

微信小程序分析

体验分析是帮助小程序提升拉新、留存、付费转化率的强大工具，能够可视化还原用户操作现场，无论是产品交互体验缺陷还是 bug 都能轻松洞察，分析套件包含交互回放、热力图、转化分析等多维度零门槛分析工具，轻松排查问题、优化产品，快速提升你的产品转化率。

使用体验分析

  1. 登录 we 分析控制台
  2. 进入“数据分析-体验分析”
  3. 进入“设置-采集配置”
  4. 配置后点击“保存”按钮

自定义上报

文档：https://developers.weixin.qq.com/miniprogram/analysis/experience/sdk/api.html

接口列表

helper 说明
setup 启动采集
getSessionId 获取当前会话ID
getStatus 获取当前采集状态
teardown 停止采集
event 上报自定义事件
setCustomId 自定义业务标记
setCustomProperties 自定义业务属性

采集状态

value 说明
NotSetup 未 setup
SettingUp 开启采集中
WaitingForFirstReport 采集第一个上报数据中
Collecting 正常采集中
TearingDown 停止采集中

调用接口

调用接口有两种方式：

  1. wx.obs 直接调用，需要基础库版本 >= 3.4.1。
  2. 如果需要兼容低版本的基础库，建议引入 npm 包，npm install @wxobs/miniprogram-helper。

参考基础库版本分布

注意事项：

  1. 以上接口通过 wx.obs 调用，需要在监听到 getStatus 的状态为 Collecting 后调用。
  2. 如果 We 分析平台 采集配置中“启动方式”是自动启动，不能调用 setup 接口。
  3. 使用 await 等待 getStatus 状态并不准确，初次获取的值可能是 NotSetup，需要轮询获取状态。

使用 npm 包

我的 Taro 项目使用 pnpm，所以我使用pnpm install @wxobs/miniprogram-helper安装，然后在微信开发者工具中点击“构建npm”，显示以下错误：

message： NPM packages not found. Please confirm npm packages which need to build are belong to miniprogramRoot directory. Or you may edit project.config.json’s packNpmManually and packNpmRelationList

原因：

工具在当前配置的目录下没有找到需要构建的 npm 包。

微信开发者工具默认会去寻找 miniprogramRoot（小程序根目录）下的 node_modules。但在 Taro 项目中，node_modules 通常位于项目根目录，而不是在小程序代码所在的 dist 目录下，所以工具找不到。

解决方法：

手动配置 project.config.json，告诉开发者工具去哪里找 npm 包。

重新执行构建项目命令，再次点击“构建npm”，显示以下错误：

message：发生错误
SyntaxError: parse js file ([项目目录]/node_modules/@nutui/icons-react-taro/dist/lib/index.umd.js) failed: Unexpected token (17:2292)

原因：

构建 npm 的过程中，工具尝试解析 @nutui/icons-react-taro 这个包时，遇到了它无法处理的 JavaScript 语法。
但其实项目中其他的 npm 包并不需要构建，只需要构建 @wxobs/miniprogram-helper 这个包。

解决方法：

需要让微信开发者工具知道，只需要构建 @wxobs/miniprogram-helper 这个包。

Error: packageJsonPath should ends with package.json

目录可以是任意目录，但是必须是 package.json 文件，packageJsonPath 不接受其他文件。

  1. 修改 packageJsonPath 配置，指向 npmBuild/package.json 文件
  1. 安装依赖
  1. 重启项目，点击“构建npm”，如果看到 dist 目录下生成 miniprogram_npm目录，且目录下有@wxobs/miniprogram-helper 包，说明构建成功。
