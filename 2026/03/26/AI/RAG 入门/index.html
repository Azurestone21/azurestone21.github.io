RAG 入门

RAG 入门

RAG 是什么？

RAG（Retrieval Augmented Generation，检索增强生成） 是一种基于大语言模型（LLM）的技术架构，通过在生成回答前从外部知识库检索相关信息，来增强模型的事实准确性和业务适配能力。

RAG 解决的核心问题

通用大语言模型存在四大固有缺陷：

缺陷 说明
知识过时 训练数据截止于特定时间点，无法自动获取最新信息
领域知识空白 训练数据以公开网络为主，无法覆盖企业内部或专业领域知识
幻觉问题 模型可能生成看似合理但实际错误的内容
数据安全风险 直接将敏感数据输入第三方模型存在泄露隐患

RAG 正是为系统性地解决这些问题而生的技术方案。

核心思想

RAG 不修改模型本身，而是通过优化输入来影响输出。其核心逻辑可概括为：

检索事实 → 拼装上下文 → 让模型基于事实作答

换句话说：与其让模型凭空回答，不如先帮它把参考答案找好。

工作原理：离线 + 在线两条线

1. 离线准备线（知识库预处理）

将原始文档转化为可检索的向量索引：

  1. 文档加载：读取各类格式文件（TXT、PDF、Word、Markdown 等）。
  2. 文本分割：将长文档切分为语义完整的文本块（Chunk）。
  3. 向量化：调用 Embedding 模型将每个文本块转换为稠密向量。
  4. 存储索引：将向量存入向量数据库（如 pgvector、Chroma、Milvus），并构建 ANN 索引。

2. 在线服务线（用户请求处理）

响应用户的实时查询请求：

  1. 问题向量化：将用户输入的问题同样转换为向量。
  2. 相似度检索：在向量数据库中检索最相似的 Top-K 个文本块。
  3. Prompt 融合：将检索到的文本块作为上下文，与用户问题拼接为结构化提示词。
  4. LLM 生成：将提示词输入大语言模型，生成最终答案。

标准三阶段

阶段 职责 核心操作
索引阶段（Indexing） 构建知识库 加载 → 分割 → 向量化 → 存储
检索阶段（Retrieval） 召回相关知识 向量化 Query → 相似度匹配 → 召回 Top-K
生成阶段（Generation） 生成最终回答 拼接上下文 → 调用 LLM → 输出答案

RAG 的核心价值

价值 说明
知识可更新 只需更新知识库文档，即可让模型输出最新信息，无需重新训练
事实准确性高 回答基于检索到的事实资料，有效降低幻觉
成本可控 无需微调模型，仅通过提示词优化即可适配业务场景
数据安全可控 敏感数据保留在内部知识库，检索结果可审计、可追溯

技术定位

  • RAG 是提示词工程的进阶形态——将“静态提示词”升级为“动态注入检索上下文的提示词”。
  • RAG 也是 LangChain 框架的核心应用场景之一。LangChain 提供了从文档加载、文本分割、向量存储到检索链路的全流程组件，是工业级 RAG 应用的首选开发框架。

一句话总结：RAG 的核心流程可概括为 检索 → 增强 → 生成，即先捞知识，再让 LLM 照着知识回答。
