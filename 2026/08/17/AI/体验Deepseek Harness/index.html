Deepseek Harness 是什么

DeepSeek Harness（命令行工具名为 dsh）是 DeepSeek 于 2026 年 8 月开源的一个智能体（Agent）运行时框架，采用 MIT 协议。它的核心理念可以用一个简单的公式概括：Agent = Model + Harness。模型是“大脑”，负责思考；Harness 则是“手脚和神经系统”，负责让模型真正动手干活。

核心设计：一切皆插件

Harness 最根本的设计原则是 “一切皆插件”（Everything is a Plugin）。与将核心逻辑写死的传统 Agent 框架不同，Harness 把 Agent 的每一个组成部分都做成了可替换的插件。

支撑这一架构的是 Cordis 元框架。它本质上是一个集成了依赖注入、事件总线和生命周期管理的插件系统。其核心优势在于：

  • 高度解耦：模型适配器、工具注册表、会话日志、Agent 主循环等全部是插件，彼此通过服务与事件协作。
  • 热插拔与可逆：插件可以动态挂载和卸载，卸载时能自动清理其产生的影响（如监听器、资源占用），确保系统状态可控。
  • 无特权内核：开发者无需修改或 fork 官方源码，仅通过编写和挂载插件就能替换或扩展任何一层能力。

四种预设运行模式

为了适应不同场景，Harness 官方内置了四种开箱即用的模式：

  • 标准模式 (Standard)：功能最完整的编码 Agent，开放文件编辑、Shell、搜索、计划、子代理等能力，适合日常写代码和通用任务。
  • PTC 模式 (Programmatic Tool Calling)：在标准模式之上，允许模型生成一段 TypeScript 程序来批量组合和调用工具，适合需要大量工具调用、多步骤筛选或汇总的复杂任务。
  • 极简模式 (Minimal)：仅保留最基础的终端 Shell 和文件编辑工具。主要用于测试模型的“裸 Agent”能力或进行基准测试（Benchmark）。
  • 创造模式 (Cordis)：拥有标准模式的全部能力，并额外开放对运行时的检查、插件实验和自定义预设创建等开发能力，适合开发 Harness 插件或深度定制。

与 Claude Code / Codex 的定位差异

Harness 常被拿来与 Claude Code、OpenAI Codex 对比，但它们的定位有本质区别：

  • Claude Code / Codex：是成品工具（精装房）。工具、会话管理、沙箱等被封装在一个闭源外壳中，开箱即用，但定制空间有限。
  • DeepSeek Harness：是开发者底层工具（毛坯房+施工图）。它提供的是一个 Agent 运行时底座，编码只是其预置的一套组合。开发者可以用它拼装出与编程完全无关的 Agent，或深度定制每一个环节。

配置

C:/Users/用户名/.dsh/ 目录是 Harness 的数据大本营，包含了所有配置文件和缓存数据。

  • sessions/：存放所有会话记录，每个会话的完整历史记录（对话、工具调用等）都会被持久化存储在这里，方便你随时恢复或回顾。
  • settings.yaml：存储你的个人设置，比如默认使用的 Agent 预设、默认模型等。
  • .credentials.yaml：存储你配置的 API 密钥（例如你的 DeepSeek API Key）。
  • storages/：存放各类插件的持久化数据。
