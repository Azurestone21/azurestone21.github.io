【React】Class 组件 vs 函数组件

类组件 vs 函数组件

一、Class 组件特点

核心特点：

  • 使用 ES6 class 语法，继承 React.Component
  • 通过 this.state 管理状态，this.setState() 更新
  • 拥有完整生命周期方法（componentDidMount、componentDidUpdate、componentWillUnmount 等）
  • 通过 this 访问 props、state 和方法
  • 需要手动绑定事件处理函数的 this（或用箭头函数）
  • 可以使用 React.PureComponent 做浅比较优化

二、函数组件特点

核心特点：

  • 本质是普通 JavaScript 函数，接收 props 返回 JSX
  • 使用 Hooks（useState、useEffect、useMemo、useCallback 等）管理状态和副作用
  • 无 this，避免 this 绑定问题
  • 代码更简洁，逻辑按”关注点”组织（自定义 Hook 可复用逻辑）
  • 每次渲染都是一个独立的闭包（需注意闭包陷阱）

三、主要区别对比

维度 Class 组件 函数组件
语法 ES6 class 继承 普通函数 + Hooks
状态管理 this.state / setState useState / useReducer
生命周期 独立生命周期方法 useEffect 统一处理
this 绑定 需手动 bind 无需 this
逻辑复用 HOC / render props 自定义 Hook（更直观）
代码量 较冗长 更简洁
性能 需 shouldComponentUpdate/PureComponent 优化 React.memo + useMemo/useCallback
错误边界 支持 componentDidCatch 暂不支持（仍需 Class）
this 陷阱 有 无
闭包陷阱 无 有（依赖数组需正确）
官方推荐 维护旧代码 ✅ 新代码首选

四、关键差异深入

1. 状态与副作用组织方式

Class 把同一逻辑分散在多个生命周期中（如订阅在 componentDidMount 订阅、componentWillUnmount 取消）；函数组件用 useEffect 把相关逻辑聚在一起，更易维护。

2. 逻辑复用

  • Class：HOC、render props，易造成嵌套地狱（wrapper hell）
  • 函数：自定义 Hook 抽离逻辑，组合灵活

3. 心智模型

Class 组件是”实例”模型（组件实例持久存在，state 挂载其上）；函数组件是”每次渲染一次快照”模型（每次渲染的 props/state 都是当次的值），这也是闭包陷阱的根源。

五、选型建议

  • 新项目：优先函数组件 + Hooks（官方推荐方向）
  • 需要错误边界：目前仍需 Class 组件（或使用第三方库）
  • 维护老项目：保持原风格，逐步迁移
  • 复杂状态逻辑：函数组件配合 useReducer 更清晰

注：React 官方已明确函数组件 + Hooks 是未来方向，Class 组件不会移除但不再是推荐写法。
