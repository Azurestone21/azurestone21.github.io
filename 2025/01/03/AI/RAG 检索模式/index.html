RAG 检索模式

RAG 检索模式

前言：检索，RAG 系统的天花板

RAG（Retrieval-Augmented Generation）的核心流程可以概括为四个字：先搜，再答。

检索层质量直接决定了 RAG 系统的上限——“搜得好”，LLM 才有好的“参考资料”，回答才靠谱；“搜得烂”，LLM 只能“编”，结果一塌糊涂。

因此，理解并选对检索模式，是构建一个高可用 RAG 系统的第一步。

一、基础检索：两条底层技术路线

所有检索模式都建立在两条底层技术路线之上。

1.1 稀疏检索（关键词检索）

稀疏检索（Sparse Retrieval） 是信息检索领域最经典的检索范式，其核心逻辑是通过关键词匹配来衡量文档与查询的相关性。

在 RAG 系统中，稀疏检索通常借助全文搜索引擎（如 PostgreSQL FTS 或 Elasticsearch）实现。与简单的 LIKE '%keyword%' 模糊匹配不同，成熟的全文检索引擎具备以下核心能力：

  1. 分词（Tokenization）：将连续文本切分为有意义的词元（Token）。
  2. 词形归一化（Lexeme Normalization）：将同一词根的不同形态归并（如 running → run），中文场景下可配合停用词过滤（如去除”的、了”等）。
  3. 相关性排序（Ranking）：利用 TF-IDF 或 BM25 等算法计算词频统计分数（如 PostgreSQL 的 ts_rank），对匹配结果进行相关性排序。

核心原理：基于 词袋模型（Bag-of-Words，BoW）——将文本视为一个”装满词语的袋子”，忽略语法和语序，仅统计词频。TF-IDF 和 BM25 本质都是在 BoW 生成的稀疏向量上进行加权计算。

代表算法：

  • TF-IDF：词频（Term Frequency）× 逆文档频率（Inverse Document Frequency），衡量词对文档的重要程度。
  • BM25：TF-IDF 的进阶版，引入了词频饱和度和文档长度归一化，是当前工业界最主流的稀疏检索算法。

词频（TF） 负责统计词在当篇文档中出现的频率，反映“这个文档有多符合这个词”。
逆文档频率（IDF） 负责统计该词在整个知识库中的稀有程度，反映“这个词有多能区分文档”。
如果一个词既在文档中频繁出现（TF高），又在整个库里极其罕见（IDF高），那么它就是这篇文章的核心关键词，搜索结果会因高权重而排名靠前。

优势：

  • 精确匹配能力强：对专有名词、产品型号、错误码等精确标识符匹配精准。
  • 可解释性强：匹配逻辑透明，可追溯每条结果的匹配依据。
  • 计算轻量：基于倒排索引，资源消耗低，适合海量数据。

局限：

  • 语义盲区：无法理解同义词（如”苹果”和”iPhone”）、近义词和上下文语义。
  • 对输入敏感：拼写错误、口语化表达、同义表述会导致匹配失败。

1.2 密集检索（语义检索）

密集检索（Dense Retrieval） 是现代 RAG 系统的核心技术，其核心思想是将文本映射到稠密向量空间，通过向量相似度来衡量语义相关性。

核心原理：文本 → Embedding 模型 → 稠密向量（如 768 维/1536 维）→ 向量数据库（ANN 索引）→ 相似度检索（如余弦距离）。

代表模型：

  • OpenAI：text-embedding-3-small / text-embedding-3-large
  • Cohere：embed-english-v3.0 / embed-multilingual-v3.0
  • BGE 系列：BAAI/bge-large-zh-v1.5（中文表现优异）
  • 开源通用：sentence-transformers/all-MiniLM-L6-v2、intfloat/e5-mistral-7b-instruct

优势：

  • 语义理解：不同措辞、不同语言的表述都能匹配，真正理解”你想问什么”。
  • 跨语言能力：多语言 Embedding 模型支持中英文互搜。
  • 容错性强：对拼写错误、口语化表达、不完整输入有不错的容忍度。

局限：

  • 精确匹配弱：对专有名词、产品型号、低频术语的匹配能力较弱——这些词在训练数据中频次低，向量表征不充分。
  • 黑盒属性：难以追溯和解释”为什么返回了这条结果”，调试和优化难度较高。
  • 计算成本较高：需要维护向量索引，检索延迟和资源消耗均高于稀疏检索。

小结：为什么需要混合检索？

能力维度 稀疏检索 密集检索
精确匹配（产品型号、错误码） ✅ 强 ❌ 弱
语义理解（同义词、口语化） ❌ 弱 ✅ 强
跨语言检索 ❌ 弱 ✅ 强
可解释性 ✅ 强 ❌ 弱
计算成本 ✅ 低 ⚠️ 较高

二、混合检索（Hybrid Retrieval）：生产级 RAG 的标配

“单一检索方式，无论是语义还是关键词，都有局限性。”

混合检索的核心目标，是整合稠密向量检索与稀疏 BM25 检索的优势——既保留语义泛化能力，又守住精准匹配能力，实现“语义不丢、精准不漏”，这也是混合检索成为生产级 RAG 标配的根本原因。

2.2 两种主流融合算法

1. 加权求和（Weighted Sum）

将关键词分数和语义分数分别加权后相加，需要手动调参控制权重。优点是控制粒度精细，缺点是依赖分数校准。

2. RRF（倒数排序融合）

不关心具体分数，只关注文档在各自结果中的排名位置，公式为 1/(k+rank)。优点是结果稳健、无需调参，缺点是丢失了分数信息。

💡 工程建议：混合检索已在 2026 年成为生产级 RAG 的标准配置，数据库引擎也已原生支持稀疏向量与稠密向量的联合索引。

三、查询增强检索：从“被动搜”到“主动改”

在检索之前对用户问题进行加工，解决“问得模糊”或“问题复杂”的问题。

3.1 查询改写（Query Rewriting）

在多轮对话中，用户经常会问“它怎么样？”或“具体说说第二个”——这种依赖上下文的查询，直接扔给检索系统必然失效。

解决方案：
在检索前将上下文传入 LLM，将口语化、有歧义的查询改写为独立、信息完整的查询语句。

虽然多轮改写需要传入上下文，但不要把整个聊天记录原封不动地塞进 Prompt 去让 LLM 改写。这样会导致 token 成本过高以及聊天中的信息干扰。

采用 “滑动窗口”，仅提取最近 2-3 轮含有实体或明确指令的对话；或者不传给通用 LLM，而是利用 SlidingWindow + LLMChain 提取本轮最核心的查询意图（只提取主语、谓语和关键宾语）。

3.2 多路查询（Multi-Query）

用 LLM 将一个问题扩写成 3-5 个不同角度的问法，分别检索后合并去重，大幅提升召回率。

3.3 HyDE（假设性文档）

让 LLM 针对问题先生成一段虚构的回答，然后用这个“假回答”去检索。因为答案往往比问题更贴近文档的原始措辞，能有效提升匹配精度。

四、层次检索：解决“小块准、上下文不全”的困境

标准 RAG 将文档切成小块进行检索，优点是精准命中，但缺点是上下文碎片化——小块内容准确，但缺乏完整语境。

4.1 父文档检索（Parent Document Retrieval）

核心思想：将文档切成小颗粒度的子块（如 150 字）用于向量检索，确保精准命中；但将大颗粒度的父块（如整个章节）返回给 LLM，确保上下文完整。

LangChain 提供了 ParentDocumentRetriever 原生支持这种模式。

4.2 层次化 RAG（Hierarchical RAG）

构建多级文档索引：

  • Level 1：文档摘要（高层，快速匹配）
  • Level 2：章节摘要（中层，主题匹配）
  • Level 3：详细分块（底层，精确内容）

检索时采用渐进式检索——从摘要层快速定位，再逐层深入细粒度内容。

五、精排：检索后的“最后一公里”

检索到的 Top-K 结果中，必然混入不相关或低相关的内容。重排序（Rerank） 就是对初步召回结果进行二次评估和精细排序。

5.1 为什么需要 Rerank？

  • Embedding 模型擅长“海选”，但精度有限
  • 多召回（如 Top 50）必然引入噪声
  • 噪声直接喂给 LLM，增加 Token 成本且干扰回答质量

5.2 典型工作流程

  1. 粗筛：混合检索从知识库中召回 Top-K（如 50 篇）
  2. 精排：Rerank 模型（如 Cohere Rerank、Cross-Encoder）对候选文档逐一计算相关性分数
  3. 交付：只将 Top-N（如 5 篇）最相关文档传递给 LLM

Rerank 模型（交叉编码器）与 Embedding 模型（双编码器）的本质区别：前者将“问题+文档”成对输入进行深度语义分析，精度更高但计算更重；后者将文本独立编码为向量，速度快但精度有限。

六、新兴检索范式：超越传统 RAG

6.1 Graph RAG

引入知识图谱来增强检索，通过实体关系和社区摘要实现全局理解和跨文档知识关联。2025-2026 年间，LightRAG、nano-GraphRAG 等轻量级变体已趋于成熟。

6.2 Agentic RAG

LLM 不再是被动的检索-生成管道，而是自主 Agent——能根据任务复杂度自主决定是否需要检索、使用何种工具、以及何时停止迭代。

6.3 Corrective RAG

引入评估器对检索结果进行质量评估，若发现检索噪声或错误上下文，自动触发网络搜索回退等补救机制。

总结：检索模式演进路线图

阶段 检索模式 核心特点 适用场景
入门 单一向量检索 快速上手，语义理解 MVP 验证、教学演示
标配 混合检索（向量 + BM25） 语义 + 关键词，全面覆盖 生产级 RAG 必选
进阶 混合检索 + 查询增强 + Rerank 召回率与精度双提升 高精度问答、企业知识库
高级 层次检索 / Graph RAG 处理复杂文档结构与实体关系 财报分析、技术白皮书
前沿 Agentic RAG / Corrective RAG 自主决策、动态纠错 企业级 Copilot、复杂任务规划
