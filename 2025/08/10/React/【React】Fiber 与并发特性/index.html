【React】Fiber 与并发特性

Fiber 与并发特性

一、并发是什么

首先要清楚：并发不是并行 。

  • 并行 ：多线程同时执行。
  • 并发 ：单线程下交替执行，看起来像同时进行。

二、Fiber 提供了并发的基础设施

并发需要三个能力，Fiber 刚好提供了：

可中断

  • Fiber 用链表遍历（child / sibling / return），不依赖 JS 调用栈。
  • 当前处理到哪个节点存在全局 workInProgress，随时可以暂停、恢复。

可丢弃

  • 双缓存机制：current 树不动，WIP 树在内存中构建。
  • 中断或插队时，直接丢弃 WIP 树，current 不受影响。
  • 下次从 root.current 重新开始。

可区分优先级

  • Lane 模型给不同更新分配不同优先级。
  • 优先级挂在 Fiber 的 lanes / childLanes 上。
  • 高优先级任务可以打断低优先级任务。

三、并发特性

Suspense

  • 组件抛 Promise 时，标记 SuspendedLane。
  • 不阻塞其他 Lane 的渲染。
  • Promise resolve 后用 RetryLane 重试。

Transition

  • startTransition：函数式 API，任何地方都可以使用
  • useTransition：Hook，只能在组件中使用
  • 把更新标记为 TransitionLane，低优先级。
  • 可被高优先级（如用户输入）打断。
  • 适合搜索框输入 + 列表更新等场景。

useDeferredValue

  • 延迟某个值的更新，标记为低优先级。
  • 类似 useTransition，但作用于值。

自动批处理

  • React 18 中所有更新默认批处理。
  • 基于 Lane 和微任务调度，不再限于 React 事件。
  • flushSync 可强制同步刷新。

React 18 createRoot vs ReactDOM.render

维度 ReactDOM.render createRoot
渲染模式 Legacy 模式，同步不可中断 Concurrent 模式，可中断、可恢复
