【React】Fiber 的调度和优先级

Fiber 的调度和优先级

React 把更新拆成带优先级的任务，交给 Scheduler 按时间片调度。高优先级任务可以打断低优先级任务，Render 阶段可中断，Commit 阶段不可中断。优先级通过 Lane 模型表示，挂在 Fiber 的 lanes / childLanes 上。

一、为什么需要调度

没有调度时的问题：

  • 一次更新可能构建整棵 Fiber 树，耗时长。
  • 主线程被长时间占用，用户输入、动画无法响应。
  • 高优先级更新（如输入框打字）被低优先级更新（如大数据列表渲染）阻塞。

调度要解决三件事：

  1. 可中断：长任务拆成小任务，让出主线程。
  2. 可插队：高优先级任务优先执行，低优先级可被打断或延后。
  3. 可恢复：中断后能从上次位置继续。

二、Scheduler：时间片与任务队列

Scheduler 是 React 独立出来的一个包（scheduler），不依赖 React。

Scheduler决定什么时候执行什么任务，并在浏览器空闲时执行，让高优先级任务先跑，低优先级任务可被打断。

优先级

Scheduler 暴露 5 个优先级：

优先级 值 来源 超时 用途
ImmediatePriority 1 SyncLane 0ms 必须同步执行，如同步setState
UserBlockingPriority 2 InputContinuousLane / SelectiveHydrationLane 250ms 用户输入直接触发的更新（输入、点击）
NormalPriority 3 DefaultLane 5000ms 常规异步更新，如setTimeout 回调
LowPriority 4 TransitionLane 10000ms startTransition 包裹的更新
IdlePriority 5 无 Lane 对应 未设定 空闲时执行，如离屏内容渲染

React 内部会把 Lane 映射到这些优先级。

任务队列

Scheduler 内部使用二叉最小堆维护两个队列：

  • timerQueue （延迟队列）：堆顶是 startTime 最小的，即”最早可以开始”的任务。用 requestHostTimeout （即 setTimeout ）来驱动，因为它需要精确的时间等待。
  • taskQueue （就绪队列）：堆顶是 expirationTime 最小的，即”优先级最高/过期最早”的任务。用 requestHostCallback （宿主空闲回调）来驱动，因为它需要在主线程空闲时被执行，且支持时间切片。

堆顶永远是 sortIndex 最小的任务（最高优先级/最早过期），取任务 O(1)，插入 O(log n)。

每次取优先级最高的任务执行。

任务对象

  • startTime ：任务应该开始执行的时间（有 delay 时为 currentTime + delay ，否则就是 currentTime ）
  • timeout ：根据优先级决定的超时时间（越紧急的优先级 timeout 越小）

工作流程

一、入队

  1. 计算 startTime （立即任务用当前时间，延迟任务用 当前时间 + delay ）。
  2. 按优先级查表得到 timeout ，算出 expirationTime = startTime + timeout 。
  3. 创建 Task 对象。
  4. startTime > currentTime ？
    • 是 → 按 sortIndex = startTime 入 timerQueue ，若它是最早到期的延迟任务则注册 requestHostTimeout(handleTimeout, 剩余等待时间) 。
    • 否 → 按 sortIndex = expirationTime 入 taskQueue ，若无正在执行且未调度则触发 requestHostCallback() 。

二、触发执行

  1. requestHostCallback 通过 setImmediate / MessageChannel / setTimeout(0) 把 performWorkUntilDeadline 投递到下一个宏任务。

三、执行循环

  1. performWorkUntilDeadline → 调用 flushWork → 调用 workLoop 。
  2. workLoop 开始时先调 advanceTimers 把到期延迟任务从 timerQueue 搬到 taskQueue 。
  3. 取 taskQueue 堆顶任务进入 while 循环：
    • 该 yield 了？ （未过期且已运行超 5ms）→ break，下一轮宏任务续跑。
    • 任务被取消 unstable_cancelCallback？（ callback === null）→ pop，取下一个。
    • 执行 callback ，传入 didUserCallbackTimeout （是否已超时）。
    • 返回了续包函数 Continuation Callback？ → 塞回 task，主动 yield return true，下一轮从这个任务继续。
    • 正常完成？ → pop 移除，续取下一个。
  4. 循环结束：
    • 还有任务未执行 → return true（续跑下一轮宏任务）。
    • taskQueue 空但 timerQueue 有任务 → 注册 requestHostTimeout 等下一个延迟。
    • 两队列都空 → return false（结束）。

四、延迟任务到期接力

  1. handleTimeout （setTimeout 触发）： advanceTimers 搬任务入队，然后按队列情况触发 requestHostCallback 或重新注册下一个 requestHostTimeout 。

任务过期与饥饿

  • 每个任务有 expirationTime，越早创建、优先级越高，过期越早。
  • 在 workLoop 中，如果任务已过期（expirationTime <= currentTime），不再让出，强制执行。
  • 防止低优先级任务被无限插队。

两种调度方式

方式 触发时机 用途
scheduleCallback 按优先级延迟执行 普通更新
scheduleSyncCallback 立即同步执行 高优先级、必须同步的更新

时间切片

为了实现时间切片，React 需要一种机制来定期检查“是否该让出主线程”。React 自研了调度器（Scheduler），底层通常使用 ‌MessageChannel来模拟宏任务调度。

  1. 用 MessageChannel 触发宏任务。
  2. 每个时间片 5ms ：每个宏任务开始时记录一个起点 startTime ， shouldYieldToHost() 不断检查当前时间和起点的差值是否超过 5ms （ frameYieldMs ）。。
  3. 检查让出 ：workLoop 每执行一个任务检查 shouldYieldToHost()，超时就 break，返回 true 表示还有任务，performWorkUntilDeadline 再 postMessage 触发下一轮。
  4. 当前宏任务 return → JS 引擎空了 → 浏览器趁机做渲染、响应用户输入 → 下一个宏任务触发 → startTime 重置为现在 → 重新计 5ms。

为什么是 5ms？

一帧约 16.7ms，留一部分给浏览器渲染、合成、用户输入。5ms 是 React 的经验值，既能推进任务，又不太影响帧率。可以通过 frameYieldMs 配置。

为什么用 MessageChannel 不用 setTimeout？

浏览器规范规定： 嵌套层级 ≥ 5 层的 setTimeout(fn, 0) 实际会被夹紧到 4ms 延迟 。Scheduler 会反复续投宏任务，几轮嵌套下来延迟就从 0ms 变 4ms，调度频率骤降。MessageChannel 没有这个限制， postMessage 永远是真正的下一个宏任务，0ms 延迟。

为什么不用 requestIdleCallback

  1. 兼容性差（Safari 长期不支持）。
  2. 触发不稳定，任务可能饿死。
  3. 无法控制优先级。
  4. 帧率不可控。

Scheduler 与 Fiber 的分工

组件 职责
Scheduler 决定何时执行，管理任务队列、优先级、时间切片
Fiber Reconciler 决定执行什么，构建 WIP 树、diff、打 flags
Renderer 决定怎么落 DOM，commit 阶段同步操作

Fiber 的 workLoopConcurrent 每个单元执行完调用 shouldYield()，如果该让出，返回 continuation，Scheduler 保存后下一帧继续。

三、Lane：React 的优先级模型

Lane 是什么

Lane 是 React 的优先级车道，用位掩码表示优先级，每个二进制位代表一类优先级；Lanes 是多个车道的集合，用位运算管理更新批次。

为什么用位掩码

每个 Lane 是 2 的幂，二进制只占一位：

好处：

操作 代码 说明
合并 a | b 多个 Lane 合并成一个集合
判断包含 (a & b) !== 0 判断是否包含某优先级
取最高优先级 lanes & -lanes 取最低位的 1
清除 lanes & ~remove 移除某优先级

如果用普通整数（1、2、3、4），位会重叠，无法表示优先级集合。

常见 Lane

Lane 优先级 场景
SyncLane 最高 点击、输入
InputContinuousLane 高 连续事件（mousemove、scroll）
DefaultLane 中 普通setState、数据请求回调
TransitionLanes 低 useTransition、startTransition
RetryLanes 低 Suspense 重试
IdleLane 最低 空闲任务
OffscreenLane 最低 离屏渲染

四、Lane 与 Scheduler 优先级的映射

多对一。Lane 更精细，负责管理更新批次、来源、中断、跳过子树；Scheduler 只负责粗粒度调度。映射发生在 ensureRootIsScheduled：

映射发生在 ensureRootIsScheduled：

Lane Scheduler 优先级
SyncLane Immediate（实际同步执行）
InputContinuousLane UserBlocking
DefaultLane Normal
TransitionLanes Normal 或 Low
IdleLane Idle

为什么 Lane 多、Scheduler 少？

  • Lane 负责精细管理更新批次（区分来源、批次、中断、跳过子树）。
  • Scheduler 只负责粗粒度调度（何时跑、能否打断）。
  • Scheduler 内部还有 expirationTime 做更细排序，防饥饿。

一句话：Lane 是精筛，Scheduler 是粗筛。

五、调度完整流程

六、高优先级如何打断低优先级

并发模式下：

关键点：

  • 高优先级可以打断低优先级。
  • 被打断的低优先级 WIP 树会被丢弃，下次重新构建。
  • 因为 Render 阶段不碰真实 DOM，丢弃是安全的。
  • Commit 阶段不可中断，所以不会出现 UI 中间态。

七、bailout：跳过无更新的子树

beginWork 里：

  • 如果当前 Fiber 没有当前 Lane 的更新，且子树也没有，直接跳过。
  • 这是 Lane 模型的重要优化：只处理有更新的子树。

八、优先级和 Suspense / Transition

Suspense

  • 组件抛 Promise 时，React 标记该 Lane 为 SuspendedLane。
  • 不阻塞其他 Lane 的渲染。
  • Promise resolve 后，用 RetryLane 重新渲染。

useTransition

  • startTransition 内的更新分配 TransitionLane。
  • 高优先级更新可以打断它。
  • isPending 表示低优先级更新还没完成。

useDeferredValue

  • 类似 startTransition，把派生更新放到低优先级。
  • 高优先级更新先渲染，低优先级稍后跟上。

九、Sync 模式 vs Concurrent 模式

维度 Sync 模式 Concurrent 模式
调度 同步、不可中断 时间片、可中断
优先级 不生效，FCFS Lane 生效
打断 不支持 高优先级可打断低优先级
WIP 丢弃 不会 可能被丢弃重建
适用 React 17 及以前 React 18+

React 18 的 createRoot 默认开启并发特性。
ReactDOM.render（旧 API）走 Sync 模式。

十、过期与饥饿

  • 低优先级更新长时间得不到执行，Lane 会过期（expiredLanes），提升优先级。
  • 避免 transition 等低优先级更新被无限插队。

十一、和 Fiber 的关系

Fiber 是调度的载体：

  • 每个 Fiber 节点有 lanes / childLanes，记录优先级。
  • 链表结构让遍历可中断、可恢复。
  • alternate 让 WIP 树可以被丢弃重建。
  • flags 让 Commit 阶段知道要做什么。

Lane 是调度的优先级语言：

  • 位掩码表示优先级。
  • 挂在 Fiber 上，随更新冒泡到根。
  • 渲染时取最高优先级 Lane。

Scheduler 是调度的执行器：

  • 时间片控制。
  • 任务队列。
  • 优先级映射。

三者配合：

Lane 决定“哪些更新先做”，Scheduler 决定“什么时候做”，Fiber 决定“怎么做、做完怎么提交”。

十二、总结

React 用 Lane 位掩码表示更新优先级，挂在 Fiber 的 lanes / childLanes 上，随更新冒泡到根；Scheduler 用时间片按优先级调度任务，高优先级可打断低优先级；Render 阶段可中断、可丢弃，Commit 阶段同步不可中断。三者配合，实现了可中断、可恢复、可插队的并发渲染。
