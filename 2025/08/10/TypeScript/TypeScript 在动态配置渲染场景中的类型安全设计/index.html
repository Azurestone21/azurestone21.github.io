2. 目标

我们希望实现以下效果：

  • 当 moduleType 为 'person' 时，TypeScript 能自动知道 config.data 的类型是 IPersonData。
  • 渲染时，根据 config.moduleType 自动选择正确的组件，并且组件 props 类型完全匹配，无需手动断言。
  • 新增模块时，如果遗漏任何映射或类型不匹配，能在编译期报错。

4. 关键类型技巧解析

4.1 交叉类型收窄 moduleType

ICompConfigs<IPersonData> 中 moduleType 是 TModuleType（宽泛联合），{ moduleType: 'person' } 中 moduleType 是字面量 'person'，交叉后：

交叉类型不会覆盖，而是取交集，因此 moduleType 被收窄为 'person'，这正是我们需要的判别字段。

4.2 映射类型 + 索引访问生成联合

{ [K in keyof ModuleDataMap]: ... }[keyof ModuleDataMap] 是 TypeScript 中从映射类型提取所有值联合的惯用模式：

  1. 先用映射类型生成一个“类型字典”。
  2. 再通过索引访问取出字典中所有值的联合。

这样避免了手动列举所有模块，实现了自动化。

4.3 Extract 提取联合中的特定成员

Extract<Union, U> 从联合类型 Union 中提取出能赋值给 U 的成员。在这里，Extract<ModuleConfig, { moduleType: K }> 精确提取出某个模块对应的配置类型，确保组件只接收自己模块的数据。

5. 新增模块时的维护步骤

当需要新增一个模块（如 'video'）时：

  1. 定义该模块的 data 类型（如 IVideoData）。
  2. 在 ModuleDataMap 中添加一行：video: IVideoData;
  3. 在 ComponentMap 中添加对应组件：video: VideoComponent,（组件 props 需匹配 ICompConfigs<IVideoData> & { moduleType: 'video' }）
  4. 若 TModuleType 未包含 'video'，记得添加。

如果遗漏任何一步（例如忘记在 ComponentMap 中添加组件），TypeScript 会提示 ComponentMap 类型缺少属性，从而在编译期发现问题。

6. 总结

通过可辨识联合和强类型组件映射表，我们可以在动态配置渲染场景中实现完整的类型安全：

  • 无 any：所有数据类型明确，避免运行时类型错误。
  • 自动收窄：根据 moduleType 自动推导出具体配置和组件 props 类型。
  • 可维护性：新增或修改模块时，类型系统会强制检查所有关联映射，减少遗漏。
  • 开发体验：编写组件或渲染逻辑时获得完整的类型提示。
