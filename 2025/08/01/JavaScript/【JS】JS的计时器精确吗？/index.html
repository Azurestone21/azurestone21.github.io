【JS】JS的计时器精确吗？

【JS】JS的计时器精确吗？

结论：不精确。更准确地说，setTimeout / setInterval 只保证“不早于指定延迟执行”，不保证“恰好在某个时间点执行”。实际执行时间通常会晚于设定值，误差可能从几毫秒到几秒甚至更久。

为什么不准？

  1. JS 是单线程 + 事件循环

    • 计时器到期后，回调不会立刻执行，而是被放进任务队列，变成宏任务。
    • 必须等当前调用栈清空、微任务清空后，主线程才可能取出这个回调执行。
    • 如果主线程正在跑长循环、复杂计算、大量 DOM 操作，计时器回调只能等着。

  2. 浏览器/Node 有最小延迟和钳制

    • 浏览器通常有最小延迟，setTimeout(fn, 0) 往往不是 0ms。
    • HTML 规范中，嵌套超过 5 层的 setTimeout，如果延迟小于 4ms，会被强制设为 4ms。
    • Node.js 中 setTimeout 最小通常是 1ms。

  3. 后台标签页会被节流

    • 页面不可见时，浏览器会限制计时器频率。
    • Chrome 中隐藏标签页的计时器可能被限制到 1 秒一次，长时间后台甚至更久。
    • 这是为了省电和减少后台资源占用。

  4. setInterval 会漂移或堆积

    • 如果回调执行时间超过间隔，下一次触发就会延迟。
    • 某些情况下还可能连续触发或排队，导致节奏不稳定。
    • 所以 setInterval(fn, 100) 不代表每 100ms 精确执行一次。

  5. 宿主环境和系统调度影响

    • 计时器不是 JS 引擎本身实现的，而是浏览器或 Node 提供的宿主 API。
    • 操作系统调度、CPU 负载、电源管理、垃圾回收等都会影响回调执行。
    • 浏览器通常有独立计时器线程负责倒计时，但到期后回调仍要回主线程排队执行。

  6. 微任务优先于计时器宏任务

    • Promise.then、queueMicrotask 等微任务会在计时器宏任务之前执行。
    • 所以即使计时器到期，也要等微任务清空。

怎么提高精度？

  • 不要用 setInterval 做精确周期任务，改用递归 setTimeout + performance.now() 校正：

  • 把重计算放到 Web Worker，避免阻塞主线程。

  • 动画用 requestAnimationFrame，它跟随屏幕刷新率，通常 60Hz / 120Hz。

  • 测量时间用 performance.now()，不要用 Date.now()，后者可能受系统时间调整影响。

  • 音频等硬实时场景用 AudioWorklet、AudioContext.currentTime 等专用机制。

  • Node.js 中可用 process.hrtime.bigint() 做高精度测量。

总结：JS 计时器适合普通延迟和调度，不适合硬实时精确计时。 如果只是“大概 100ms 后执行”，它够用；如果要求“必须精确到 1ms 或微秒级”，它做不到。
