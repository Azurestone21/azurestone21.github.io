图片格式

以下为优化补充版，修正了部分过时或不严谨表述，并补全“图片 Base64”部分。

一、位图与矢量图

  • 位图：由像素组成，放大会失真。常见：JPEG、PNG、WebP、BMP、GIF。
  • 矢量图：由数学路径描述，放大缩小不失真。典型：SVG。

二、常见图片格式

格式 压缩 透明 动画 特点 适用场景
JPEG 有损 不支持 不支持 文件较小，色彩丰富 照片、复杂图像
PNG 无损 支持 不支持 质量高，体积较大 图标、截图、透明图
WebP 有损/无损 支持 支持 体积小，现代浏览器支持好 网页图片、透明图、动图
BMP 通常无压缩 部分支持 不支持 文件很大 Windows 内部、临时图
GIF 无损 LZW，但限 256 色 支持布尔透明 支持 适合简单动画 表情包、简单动图
SVG 矢量 支持 支持 可缩放、可编辑、可脚本化 Logo、图标、图表、地图

1. JPEG/JPG

  • 有损压缩点阵图，适合存储照片。
  • 不适合线框图、企业 Logo、文字等需要高清晰度的图片。
  • 不支持透明、半透明背景。
  • 文件相对较小，但压缩过度会出现块状噪点。
  • 支持渐进式 JPEG，可先模糊后清晰加载。

JPEG：正式名称，也是制定该标准的组织名“Joint Photographic Experts Group”的缩写。
JPG：只是 JPEG 格式常见的文件扩展名，通常被认为是缩写版。
为什么会有两个名字？
早期 Windows / DOS 系统对文件扩展名有 3 个字符限制，.jpeg 有 4 个字符，所以被缩短成 .jpg。后来这个习惯沿用下来，.jpg 反而更常见。

2. PNG

  • 无损压缩点阵图，分为 PNG-8 和 PNG-24。
  • PNG-8：索引色，最多 256 色，通常支持透明背景，不支持半透明。
  • PNG-24：直接色，文件比 BMP 小；带 alpha 通道时通常称 PNG-32，支持透明和半透明。
  • 适合图标、图形、截图、需要透明度的场景。
  • 相比 JPEG，文件通常更大。

3. WebP

  • 由 Google 开发，目标是加快图片加载速度。
  • 支持有损和无损压缩，支持透明、半透明和动画。
  • 相同质量下，WebP 通常比 PNG 小约 26%，比 JPEG 小约 25%～35%。
  • 现代浏览器支持较好：Chrome、Edge、Firefox、Opera、Safari 14+ 等。
  • 老版本浏览器可能需要回退到 JPEG/PNG。

4. BMP

  • 无损，支持索引色和直接色。
  • 通常不压缩，因此文件很大。
  • 适合 Windows 内部使用，不适合网页直接使用。

5. GIF

  • 无损 LZW 压缩，采用索引色，最多 8bit / 256 色。
  • 支持透明和动画。
  • 适合简单动画、表情包，但色彩丰富图片会失真。
  • 文件相对较小，但动画帧多时体积会变大。

6. SVG

SVG：可伸缩矢量图形，Scalable Vector Graphics，使用 XML 定义图形，是 W3C 标准。

特点：

  • 基于路径的矢量图形，放大缩小不失真。
  • 任意分辨率下保持清晰，适合响应式设计。
  • 可通过文本编辑器创建和修改。
  • 可被搜索、索引、脚本化或压缩。
  • 可嵌入 HTML5。
  • 可与 JavaScript 结合，实现动画和交互。
  • 大多数现代浏览器都支持。

7. 其他现代格式

  • AVIF：压缩率很高，支持透明和动画，但兼容性略逊于 WebP。
  • HEIF/HEIC：苹果设备常用，网页兼容性一般。
  • ICO：网站图标 favicon 常用。

三、使用场景与兼容性

使用场景

  • GIF：适合动画和低色彩需求场景。
  • JPEG：适合照片存储。
  • PNG：适合需要透明度的图标和图形。
  • SVG：适合高清晰度矢量图形、Logo、图表。
  • WebP：适合需要减少数据传输量的网页图片。
  • AVIF：适合追求极致压缩且可接受兼容性回退的场景。

四、字体图标

字体图标本质上是字体，把图标做成字体文件，通过 @font-face 引入。

特点

  • 可放大缩小、更换颜色。
  • 体积小、请求少、加载快、复用性高。
  • 缺点：颜色不丰富，通常只能是单色；多色需用 CSS 渐变文字或改用 SVG。
  • 可访问性较差，建议配合 aria-hidden 或 aria-label。

@font-face

@font-face 用于指定自定义字体，可从远程服务器或本地安装字体加载。

  • local()：从本地查找指定字体名称。
  • url()：从远程服务器加载字体。
  • 浏览器按 src 顺序尝试，通常优先 woff2。

常见字体格式：

  • woff2：体积最小，现代浏览器首选。
  • woff：兼容性较好。
  • ttf / otf：常见，但体积较大。
  • eot：旧 IE。
  • svg：旧 iOS。

字体图标原理

  1. 制作 SVG 格式图标。
  2. 使用 FontCreator 等软件导入字体文件，并设置 Unicode 编码。
  3. 生成兼容浏览器的字体文件：ttf、otf、woff、eot、svg。
  4. 通过 CSS @font-face 导入字体，设置公共样式。
  5. 将 icon 名称与 Unicode 编码一一对应。

字体图标 vs SVG 图标

  • 字体图标：单色、CSS 控制方便、兼容性好；多色困难、可访问性弱。
  • SVG 图标：支持多色、精细、可访问、可动画；需要合理管理体积和请求。
  • 现代项目更推荐 SVG Symbol Sprite 或组件化 SVG。

五、Base64

Base64 不是图片格式，而是一种编码方式。它把二进制图片编码成字符串，直接嵌入 HTML、CSS 或 JS 中，形式是 Data URI。

优点

  • 减少 HTTP 请求。
  • 适合小图标、小背景图。
  • 适合单文件 HTML、邮件模板。
  • 图片不会因路径问题丢失。

缺点

  • Base64 后体积约增大 33%。
  • 不能单独缓存，修改图片需重新构建 CSS/HTML。
  • 增大 HTML/CSS 体积，可能阻塞解析和渲染。
  • 可读性差，维护困难。
  • 旧 IE 对 Data URI 有 32KB 限制。
  • 大图内联会严重拖慢首屏。

使用建议

  • 只内联小于 5~10KB 的小图。
  • 大图使用独立文件 + CDN + 缓存。
  • HTTP/2 下请求开销降低，不必过度内联。
  • 构建工具可自动处理：
    • Webpack：asset modules
    • Vite：assetsInlineLimit
  • 注意 MIME 类型正确：
    • PNG：image/png
    • JPEG：image/jpeg
    • SVG：image/svg+xml
    • WebP：image/webp

六、图片优化清单

  1. 选对格式：
    • 照片：JPEG / WebP / AVIF
    • 透明图：PNG / WebP / SVG
    • 图标/Logo：SVG 优先
    • 动画：WebP / GIF / 视频
  2. 压缩图片：TinyPNG、Squoosh、ImageMagick。
  3. 按显示尺寸输出，避免大图缩小用。
  4. 响应式图片：srcset、sizes、picture。
  5. 懒加载：loading="lazy"。
  6. 异步解码：decoding="async"。
  7. 使用 CDN 和缓存策略。
  8. 小图才考虑 Base64，大图不要内联。
  9. 图标优先 SVG 或字体图标，减少图片请求。

七、快速选择

  • 要照片、体积小：JPEG / WebP / AVIF
  • 要透明、高质量：PNG / WebP
  • 要矢量、可缩放：SVG
  • 要简单动画：GIF / WebP
  • 要小图内联：Base64，但控制在 5～10KB 内
  • 要单色图标：字体图标或 SVG
  • 要多色图标：SVG 优先
