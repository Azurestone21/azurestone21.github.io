React 高阶组件（HOC）

一、概述

高阶组件（Higher-Order Component，HOC）是 React 中一种复用组件逻辑的模式。它本身不是 React API，而是一个函数：

签名：

  • WrappedComponent：被包装的组件。
  • EnhancedComponent：返回的新组件。
  • HOC 不修改原组件，而是通过组合的方式增强它。

它来自函数式编程中的“高阶函数”：接收函数，返回函数。HOC 就是接收组件，返回组件。

四、HOC 的约定

写 HOC 时，社区有一些约定，目的是让代码可预测、可调试。

1. 不要修改原组件

正确做法是返回一个新组件，通过组合增强：

2. 透传不相关的 props

HOC 应该把不关心的 props 原样传给被包装组件：

3. 最大化组合性

HOC 不应该假设被包装组件如何使用 props。它应该只关注自己的逻辑，其他 props 透传。

4. 包装显示名便于调试

这样在 React DevTools 中能看到 WithSubscription(MyComponent)，而不是一堆 Anonymous。

五、注意事项与常见坑

1. 不要在 render 中创建 HOC

每次渲染都会创建新的组件类型，React 会认为这是一个全新组件，导致：

  • 旧组件卸载
  • 旧组件状态丢失
  • 子树重新挂载

六、HOC 与 Hooks 的对比

Hooks 出现后，很多 HOC 场景可以用自定义 Hook 替代。

维度 HOC Hooks
复用方式 包装组件 函数内部逻辑
组件层级 增加层级 不增加层级
适用组件 类组件 + 函数组件 只能函数组件
代码可读性 嵌套多时较差 更直观
状态逻辑 通过 props 注入 直接返回状态
命名冲突 容易冲突 局部变量，不易冲突
调试 DevTools 层级深 更扁平
典型场景 权限、错误边界、第三方库 大多数逻辑复用

七、HOC 仍然有用的场景

虽然 Hooks 是主流，但 HOC 并没有完全消失：

  1. 错误边界：目前只能用类组件实现，HOC 可以包装成 withErrorBoundary。
  2. 包装类组件：类组件不能用 Hooks，HOC 仍可复用逻辑。
  3. 第三方库 API：如 Redux 的 connect、旧版 Material-UI 的 withStyles。
  4. 权限控制：withAuth 这种包装式权限控制仍然直观。
  5. React.memo：它本身就是一个 HOC。
  6. 需要改变组件类型或层级：有些场景 Hooks 做不到，HOC 可以。
  7. 跨组件树注入 props：某些库仍用 HOC 注入 context 或配置。

九、总结

HOC 的核心：

要点：

  • 不修改原组件，通过组合增强。
  • 透传不相关的 props。
  • 注意静态方法、ref、displayName。
  • 不要在 render 中创建 HOC。
  • 避免 props 命名冲突。
  • 多个 HOC 嵌套可用 compose 改善，但仍有层级。
  • Hooks 出现后，大多数逻辑复用优先用自定义 Hook。
  • HOC 仍适用于错误边界、类组件、第三方库、权限包装等场景。

一句话：HOC 是“组件工厂”，用包装的方式复用逻辑；现代 React 优先 Hooks，但 HOC 在特定场景仍然不可替代。
