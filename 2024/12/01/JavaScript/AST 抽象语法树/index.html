1. AST 是什么

AST（Abstract Syntax Tree，抽象语法树） 是源代码语法结构的一种树状表示。

编译器、解释器、Lint 工具、格式化工具、IDE 等，通常都会先把代码解析成 AST，再进行分析、转换或生成代码。

核心流程：

特点：

  • 树形结构：每个节点代表程序里的一个结构。
  • 抽象：忽略空格、换行、注释、分号、括号等不影响语义的细节。
  • 保留语义：保留运算符优先级、嵌套关系、声明与表达式关系等。
  • 可遍历、可修改、可生成代码。
  • 由解析器生成：如 Acorn、Babel、TypeScript Compiler。

2. AST vs CST

对比项 AST 抽象语法树 CST 具体语法树
保留内容 只保留语义相关结构 保留所有 token
是否包含空格/注释 通常不包含 包含
用途 分析、转换、代码生成 格式化、语法高亮、精确还原
简洁度 更简洁 更冗长

3. JavaScript 中的 AST

JavaScript 生态最常用的 AST 规范是 ESTree。

常见变体：

  • ESTree：Acorn、Espree 等使用。
  • Babel AST：Babel 使用，和 ESTree 相似但不完全一样。
  • TypeScript AST：TypeScript Compiler API 使用。

JavaScript AST 通常由普通对象组成，可以序列化成 JSON。每个节点都有一个 type 字段表示节点类型。

常见字段：

  • type：节点类型。
  • start / end：在源码中的位置。
  • loc：行列位置信息。
  • 其他字段：子节点、名称、值、操作符等。

9. AST 常见用途

  • Babel：ES6+ 转 ES5。
  • ESLint：静态检查代码规则。
  • Prettier：格式化代码。
  • jscodeshift / recast：批量重构代码。
  • IDE：补全、跳转、重构、高亮。
  • 打包工具：分析模块依赖。
  • 代码压缩 / 混淆。
  • TypeScript：类型检查、编译。

10. 注意事项

Babel AST 和 ESTree 不完全一样

内容 ESTree / Acorn / Espree Babel
根节点 Program File → Program
数字字面量 Literal NumericLiteral
字符串字面量 Literal StringLiteral
布尔字面量 Literal BooleanLiteral

写工具前，要先确认用的是哪套 AST。

其他注意点

  • AST 节点通常包含位置信息，但不同解析器字段可能不同。
  • 注释通常不在主 AST 中，需要额外配置或单独收集。
  • sourceType 区分 script 和 module。
  • 解析器需要设置 ecmaVersion，否则可能不支持新语法。
  • 直接字符串替换不安全，AST 转换更可靠。
  • 修改 AST 后，需要重新生成代码。
