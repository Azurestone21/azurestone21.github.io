Babel

Babel 可以理解成一个 JavaScript 编译器/转译器：把较新的 JS 语法、JSX、TypeScript/Flow 等代码，转换成目标环境能运行的、通常更旧的 JavaScript 代码。它本身不负责打包，也不做类型检查。

核心作用

  • 语法降级：箭头函数、可选链、类字段、async/await 等转成旧浏览器能跑的代码。
  • 扩展语法转换：React JSX、TypeScript 类型剥离、Flow。
  • 代码转换/插件开发：通过插件改 AST，做按需引入、宏、国际化提取等。

工作流程

Babel 的核心是 AST：

  1. Parse：@babel/parser 把源码解析成 AST。
  2. Transform：@babel/traverse 遍历 AST，插件修改节点。
  3. Generate：@babel/generator 把 AST 生成代码，可带 source map。

常见包和概念

  • @babel/core：核心。
  • @babel/cli：命令行工具。
  • @babel/preset-env：最常用预设，根据 targets / browserslist 自动决定要转哪些语法。
  • @babel/preset-react：处理 JSX。
  • @babel/preset-typescript：剥离 TS 类型。
  • 插件 plugins：真正做转换，preset 本质是插件集合。
  • @babel/plugin-transform-runtime：复用 helper，减少重复代码，避免污染全局。
  • core-js：提供 API polyfill，比如 Promise、Array.from、Symbol。

重要区别：语法转换 vs Polyfill

Babel 默认只转语法，不自动补内置 API。

  • 箭头函数、可选链、类字段：Babel 转。
  • Promise、Array.from、Object.assign、Symbol：需要 core-js 这类 polyfill。
  • 旧的 @babel/polyfill 已不推荐，现在通常用 core-js + regenerator-runtime，或 @babel/plugin-transform-runtime。

使用场景

  • Webpack 里配合 babel-loader。
  • React / Vue / TypeScript 项目转译。
  • Jest 测试环境转译。
  • React Native、旧浏览器兼容。
  • 写 Babel 插件做自定义代码转换。

优缺点

优点：生态最成熟、插件极多、兼容性和可定制性强。
缺点：纯 JS 实现，速度通常不如 SWC、esbuild；配置有时复杂。现代项目若目标环境较新，可能用 esbuild/SWC 替代部分 Babel 工作；但复杂插件转换仍常靠 Babel。

Babel 是 JS 生态里的“语法降级 + 代码转换”基础设施，核心是 AST 和插件系统。
