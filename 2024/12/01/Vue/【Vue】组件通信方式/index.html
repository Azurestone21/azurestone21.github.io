Vue 组件通信方式

组件通信的核心是：数据往下传，事件往上传，跨层级用依赖注入或状态管理。
Vue 3 和 Vue 2 思路一致，但 API 和推荐做法有变化。

一、父子组件通信

1. 父传子：props

父组件通过 props 把数据传给子组件。props 是只读的，子组件不能直接修改。

二、兄弟组件通信

兄弟组件之间没有直接通信方式，常用三种方案：

1. 状态提升到父组件

把共享状态放在父组件，通过 props 和 emit 分别传给两个子组件。

2. 事件总线：EventBus / mitt

Vue 2：new Vue() 作为事件总线

Vue 3：移除了 $on，推荐 mitt

事件总线适合简单、临时的通信，复杂场景建议用状态管理。

3. 状态管理：Pinia / Vuex

把共享状态放到 store，任何组件都可以读写。

三、跨层级通信

1. provide / inject

祖先组件提供数据，后代组件注入，不管层级多深。

provide / inject 本身不是响应式的，但传入 ref 或 reactive 对象可以保持响应。

2. attrs：透传属性和事件

父组件给子组件传了未声明的 props 或事件，可以通过 $attrs 继续往下传。

Vue 2

Vue 3 中 $listeners 已合并到 $attrs，统一用 v-bind="$attrs"。

3. 状态管理：Pinia / Vuex

跨层级、全局共享状态，首选 Pinia（Vue 3）或 Vuex（Vue 2）。

四、全局通信

  • Pinia / Vuex：全局状态管理，适合复杂应用。
  • EventBus / mitt：简单全局事件，适合临时通知。
  • app.config.globalProperties：挂载全局属性，但不利于类型推导，不推荐滥用。

五、Vue 2 与 Vue 3 通信差异

通信方式 Vue 2 Vue 3
父传子 props props / defineProps
子传父 $emit $emit / defineEmits
双向绑定 v-model + .sync v-model / v-model:prop
父访问子 $refs ref + defineExpose
子访问父 $parent getCurrentInstance()，不推荐
跨层级 provide/inject provide/inject
透传 $attrs + $listeners $attrs / useAttrs
事件总线 new Vue() + $on/$emit mitt
状态管理 Vuex Pinia（推荐）

六、如何选择

场景 推荐方式
父传子 props
子传父 emit
父子双向 v-model
父调用子方法 ref + defineExpose
兄弟简单通信 状态提升到父组件
兄弟临时通信 mitt / EventBus
跨层级传递 provide / inject
透传属性和事件 $attrs
全局共享状态 Pinia / Vuex
内容分发 插槽 slot

七、总结

父子通信：props 向下，emit 向上，v-model 是语法糖。
兄弟通信：状态提升、mitt、Pinia。
跨层级通信：provide/inject、$attrs、Pinia。
全局通信：Pinia / Vuex 最稳，EventBus 适合简单场景。
Vue 3 变化：defineProps / defineEmits / defineExpose，v-model:prop 替代 .sync，mitt 替代 $on，Pinia 替代 Vuex。
