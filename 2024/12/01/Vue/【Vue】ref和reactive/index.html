【Vue】ref和reactive

ref 适合基本类型，通过 .value 访问。
reactive 适合对象/数组，直接访问属性。
两者底层都基于 Proxy，但 ref 对基本类型做了包装。

一、ref

1. 基本用法

2. 特点

  • 可以包装任意类型：基本类型、对象、数组。
  • 在 JS 中必须通过 .value 读写。
  • 在模板中自动解包，直接写 count 即可。
  • 如果传入对象，ref 内部会调用 reactive 将其转为响应式代理。
  • 返回的是一个 RefImpl 对象，有 .value 属性。
  • 支持替换整个值：count.value = 10、user.value = { age: 20 }。

1. 基本用法

2. 特点

  • 只能用于对象类型：对象、数组、Map、Set 等。不能用于基本类型。
  • 返回一个 Proxy 代理对象，直接访问和修改属性。

三、核心区别对比

对比项 ref reactive
适用类型 任意类型，尤其基本类型 对象、数组、Map、Set 等
访问方式 JS 中.value，模板自动解包 直接访问属性
返回值 RefImpl 对象 Proxy 代理对象
替换整个值 支持，ref.value = newVal 不支持，会丢失响应性
解构 解构包含 ref 的对象，属性仍是 ref，保留响应性 直接解构会丢失响应性，需toRefs
深层响应式 传入对象时内部用reactive 包装 默认深层响应式
模板解包 顶层 ref 自动解包 不需要解包
类型推导 对基本类型友好 对对象类型友好

四、如何选择？

推荐用法

  • 基本类型（string、number、boolean）→ 用 ref。
  • 对象或数组 → reactive 或 ref 都可以。
  • 需要整体替换 → 用 ref。
  • 组合式函数返回值 → 推荐用 ref，方便解构和传递。
  • 复杂表单、状态对象 → reactive 写起来更简洁。

实际项目中常见的两种风格

风格一：统一用 ref

优点：一致性好，解构不丢响应性，方便传递。
缺点：到处写 .value。

风格二：基本类型用 ref，对象用 reactive

优点：对象访问简洁。
缺点：解构需注意 toRefs。

六、总结

  • ref：包装任意值，.value 访问，模板自动解包，适合基本类型和需要替换整体的场景。
  • reactive：代理对象，直接访问属性，适合复杂对象，但解构和替换要注意。
  • 两者可以配合使用：reactive 中嵌套 ref，Vue 会自动解包（在 reactive 对象中，ref 作为属性时会被自动解包）。
  • 选择哪种取决于团队规范和具体场景，没有绝对优劣，但理解它们的差异能避免响应性丢失的坑。

快速记忆：
基本类型用 ref，对象数组用 reactive；要替换整体用 ref，要解构用 toRefs。
const { age } = user.value 会丢失响应性，要用 toRefs、toRef 或 computed。
