Vue 单向绑定和双向绑定

在 Vue 中，单向绑定和双向绑定描述的是“数据”与“视图”之间的同步方向。理解它们的关键是：Vue 的核心原则是单向数据流，而 v-model 只是基于单向数据流和事件机制封装出来的语法糖。

一、单向绑定

数据 → 视图，视图不能直接反向修改数据。

1. 实现方式

  • 插值：{{ msg }}
  • 指令：v-bind（缩写 :）

2. 特点

  • 数据变化时，视图自动更新。
  • 视图（如输入框）变化时，数据不会自动改变。
  • 如果要让视图变化影响数据，需要手动监听事件：

3. 典型用途

  • 展示数据
  • 绑定 HTML 属性、class、style
  • 父组件向子组件传递 props

三、单向数据流 vs 双向绑定

这是最容易混淆的地方。

1. 单向数据流

Vue 组件间通信遵循单向数据流：

  • 父组件通过 props 向子组件传数据。
  • 子组件不能直接修改 props。
  • 子组件想修改，必须通过 emit 事件通知父组件，由父组件自己修改。

父组件：

这其实就是 v-model 的底层机制。

2. 双向绑定是语法糖

v-model 看起来是双向绑定，但本质仍然是：

  • 数据向下传（单向）
  • 事件向上通知（单向）

合起来形成闭环，所以叫“双向绑定”，但并没有打破单向数据流。

五、使用场景

单向绑定适合

  • 展示数据
  • 父传子 props
  • 只读属性绑定
  • 需要明确数据流向、便于调试的场景

双向绑定适合

  • 表单输入：input、textarea、select、checkbox、radio
  • 自定义表单组件
  • 需要父子组件同步状态的场景

六、总结

对比项 单向绑定 双向绑定
方向 数据 → 视图 数据 ↔ 视图
指令 v-bind / : / {{ }} v-model
视图改数据 不会自动改 自动改
本质 数据驱动视图 v-bind + v-on 的语法糖
数据流 单向数据流 底层仍是单向数据流 + 事件
典型场景 展示、传参 表单、自定义组件同步

单向绑定是“数据变，视图变”；双向绑定是“数据变，视图变；视图变，数据也变”。
v-model 不是真正的双向数据流，而是 :value + @input 的语法糖，底层依然遵循单向数据流。
