JS 垃圾回收机制和内存泄漏

1. 垃圾回收（GC）核心机制

GC 的核心逻辑是 可达性（Reachability）。GC 会从“根对象”（如 window、global）出发，遍历所有引用。能遍历到的保留，遍历不到的回收。

1.1 主要算法

  • 标记-清除（Mark-and-Sweep）：现代浏览器主流算法。先标记所有可达对象，再清除未标记的。优势：能处理循环引用。
  • 引用计数（Reference Counting）：记录对象的引用次数，归零则回收。缺陷：无法处理循环引用（已淘汰，但需了解）。

1.2 V8 引擎优化：分代回收

V8 将内存分为“新生代”和“老生代”：

  • 新生代：存活时间短的对象（如函数局部变量），采用副垃圾回收器，回收频繁且快。
  • 老生代：存活时间长的对象（如全局变量、闭包），采用主垃圾回收器，回收较慢且间隔长。

1.3 原始值（Primitive）的特殊性

let count = 0; 这类原始值（数字、字符串、布尔）：

  • 直接存储在栈（Stack） 内存中，不进入堆（Heap）。
  • V8 对小整数（SMI）有特殊优化，直接编码在指针中，根本不占堆内存。
  • 如果代码中未使用该变量，引擎的 死代码消除（DCE） 会直接在编译阶段将其移除。

2. 变量的生命周期与回收时机

定义位置 何时符合回收条件 物理内存释放时机
全局作用域 (let/var 在最外层) 永不（除非刷新页面） 页面关闭前永不释放
函数作用域 (function fn() { let a; }) 函数执行完毕后，作用域弹出执行栈 下一次 GC 周期（或引擎优化直接忽略）
块级作用域 (if(true){ let a; }) 跳出大括号后立即符合条件 下一次 GC 周期

结论：全局变量是内存泄漏的第一大根源。使用严格模式 'use strict' 可以有效避免意外创建全局变量。

4. 闭包与内存泄漏（必须纠正的误区）

结论：闭包本身不是内存泄漏，它只是内存泄漏的“载体”。

  • 安全场景：闭包随父函数执行完毕而被释放。
  • 泄漏场景：闭包被长期存活的对象（如 setInterval、全局数组）持有。
  • 现代引擎优化：V8 会进行作用域分析。如果闭包内定义了多个外部变量，但只使用了其中一部分，未使用的变量会被引擎主动丢弃，不会被闭包拽住。

5. 生产级优化：当“定时器永久运行”且“每次必须使用大对象”

当业务强制要求定时器永久运行且必须持有全量数据时，这属于合法驻留内存，而非泄漏。我们通过改变数据结构来解决内存占用问题。

5.1 策略一：结构体数组（平行数组 / AoSoA）

原理：将“行存储”（数组存对象）改为“列存储”（多个字段数组）。
效果：去掉 500 万个对象头，内存直降 70%，GC 扫描压力骤减。

5.2 策略二：LRU 分页缓存（外部存储）

原理：全量数据存 IndexedDB，内存只保留最近使用的几页（Page）。
效果：无论数据总量多大（1亿条），JS 堆内存始终稳定在几十 MB。

5.3 策略三：二进制序列化（ArrayBuffer / FlatBuffers）

原理：将对象拍平为连续的内存字节流，不在堆中创建任何 JS 对象。
效果：GC 完全无视这块内存（不扫描），内存占用仅为原始数据大小，无对象头开销。

6. 数据结构演变对比表

维度 原始对象数组 平行数组（策略一） 分页缓存（策略二） 二进制缓冲区（策略三）
内存布局 5万个独立对象 3块连续的大数组 仅几千个对象 + 磁盘数据 1块巨大的连续字节流
JS 对象数量 极多 几乎没有 极少（可控制） 零
GC 扫描压力 极高 极低 低 零
适用场景 小型项目 高频全量计算 超大规模随机访问 极致性能/嵌入式

7. 调试与排查工具（Chrome DevTools）

  1. 任务管理器：Shift + Esc 查看“JavaScript 内存”实时变化。
  2. Performance 面板：录制时勾选 “Memory”，观察 Heap 曲线是否有阶梯式上涨且不回落。
  3. Memory 面板：
    • 堆快照（Heap Snapshot）：对比两处快照，重点搜索 Detached（分离 DOM）。
    • 分配时间轴（Allocation Timeline）：逐帧定位是哪个函数分配了大量内存。

8. 最佳实践总结

  1. 使用严格模式：'use strict' 防止变量泄漏到全局。
  2. 及时清理：组件卸载时必须 clearInterval、removeEventListener。
  3. 弱引用：使用 WeakMap 和 WeakSet 存储对象引用，不阻止 GC。
  4. 主动置空：对于不再使用的大型对象或 DOM 引用，主动 obj = null。
  5. 慎用闭包：确保闭包只引用必要的最小数据，避免长期持有大对象。
  6. 大数据优化三字经：拆（拆对象为数组）、换（换内存为磁盘）、压（压对象为二进制）。
