Vue 3 与 Vue 2 的区别

Vue 3 与 Vue 2 的区别

Vue 3 与 Vue 2 的核心区别在于响应式原理、API 设计哲学和性能表现。Vue 3 是一次彻底的重构，旨在解决 Vue 2 在大型应用中的局限性。

一、响应式系统：从 Object.defineProperty 到 Proxy

这是两者最根本的区别。

  • Vue 2：使用 Object.defineProperty 来劫持对象属性的读写。这种方式存在局限：无法监听对象属性的新增和删除（需要 Vue.set/Vue.delete），对数组索引和长度的直接修改也无效（通过重写数组方法实现响应式）。
  • Vue 3：改用 ES6 的 Proxy 代理整个对象。它可以监听属性的新增、删除，以及数组索引和 Map、Set 等数据结构的变化，不再需要 Vue.set，代码更简洁，性能也更好。

二、组件逻辑组织：Options API vs Composition API

  • Vue 2 的 Options API：逻辑按选项（data、methods、computed 等）分散组织。当组件复杂时，同一功能的代码可能被拆散，难以阅读和复用。
  • Vue 3 的 Composition API：引入 setup 函数，允许按功能逻辑而非选项类型来组织代码。你可以将相关状态、方法和生命周期钩子写在一起，逻辑复用和类型推导都更友好，尤其适合大型组件。

三、性能优化：更快、更轻

Vue 3 在性能上有显著提升，渲染性能比 Vue 2 提高了近 40%。

  • 编译优化：Vue 3 引入了静态提升、补丁标记和事件监听器缓存等技术，在编译时标记静态内容，大幅减少了运行时 diff 比较的工作量。
  • 更小的打包体积：Vue 3 的代码库是模块化的，支持 Tree-shaking。未使用到的功能（如 v-model 的某些修饰符）可以在打包时被剔除，使最终体积比 Vue 2 减小约 10%。

四、生命周期钩子：名称与用法的变化

Vue 3 保留了生命周期概念，但为了配合 Composition API，钩子名称前都加了 on，并作为函数在 setup 中调用。同时，beforeCreate 和 created 被 setup 本身替代。

Vue 2 钩子 Vue 3 钩子 (Composition API)
beforeCreate / created setup()
beforeMount / mounted onBeforeMount / onMounted
beforeUpdate / updated onBeforeUpdate / onUpdated
beforeDestroy / destroyed onBeforeUnmount / onUnmounted

Vue 3 还新增了 onRenderTracked 和 onRenderTriggered 等调试钩子。

五、新特性与功能增强

  • 多根节点 (Fragment)：Vue 2 强制组件只能有一个根元素，Vue 3 允许组件有多个根节点，减少了无意义的包裹 div。
  • Teleport：可将组件的一部分模板渲染到 DOM 树的其他位置，非常适合实现模态框、通知等。
  • Suspense：用于处理异步组件的加载状态，提供更好的用户体验。
  • 自定义渲染器：Vue 3 的核心逻辑与 DOM 解耦，使其可以渲染到 Canvas、原生应用等非 DOM 环境。

六、其他重要变化

  • TypeScript 支持：Vue 3 的源码完全使用 TypeScript 重写，提供了一流的类型支持，这是 Vue 2 无法比拟的。
  • 全局 API 重构：Vue 2 通过 new Vue() 创建根实例，全局配置会影响所有实例。Vue 3 改用 createApp() 创建独立的应用实例，避免了全局污染，使代码更模块化。
  • v-if 与 v-for 优先级：在 Vue 2 中 v-for 优先，而在 Vue 3 中 v-if 优先，这可以减少不必要的循环计算，提升性能。

七、总结

总的来说，Vue 3 在性能、TypeScript 支持和代码组织能力上全面优于 Vue 2，是当前新项目的首选。
