JS 事件循环

JavaScript 事件循环

一、为什么需要事件循环

JavaScript 是单线程语言，同一时刻只能执行一个任务。但网络请求、定时器、文件读写等操作耗时很长，同步等待会阻塞主线程。

事件循环解决的矛盾：

单线程执行 + 大量异步耗时操作，如何做到不阻塞、又能有序处理回调。

基本思路：把耗时操作交给宿主环境（浏览器/Node.js）处理，主线程继续执行后面的代码；操作完成后，回调进入队列，由事件循环在适当时机取出执行。

二、核心概念

1. 调用栈（Call Stack）

  • 存放当前正在执行的函数帧。
  • 函数调用时入栈，返回时出栈。
  • 栈空时，主线程才有机会处理队列里的任务。
  • 结构：栈（LIFO，后进先出）。

2. 任务队列（Task Queue）

存放异步操作完成后的回调，分为两类：

类型 别名 典型来源
宏任务（MacroTask） Task setTimeout、setInterval、I/O、UI 渲染、MessageChannel、setImmediate（Node）
微任务（MicroTask） Job Promise.then/catch/finally、queueMicrotask、MutationObserver、process.nextTick（Node）

结构：队列（FIFO，先进先出）。

3. 调用栈 vs 任务队列

维度 调用栈 任务队列
数据结构 栈（LIFO） 队列（FIFO）
存什么 正在执行的函数帧 待执行的回调
解决什么 函数嵌套调用与返回 异步任务的排队与调度
谁维护 JS 引擎 宿主环境（浏览器/Node）
元素关系 嵌套（A 调用 B） 并列（任务之间无依赖）

调用栈用栈，因为函数调用是嵌套的，必须“后调用的先返回”；
任务队列用队列，因为异步回调是并列的，应该“先注册的先执行”。

4. 没有嵌套时调用栈怎么工作

即使没有函数嵌套，调用栈依然存在，只是任意时刻最多只有一帧：

  • 每次调用压一帧，执行完立刻弹栈。
  • 栈深度最多为 1（不算全局帧），LIFO 特性体现不明显。
  • 全局执行上下文始终在栈底。

栈的存在不依赖嵌套，嵌套只是让栈变深、让后进先出变得可见。

关键规则：

  • 每执行完一个宏任务，就清空一次微任务队列。
  • 微任务优先级高于宏任务：微任务队列不为空，就不执行下一个宏任务。
  • setTimeout(fn, 0) 不是立即执行，要等当前宏任务和所有微任务结束，且延迟时间到达。

四、浏览器中的事件循环

执行顺序

  1. 从宏任务队列取出一个宏任务执行。
  2. 该宏任务执行完后，清空所有微任务（执行中产生的新微任务也在本轮全部执行完）。
  3. 检查是否需要 UI 渲染，需要则渲染。
  4. 回到第 1 步，进入下一轮循环。

五、Node.js 中的事件循环

Node.js 的事件循环由 libuv 实现，分为六个阶段：

各阶段说明

  • timers：执行到期的 setTimeout、setInterval 回调。
  • pending callbacks：处理上一轮未完成的系统回调。
  • poll：核心阶段。获取新的 I/O 事件，执行 I/O 回调。队列空时会在这里等待。
  • check：执行 setImmediate 回调。
  • close callbacks：执行 socket.on('close') 等回调。

微任务在 Node 中的位置

Node 中微任务有两个队列：

  • process.nextTick 队列：优先级最高。
  • Promise 微任务队列：次之。

每个阶段结束后（不是每个宏任务后），都会先清空 nextTick 队列，再清空 Promise 微任务队列。

setTimeout 与 setImmediate 的顺序

  • 主模块中：顺序不确定，取决于进程启动耗时是否超过 1ms。
  • I/O 回调内部：setImmediate 总是先于 setTimeout。

原因：I/O 回调在 poll 阶段执行，接下来进入 check 阶段执行 setImmediate，而 setTimeout 要等到下一轮的 timers 阶段。

六、浏览器 vs Node.js 对比

维度 浏览器 Node.js
实现者 浏览器引擎 libuv
宏任务粒度 一个宏任务后清空微任务 一个阶段后清空微任务
微任务类型 Promise、MutationObserver Promise、process.nextTick
特有 API requestAnimationFrame、UI 渲染 setImmediate、process.nextTick
阶段划分 无明确阶段 六阶段循环

七、宏任务和微任务的产生、排队、执行

1. 产生任务

  • 宏任务：几乎都由宿主环境产生，本质是“宿主环境通知 JS 引擎去执行某段代码”。
  • 微任务：Promise 相关由 JS 引擎产生，MutationObserver、process.nextTick 由宿主环境产生。

注意：setTimeout 注册时并不立刻把回调放进队列，而是计时到期后才放入。所以 setTimeout(fn, 0) 的 0 不是“立即”，而是“尽快到期”。
微任务执行过程中产生的新微任务，会追加到当前微任务队列末尾，并在本轮全部执行完，不会拖到下一轮。这也是“微任务可能饿死宏任务”的原因。

产生后的任务进入对应队列，等待事件循环调度。

2. 排队规则

规则 说明
先进先出（FIFO） 同一队列内，先入队的先执行
微任务优先于宏任务 微任务队列不清空，不执行下一个宏任务
nextTick 优先于 Promise Node 中每阶段结束先清空nextTick，再清空 Promise
执行中产生的新任务 宏任务放入宏任务队列（等下一轮）；微任务放入微任务队列（本轮继续执行）

3. 执行

  • 宿主环境（事件循环）：决定“下一个执行哪个任务”
  • JS 引擎：把任务压入调用栈，真正执行回调代码

八、宿主环境、主线程与 JS 引擎

三者关系

  • 宿主环境：提供 JS 运行所需一切的整套系统，包含主线程，但远不止主线程。
  • 主线程：宿主环境中执行 JS 代码、维护调用栈的那条线程。
  • JS 引擎：真正执行代码、管理内存、编译优化的虚拟机。

谁决定下一个任务

场景 决定者
调用栈内部（函数 A 调用 B） JS 引擎按代码逻辑执行
调用栈清空后（下一个任务是谁） 宿主环境的事件循环按规则决定
真正压栈执行 JS 引擎

事件循环是决策者，JS 引擎是执行者。

宏任务和微任务都是 JS 引擎执行的吗

不完全是。

  • 宏任务和微任务的回调代码由 JS 引擎执行。
  • 任务的产生、排队、调度、触发时机由宿主环境负责。
  • 微任务队列由 JS 引擎维护（Promise 等），但清空时机由宿主环境的事件循环决定。
  • 宏任务完全是宿主环境的概念，不在 ECMAScript 规范中；事件循环也不在 ECMAScript 规范中（在 HTML 规范和 Node 文档中定义）。

九、JS 引擎详解

定位

JS 引擎是一个虚拟机（Virtual Machine），模拟计算机的 CPU、堆栈、寄存器，屏蔽平台差异。它不负责调度（那是宿主环境的事），只负责执行。

核心组件

组件 职责
解析器（Parser） 将源代码转成抽象语法树（AST）
解释器（Interpreter） 直接执行字节码，启动快
JIT 编译器 将“热代码”编译成机器码，执行快
垃圾回收器（GC） 自动回收不再使用的对象内存
内联缓存（IC） 缓存属性访问路径，加速动态查找

V8 的完整流水线

  1. 解析（Parsing）：源码 → AST，含惰性解析（函数声明时不立刻解析函数体，调用时才解析）。
  2. 生成字节码（Bytecode）：AST → 字节码，比机器码抽象，可缓存。
  3. 解释执行：基线解释器逐条执行字节码，同时收集类型信息。
  4. JIT 优化：热代码被 JIT 编译成机器码（V8 用 TurboFan，SpiderMonkey 用 WarpMonkey）。
  5. 反优化（Deoptimization）：类型假设被打破时，丢弃优化代码，回退到解释器。

两个关键加速机制

  • 内联缓存（IC）：在代码里缓存上次查到的属性访问结果（形状 + 偏移量），加速动态查找。
  • 垃圾回收（GC）：标记-清除 + 分代回收（年轻代频繁回收，老年代低频回收）。

十、常见易错点

  1. Promise 构造函数内的代码是同步的，只有 .then、.catch、.finally 回调才是微任务。
  2. await 后面的代码相当于 .then 回调，是微任务。
  3. 微任务可以无限嵌套，一直产生新微任务会饿死宏任务和 UI 渲染。
  4. setTimeout 最小延迟：浏览器嵌套超过 5 层后最小为 4ms；Node 中为 1ms。
  5. process.nextTick 优先级高于 Promise，滥用会导致 I/O 饥饿。
  6. setTimeout 与 setImmediate 顺序：主模块中不确定，I/O 回调中 setImmediate 先。
  7. 宿主环境 ≠ 主线程：宿主环境是整套运行系统，主线程只是其中执行 JS 的那条线程。

十一、总结

事件循环是单线程 JavaScript 处理异步的调度器：同步代码在调用栈执行，异步回调按宏任务/微任务分类排队，每轮先执行一个宏任务、再清空所有微任务，如此循环往复。宿主环境负责调度，JS 引擎负责执行；调用栈用栈解决嵌套调用，任务队列用队列解决并列排队。浏览器和 Node.js 实现细节不同，但核心思想一致。
