Webpack 的 loader 具体做了什么

loader 是 Webpack 的“翻译官”，负责把各种非 JS 资源翻译成 Webpack 能识别和打包的 JS 模块。

Webpack 本身只认识 JavaScript 和 JSON。CSS、图片、字体、TypeScript、Vue SFC、SCSS 这些它都不认识。loader 的作用，就是在 Webpack 构建依赖图时，把这些文件“转换”成 JS 模块，让 Webpack 能继续处理。

一、转换发生在什么时候

Webpack 从 entry 开始构建依赖图，每遇到一个模块，就会：

  1. 根据 module.rules 匹配文件；
  2. 找到对应的 loader 链；
  3. 把文件内容交给 loader 处理；
  4. loader 返回转换后的 JS 代码；
  5. Webpack 把这段 JS 代码作为模块内容，继续解析它的依赖。

所以 loader 转换是 模块构建阶段 的核心环节。

执行顺序是 从右到左，从下到上：

  1. sass-loader：把 SCSS 编译成 CSS；

  3. style-loader：把 CSS 字符串通过运行时插入 <style> 标签。

每个 loader 接收上一个 loader 的输出，最终输出一段 JS 代码。

三、常见 loader 具体转换了什么

loader 输入 输出 具体做了什么
babel-loader ES6+ / JSX ES5 JS 用 Babel 转译语法，兼容旧浏览器
ts-loader TypeScript JS 调用 TypeScript 编译器，做类型检查并转 JS
sass-loader SCSS CSS 把 SCSS 编译成 CSS
css-loader CSS JS 模块 把 CSS 变成 JS 字符串，@import 变成 require
style-loader CSS 的 JS 模块 JS 代码 运行时把 CSS 注入<style>
file-loader 图片/字体 文件路径 复制文件到输出目录，返回 URL
url-loader 小图片 base64 URL 小文件转成 data URL
vue-loader .vue 文件 JS 模块 拆解 template/script/style，分别交给对应 loader
html-loader HTML JS 模块 把src、href 转成 require
raw-loader 任意文件 字符串 把文件内容作为字符串导出

五、loader 的本质

loader 本质上是一个函数：

它可以：

  • 接收 source 和 sourceMap；
  • 通过 this.query 获取配置；
  • 通过 this.async() 变成异步；
  • 通过 this.callback(null, code, map) 返回多个值；
  • 通过 this.emitFile() 输出额外文件。

六、loader 和 plugin 的区别

  • loader：转换文件内容，关注“一个文件怎么变成另一个模块”。
  • plugin：扩展构建流程，监听 Webpack 生命周期钩子，关注“整个构建过程要做什么”。

比如：

  • babel-loader 把 ES6 转 ES5，是 loader；
  • HtmlWebpackPlugin 生成 HTML 文件，是 plugin。

七、总结

loader 转换具体做了这些事：

  1. 读取原始文件内容；
  2. 按规则链式调用多个 loader；
  3. 把非 JS 资源转成 JS 模块；
  4. 处理依赖，比如 CSS 里的 @import、图片 url()；
  5. 输出 Webpack 能继续解析和打包的代码。

所以，Webpack 开发时“先打包，再启动”，其中“打包”的关键一步，就是 loader 把各种资源统一转换成 JS 模块，最终合成 bundle。
