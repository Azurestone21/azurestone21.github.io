Vite 如何让启动更快

Vite 如何让启动更快

先说结论

很多人说“Vite 比 Webpack 快”，更准确的说法是：

Vite 的快，主要体现在开发阶段。
Webpack 是“先打包，再启动开发服务器”；Vite 是“先启动开发服务器，浏览器请求什么，再按需编译什么”。

生产环境下，Vite 仍然会打包，通常使用 Rollup，新版本逐步引入 Rolldown，并用 esbuild 做压缩。所以 Vite 并不是完全不打包，而是改变了开发模式下的构建思路。

一、开发模式：Webpack 先打包，Vite 先启动

Webpack 的开发流程大致是：

  1. 从 entry 入口开始；
  2. 递归分析所有依赖；
  3. 经过 loader 转换；
  4. 生成 bundle；
  5. 启动 dev server；
  6. 浏览器访问页面。

也就是说，项目越大，Webpack 启动前要做的打包工作越多，冷启动就越慢。

Vite 的开发流程则是：

  1. 先启动 dev server；
  2. 浏览器请求 index.html；
  3. 浏览器请求入口模块；
  4. Vite 按需编译这个模块；
  5. 浏览器遇到 import，再请求下一个模块；
  6. Vite 再编译下一个模块。

所以 Vite 不需要在启动时打包整个项目，只编译当前页面真正用到的模块。项目越大，这种优势越明显。

三、esbuild 预构建依赖，速度远超 JS 工具链

Vite 在开发阶段会用 esbuild 做依赖预构建。

esbuild 快的原因主要有：

  • 使用 Go 编写，编译成原生机器码；
  • 多核并行处理；
  • 没有 JavaScript 单线程和 GC 的性能瓶颈；
  • 转换、压缩、生成 sourcemap 都很快。

Vite 用 esbuild 做这些事：

  • 把 CommonJS / UMD 依赖转成 ESM；
  • 把多个小模块合并成少量文件，减少浏览器请求；
  • 转换 TypeScript、JSX 等；
  • 生产构建时做代码压缩。

Webpack 的 loader 大多由 JavaScript 实现，例如 Babel、ts-loader、css-loader 等。它们功能强大，但速度上通常不如 esbuild。

四、按需编译，不编译没访问到的代码

Webpack 开发时通常要构建完整的依赖图。即使你只打开首页，它也可能已经处理了大量路由、组件和工具模块。

Vite 则是按需编译：

  • 你访问首页，它只编译首页相关模块；
  • 你跳到某个路由，它才编译那个路由的组件；
  • 没被请求的代码，开发阶段根本不用编译。

这就像餐厅点菜：

  • Webpack：先把整本菜单所有菜都做好；
  • Vite：你点什么，厨房做什么。

项目越大，Vite 的按需模式越有优势。

五、HMR 更快，因为基于 ESM 精确更新

HMR 是热模块替换。修改代码后，页面不刷新也能更新。

Vite 的 HMR 基于原生 ESM，模块边界清晰。修改某个模块时，Vite 只需要：

  1. 让这个模块失效；
  2. 沿着 import 链找到接受更新的模块；
  3. 通过 WebSocket 通知浏览器；
  4. 浏览器动态 import 新模块。

Webpack 的 HMR 也很强，但它通常需要重新构建相关 chunk。项目越大，重新构建的成本越高。

所以 Vite 的快，不只是启动快，热更新也通常更快。

六、生产构建：Vite 用 Rollup / Rolldown

开发阶段 Vite 不打包业务源码，但生产环境仍然要打包，因为需要：

  • 减少 HTTP 请求；
  • tree-shaking；
  • 压缩代码；
  • 代码分割；
  • 兼容旧浏览器；
  • 优化加载性能。

Vite 生产构建默认使用 Rollup。Rollup 对 ESM 的静态分析很好，tree-shaking 效率高，输出也比较干净。Vite 还用 esbuild 做压缩，比传统的 Terser 快很多。

Webpack 5 也有持久化缓存、模块联邦等能力，在复杂项目中生产构建不一定慢。所以：

Vite 开发阶段通常明显快于 Webpack；生产构建则要看项目规模、插件和配置。

七、Vite 不是银弹

Vite 很快，但并不是所有场景都一定优于 Webpack。

这些情况 Webpack 可能更合适：

  • 项目依赖大量 Webpack 专属 loader / plugin；
  • 需要非常复杂的构建定制；
  • 老项目迁移成本高；
  • 需要 Module Federation 等高级能力；
  • 对旧浏览器兼容有特殊要求；
  • 生产构建流程已经高度优化。

Vite 生态增长很快，但 Webpack 的成熟度和插件丰富度仍然很强。

八、总结

Vite 比 Webpack 快，核心不是“打包算法优化了一点”，而是架构不同：

对比项 Webpack Vite
开发启动 先打包再启动 先启动再按需编译
模块加载 Webpack 构建依赖图 浏览器原生 ESM
依赖处理 JS loader 链 esbuild 预构建
HMR 重新构建相关 chunk 基于 ESM 精确更新
生产构建 Webpack 自身 Rollup / Rolldown
速度优势 成熟稳定 开发体验极快

一句话概括：

Webpack 是“先打包再服务”，Vite 是“先服务再按需编译”。

Vite 快在开发阶段，靠的是原生 ESM、按需编译、esbuild 预构建和精确 HMR。生产环境仍然要打包，只是换成了 Rollup / Rolldown 这套更轻量的方案。

所以，新项目优先考虑 Vite；老项目、复杂项目、深度定制项目，Webpack 仍然是可靠选择。
