前端工程化

前端工程化

实现前端工程化的基础：前后端分离。

为什么需要前端工程化

随着前端需求和代码量的增加，需要解决代码冗余、项目可维护性、版本迭代升级等问题。

前端工程化是什么

前端工程化是指使用软件工程的技术和方法，将前端的开发流程、技术、工具、经验等规范化和标准化。其主要目的是提高效率、降低维护成本，即提高开发过程中的开发效率，减少不必要的重复工作时间。

前端工程化具体包含：

  • 标准化：定义编码、目录结构、接口以及源码管理等规范；
  • 组件化：将 UI 拆分为可复用组件，一个组件通常包含 HTML 模板、CSS 样式和 JS 逻辑；
  • 模块化：功能封装；
  • 自动化：持续集成和持续部署。

如何实施前端工程化

项目构建

使用 Webpack 等构建工具将源代码转化为浏览器可以执行的代码（HTML、CSS、JS）。

  • 依赖打包：将同步依赖的文件打包在一起，减少 HTTP 请求数量。
  • 资源嵌入：例如将小于 10KB 的图片编译为 base64 格式嵌入文档，减少 HTTP 请求。
  • 文件压缩：减小文件体积，缩短请求时间。
  • 资源定位：将开发环境下的域名与静态资源文件路径修改为生产环境下的域名和路径。
  • JavaScript 编译：使用 Babel 将浏览器未实现的 ECMAScript 规范语法转化为可运行的低版本语法，例如将 ES6 的 class 转化为 ES5 的 prototype 实现。
  • CSS 预编译。
  • 文件 hash 指纹：为文件加入 hash 指纹，以应对浏览器缓存策略。

开发

  • 模块化
    • 使用模块化开发方式（如 ES Modules、CommonJS、AMD）将代码拆分为独立的模块。
    • 模块化开发可以解决：
      • 避免命名冲突
      • 便于依赖管理
      • 利于性能优化
      • 提高可维护性
      • 提高代码可复用性
  • 组件化
    • 一个组件包含 HTML 模板、CSS 样式和 JS 逻辑。

模块化是文件层面对代码和资源的拆分；组件化是设计层面对 UI 的拆分。

性能优化

  • 网络层：缓存策略、CDN 内容分发网络、请求合并；
  • 加载层：按需加载、预加载、首屏渲染；
  • 测试层：性能测试。

规范化

  • 代码规范：目录结构规范、编码规范、技术栈规范、图标规范；
  • 协作规范：Git 分支管理规范、Code Review 规范、文档规范、设计规范、版本控制；
  • 流程规范：开发流程规范、发布流程规范。

项目部署流程化

  • 持续部署：CI/CD（持续集成、持续交付/部署）工具，如 Jenkins（较老旧）、GitLab CI/CD、GitHub Actions、Docker（发布制品）和 K8s（容器编排）等。
  • 部署配置：Nginx 反向代理、跨域配置等。

前端工程化解决了什么问题

前端工程化的主要目标是解放生产力、提高生产效率。通过制定一系列规范，借助工具和框架，解决前端开发以及前后端协作过程中的痛点和难点问题，包括代码冗余、依赖混乱、协作规范不统一、构建部署重复、性能优化缺少手段等。
