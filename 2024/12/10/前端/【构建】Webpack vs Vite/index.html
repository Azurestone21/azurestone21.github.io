Webpack vs Vite

Webpack vs Vite

一、Webpack

1. 概述

Webpack 是一个老牌、成熟的 静态模块打包器。它会从入口文件开始，递归分析依赖，构建依赖图，然后通过 loader 和 plugin 把 JS、CSS、图片等资源打包成一个或多个 bundle。

核心概念：

  • entry：入口
  • output：输出
  • loader：处理非 JS 资源，如 CSS、图片、TS
  • plugin：扩展构建能力，如 HTML 生成、压缩、环境变量
  • devServer：开发服务器，支持 HMR
  • mode：development / production

2. 特点

  • 生态极其成熟，loader / plugin 非常丰富
  • 配置灵活，几乎什么都能定制
  • 适合复杂项目、老项目、微前端、特殊构建需求
  • 开发时通常先打包再启动，项目大时冷启动和 HMR 可能较慢
  • Webpack 5 支持持久化缓存、模块联邦等高级能力

二、Vite

1. 概述

Vite 是新一代前端构建工具，名字来自法语“快”。它的核心思路是：

  • 开发环境：基于浏览器原生 ES Module，不先打包，按需编译
  • 依赖预构建：用 esbuild 把 CommonJS / UMD 依赖转成 ESM，并合并请求
  • 生产环境：传统上基于 Rollup 打包，新版本逐步引入 Rolldown，具体看版本

Vite 不是 Webpack 的简单替代，而是改变了开发阶段的构建方式。

2. 特点

  • 冷启动非常快，项目越大优势越明显
  • HMR 很快，基于 ESM，通常只更新变更模块
  • 开箱即用支持 TS、JSX、CSS、静态资源等
  • 配置简单，约定优于配置
  • 插件生态兼容 Rollup 插件，Vue / React / Svelte 等框架支持好
  • 注意：Vite 的 TS 转译通常用 esbuild，不做类型检查，类型检查需 tsc 或 vue-tsc

三、核心区别

维度 Webpack Vite
定位 模块打包器 新一代构建工具
开发启动 先打包依赖图，再启动 先启动，按需编译
开发编译 loader 链处理 esbuild 预构建依赖，源码按需转换
HMR 重新打包变更模块后更新 基于 ESM，精确模块替换，通常更快
生产构建 Webpack 自身 Rollup / Rolldown
配置复杂度 高，灵活但繁琐 低，约定优于配置
生态 loader / plugin 极丰富 Rollup 插件兼容，生态增长快
浏览器兼容 更容易打包兼容旧浏览器 开发需现代浏览器，生产可配置 target
适用场景 老项目、复杂定制、特殊构建 新项目、快速开发、Vue/React 等

四、总结

  • Webpack：成熟、强大、灵活，生态最丰富。适合复杂项目、老项目、需要深度定制构建流程的场景。
  • Vite：开发体验极快，配置简单，适合新项目、现代框架项目、追求开发效率的团队。
  • 选型建议：
    • 新项目优先考虑 Vite。
    • 已有 Webpack 项目且运行稳定，不必强行迁移。
    • 如果项目依赖大量 Webpack 专属 loader / plugin，或需要非常复杂的构建定制，Webpack 仍然更合适。
    • 如果特别在意冷启动和 HMR 速度，Vite 优势明显。
