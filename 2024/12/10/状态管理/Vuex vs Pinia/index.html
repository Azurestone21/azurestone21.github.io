Vuex vs Pinia

Vuex vs Pinia

一、总览

状态管理用于解决组件间共享状态、跨组件通信、状态可预测变更等问题。

  • Vuex：Vue 早期官方状态管理库，Vuex 3 用于 Vue 2，Vuex 4 用于 Vue 3。现在处于维护模式，官方推荐新项目使用 Pinia。
  • Pinia：Vue 官方新一代状态管理库，Vue 3 默认推荐方案。更轻量、类型友好、组合式 API 风格明显，去掉了 Vuex 中繁琐的 mutations。

二、Vuex

1. 概述

Vuex 是集中式状态管理库，核心特点是：

  • 集中式存储
  • 状态变更流程严格：dispatch action -> commit mutation -> 修改 state
  • 支持模块化 modules
  • 适合中大型 Vue 2 / Vue 3 老项目

2. 核心概念

概念 说明
State 单一状态树，存放共享数据
Getters 类似计算属性，派生状态
Mutations 唯一同步修改 state 的方法，必须commit
Actions 可异步，最终通过commit 触发 mutation
Modules 将 store 拆分为模块，可namespaced

6. Vuex 可以不使用 Action，直接使用 Mutations 吗？

可以，但仅限于同步操作。

Vuex 允许组件直接 commit mutation：

或使用 mapMutations：

但有一条关键规则：

Mutation 必须是同步函数。

因为 Vuex Devtools 需要捕捉状态变更前后的快照。如果 mutation 中有异步操作，Devtools 无法准确追踪状态何时改变。

因此：

场景 推荐做法
简单同步状态变更 可直接commit mutation
任何异步操作 必须通过 action 处理
复杂业务逻辑（即使同步） 建议通过 action 处理，便于复用和测试

三、Pinia

1. 概述

Pinia 是 Vue 官方新一代状态管理库，特点：

  • 官方推荐
  • 无 mutations，同步异步都写在 actions
  • TypeScript 支持非常好
  • 支持 setup 风格定义 store
  • 扁平化 store，无需嵌套 modules
  • 支持 devtools、SSR、热更新、代码分割

2. 核心概念

概念 说明
Store 通过defineStore 定义，每个 store 独立
State 存放状态，可用ref/reactive 或 state()
Getters 派生状态，类似 computed
Actions 同步/异步方法，可直接修改 state

四、Vuex 与 Pinia 区别

维度 Vuex Pinia
官方推荐 旧一代，维护模式 Vue 3 官方推荐
核心概念 State / Getters / Mutations / Actions / Modules State / Getters / Actions
仓库模式 单一状态树，单仓库 多 Store，每个 store 独立
修改状态 必须commit mutation action 可直接修改，也可直接改 state
异步 Actions 中处理 Actions 中处理，同步异步都行
模块化 嵌套 modules + namespaced 扁平 store，可互相引用
TypeScript 支持一般，需额外类型 类型推导优秀
组合式 API useStore 后映射 defineStore + storeToRefs
状态解构 直接解构丢失响应性，需computed / mapState / toRefs 直接解构丢失响应性，需storeToRefs
样板代码 多 少
代码分割 较弱 天然支持动态导入
体积 较大 更轻
持久化 vuex-persistedstate / 手动 pinia-plugin-persistedstate / 手动
适用场景 Vue 2 / 老项目 Vue 3 / 新项目

简单理解：

  • Vuex 更“重”，流程严格，概念多。
  • Pinia 更“轻”，API 简洁，类型友好，开发体验更好。
  • Pinia 不是 Vuex 的简单升级版，而是新一代状态管理方案。

五、选型建议与总结

  • Vuex：核心是 State、Getters、Mutations、Actions、Modules。状态变更流程严格，适合 Vue 2 或已有 Vuex 的老项目。
  • Pinia：官方推荐的新一代状态管理库，去掉了 mutations，只有 state、getters、actions。更轻量、更简洁、TypeScript 支持更好，适合 Vue 3 新项目。
  • Vuex 是单仓库：设计上使用单一状态树，通常只有一个 Store 实例，modules 只是逻辑拆分。
  • Vuex 可以跳过 Action 直接 Mutation：仅限同步操作。Mutation 必须同步；异步操作必须通过 Action。
  • 状态解构需注意响应性：
    • Vuex：直接解构 store.state 会丢失响应性，推荐 computed、mapState、toRefs，或模板中直接访问。
    • Pinia：直接解构 store 会丢失响应性，state 和 getters 用 storeToRefs，actions 可直接解构。
  • 持久化：Vuex 常用 vuex-persistedstate，Pinia 常用 pinia-plugin-persistedstate，也可以手动写 localStorage。
  • 选型：新项目优先 Pinia；老项目如果已大量使用 Vuex，可继续维护，后续逐步迁移到 Pinia。
