scoped 样式作用域

【Vue】scoped 样式作用域

<style scoped> 让样式只作用于当前组件，避免全局污染和组件间样式冲突。

一、作用

在 Vue 单文件组件中：

  • 不加 scoped：样式全局生效，可能影响其他组件。
  • 加 scoped：样式只在当前组件内生效，实现样式私有化。
  • 典型用途：避免类名冲突、让组件更独立可复用。

二、编译原理

只有带 data-v-7ba5bd90 的元素才会匹配该样式，其他组件没有这个属性，因此样式不会作用过去。

三、父子组件行为

1. 父组件 scoped 样式可以影响子组件根元素

Vue 会让子组件的根节点同时带上父组件的 scopeId，所以父组件的 scoped 样式可以作用到子组件根元素。

编译后：

  • 子组件根元素 div 同时带了 data-v-父 和 data-v-子。
  • 子组件内部元素 p 只带 data-v-子，不带 data-v-父。

2. 父组件 scoped 样式默认不能影响子组件内部元素

子组件内部元素只带子组件自己的 scopeId，不带父组件的。
父组件想改子组件内部样式，需要深度选择器。

五、常见坑与注意事项

  1. scoped 不是完全隔离全局样式仍然可以影响组件内部元素。

  2. 动态创建的元素不带 scoped 属性通过 document.createElement 或第三方库生成的 DOM 可能没有 data-v-xxx，scoped 样式会失效。

  3. 样式权重增加因为加了属性选择器，权重比普通类选择器高，覆盖第三方组件样式时可能需要 :deep()。

  4. 子组件根元素会被父组件 scoped 样式影响这是设计行为，不想被影响可避免在父组件直接写子组件根元素样式。

六、与 CSS Modules 对比

对比项 scoped module（CSS Modules）
隔离方式 给元素加data-v-xxx 属性，选择器加 [data-v-xxx] 把类名编译成唯一哈希，如_box_1a2b3
类名是否变化 不变，仍写.box 变成哈希，模板中要用$style.box
模板写法 class="box" :class="$style.box"
动态类名 :class="{ active: isActive }" :class="{ [$style.active]: isActive }"
全局样式影响 全局样式仍可能命中组件内部元素 类名被哈希，全局样式几乎无法命中
深度选择器 :deep()、:slotted()、:global() :global()，写法不同
配置 Vue 编译器原生支持，开箱即用 需要构建工具（Vite/Webpack）支持
学习成本 低，几乎无感 稍高，需要改变类名引用方式

七、为什么有了 module 还需要 scoped

scoped 和 module 解决的是相似但不同的问题，不是替代关系。

1. scoped 写法更自然，学习成本低

保留原始类名，模板照常写 class="box"，CSS 照常写 .box。

2. Vue 原生集成，无需额外配置

<style scoped> 是 Vue SFC 编译器直接支持的功能，开箱即用。

3. 保留语义化类名，便于调试

DevTools 里看到的还是 .box，容易定位。

4. 与全局样式共存更灵活

scoped 只加属性选择器，全局样式（重置样式、第三方库）可以继续影响组件。

5. 历史与生态惯性

scoped 是 Vue 早期方案，大量 Vue 2 项目和组件库基于它。
CSS Modules 更多来自 React 生态，Vue 集成它是为了多一种选择。

6. 适用场景不同

  • scoped 适合：大多数 Vue 项目、组件库、需要保留类名语义、与全局样式混合、快速开发。
  • CSS Modules 适合：对样式隔离要求极严格、团队习惯 CSS Modules、希望类名完全局部化。

八、总结

  • scoped 的作用是让样式只作用于当前组件，避免全局污染。
  • 原理是给模板元素加唯一属性，给样式选择器加对应属性选择器。
  • 父组件 scoped 样式可影响子组件根元素，但不能影响子组件内部元素。
  • 需要穿透时用 :deep()（Vue 3）或 ::v-deep（Vue 2）。
  • 注意全局样式、动态元素和样式权重问题。
  • 与 CSS Modules 相比，scoped 更轻量、更直观，适合大多数 Vue 项目的默认需求。
