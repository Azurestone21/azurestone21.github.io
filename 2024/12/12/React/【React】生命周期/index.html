React 生命周期

React 的“生命周期”是指组件从创建、更新到销毁的整个过程。随着 React 发展，生命周期的使用方式经历了从类组件生命周期方法到函数组件 Hooks的演变。

理解生命周期，核心是理解三个阶段：

一、类组件生命周期

类组件通过特定的方法在生命周期的不同阶段执行代码。

1. 生命周期图谱

2. 挂载阶段

方法 说明
constructor 初始化 state、绑定事件处理函数
static getDerivedStateFromProps 根据 props 派生 state，少见
render 返回 JSX，必须纯函数
componentDidMount DOM 已挂载，适合请求、订阅、操作 DOM

3. 更新阶段

方法 说明
static getDerivedStateFromProps props 变化时派生 state
shouldComponentUpdate 返回 false 可阻止重渲染，性能优化
render 重新计算 JSX
getSnapshotBeforeUpdate DOM 更新前读取布局信息
componentDidUpdate DOM 已更新，适合操作 DOM、发请求

4. 卸载阶段

方法 说明
componentWillUnmount 清理定时器、取消订阅、取消请求

5. 已废弃的生命周期

以下方法因容易出错，已被标记为不安全：

  • componentWillMount
  • componentWillReceiveProps
  • componentWillUpdate

替代方案：

  • componentWillMount → constructor 或 componentDidMount
  • componentWillReceiveProps → getDerivedStateFromProps 或 componentDidUpdate
  • componentWillUpdate → getSnapshotBeforeUpdate

6. 错误处理

方法 说明
static getDerivedStateFromError 渲染出错时更新 state 显示 fallback
componentDidCatch 捕获错误，记录日志

二、函数组件生命周期

函数组件没有生命周期方法，而是用 Hooks 模拟各个阶段。

1. 核心映射

类组件 函数组件
constructor useState 初始化
componentDidMount useEffect(() => {}, [])
componentDidUpdate useEffect(() => {}, [deps])
componentWillUnmount useEffect 返回的清理函数
shouldComponentUpdate React.memo、useMemo、useCallback
getSnapshotBeforeUpdate useLayoutEffect
componentDidCatch 仍需类组件或 Error Boundary 库

2. 挂载

useEffect 在浏览器绘制后执行，适合请求、订阅。

如果需要在绘制前同步执行，用 useLayoutEffect。

3. 更新

依赖变化时执行。依赖数组决定“什么时候重新同步”。

4. 卸载

返回的清理函数在卸载或依赖变化导致下一次执行前调用。

5. 执行顺序

三、类组件与函数组件对比

维度 类组件 函数组件
状态 this.state useState / useReducer
生命周期 生命周期方法 Hooks
副作用 componentDidMount 等 useEffect / useLayoutEffect
性能优化 shouldComponentUpdate / PureComponent React.memo / useMemo / useCallback
逻辑复用 HOC / render props 自定义 Hook
代码量 较多，涉及 this 较少，更简洁
错误边界 类组件 仍需要类组件
推荐程度 维护旧代码 新代码首选

四、现代 React 的生命周期视角

React 18+ 之后，生命周期不再只是“组件自己的事”，还涉及并发渲染和调度。

1. 渲染阶段 vs 提交阶段

Render 阶段必须是纯的，不能有副作用。这是 React 并发特性的基础。

2. StrictMode 下的双调用

开发环境下，StrictMode 会故意双调用：

  • 组件函数
  • useState 初始化函数
  • useMemo 计算函数
  • useEffect 的挂载和清理

目的是暴露副作用不纯的问题。生产环境不会双调用。

3. 并发特性

React 18 引入并发渲染后：

  • Render 阶段可能被中断、丢弃、重放。
  • 生命周期中的“渲染”部分必须是纯的。
  • 副作用应放在 Commit 阶段（useEffect / useLayoutEffect）。

五、常见使用场景

场景 类组件 函数组件
初始化 state constructor useState
请求数据 componentDidMount useEffect(() => {}, [])
依赖变化请求 componentDidUpdate useEffect(() => {}, [deps])
清理定时器 componentWillUnmount useEffect 清理函数
操作 DOM componentDidMount / componentDidUpdate useEffect / useLayoutEffect
读取布局 getSnapshotBeforeUpdate useLayoutEffect
性能优化 shouldComponentUpdate React.memo / useMemo / useCallback
错误捕获 componentDidCatch 仍需类组件

六、注意事项

  1. Render 必须纯：不要在渲染期间发请求、改 DOM、写 ref。
  2. Effect 依赖要完整：漏依赖会导致旧闭包。
  3. 清理函数必须写：定时器、订阅、请求都要清理。
  4. 不要用生命周期思维硬套 Hooks：Hooks 是“同步外部系统”，不是“在某个时间点执行代码”。
  5. StrictMode 双调用是故意的：用来暴露不纯的副作用。
  6. 并发模式下渲染可能被中断：副作用应放在 Commit 阶段。
  7. 错误边界仍需要类组件：函数组件暂不支持。

七、总结

React 生命周期分三个阶段：

  • 类组件：用生命周期方法（componentDidMount、componentDidUpdate、componentWillUnmount 等）。
  • 函数组件：用 Hooks（useEffect、useLayoutEffect、useInsertionEffect）模拟。
  • 现代视角：Render 阶段必须纯，副作用放 Commit 阶段。
  • 核心原则：把生命周期理解为“与外部系统同步”，而不是“在某个时间点执行代码”。

一句话：类组件用生命周期方法，函数组件用 Hooks；现代 React 更强调渲染纯度和副作用的正确时机，而不是死记生命周期方法。
