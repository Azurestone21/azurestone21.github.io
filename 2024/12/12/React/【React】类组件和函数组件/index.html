React 类组件和函数组件

一、概述

React 中定义组件有两种方式：

  • 类组件（Class Component）：用 ES6 class 定义，继承 React.Component。
  • 函数组件（Function Component）：用普通函数定义，返回 JSX。

React 16.8 引入 Hooks 之前，函数组件只能做无状态展示，类组件才能管理状态和生命周期。Hooks 之后，函数组件具备了类组件的所有能力，并成为 React 官方推荐的写法。

2. 核心特点

五、如何选择

新代码

优先用函数组件 + Hooks。这是 React 官方推荐，也是生态主流。

旧代码

如果已有类组件，不必为了迁移而迁移。类组件仍然完全支持，只是：

  • 无法使用 Hooks。
  • 并发特性支持有限。
  • React Compiler 优化效果不如函数组件。

必须用类组件的场景

  • 错误边界：目前只能用类组件实现。
  • 维护老项目：已有类组件，且没有重构计划。
  • 依赖类组件 API 的第三方库：某些库仍要求类组件。

六、常见误区

1. “函数组件性能更好”

不一定。函数组件每次渲染都会重新执行整个函数，但 React 的 Diff 和 Hooks 机制让它通常足够快。性能差异更多取决于代码写法，而不是组件类型。

2. “类组件已经废弃”

不是。类组件仍然完全支持，只是新代码推荐函数组件。React 没有移除类组件的计划。

3. “函数组件不能有状态”

这是 Hooks 之前的限制。现在函数组件通过 useState、useReducer 完全可以管理状态。

4. “Hooks 是生命周期方法的替代品”

不完全是。Hooks 的思维模型是“同步外部系统”，而不是“在某个时间点执行代码”。useEffect 不是 componentDidMount 的简单替代。

5. “类组件不能用 Hooks”

对。Hooks 只能在函数组件或自定义 Hook 中调用，类组件不能用。

七、总结

类组件和函数组件的核心区别：

维度 类组件 函数组件
状态 this.state useState
生命周期 生命周期方法 useEffect 等 Hooks
逻辑复用 HOC / render props 自定义 Hook
this 需要绑定 没有
错误边界 支持 不支持
并发特性 支持有限 支持更好
官方推荐 维护旧代码 新代码首选

一句话：

  • 类组件：面向对象风格，生命周期方法，this，HOC 复用。
  • 函数组件：函数式风格，Hooks，无 this，自定义 Hook 复用。
  • 新代码用函数组件，旧代码可继续用类组件，错误边界仍需类组件。
