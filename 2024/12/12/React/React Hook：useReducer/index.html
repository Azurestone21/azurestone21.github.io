React Hook：useReducer

useReducer 笔记

一、概述

useReducer 是 React 提供的一个状态管理 Hook，用于处理复杂的状态逻辑。它是 useState 的替代方案，核心思想来自 Redux：通过 dispatch action 来触发状态更新，而不是直接设置新值。

基本语法

  • state：当前状态。
  • dispatch：派发 action 的函数。
  • reducer：纯函数，接收 (state, action)，返回新状态。
  • initialState：初始状态。

与 useState 的直观对比

useState 直接设置新值，useReducer 描述“发生了什么”，由 reducer 决定新状态。

二、基本使用

1. 定义 reducer

reducer 必须是纯函数：

  • 不修改原 state，返回新对象。
  • 不做副作用（请求、DOM 操作、日志等）。
  • 相同输入永远返回相同输出。

四、useReducer vs useState

维度 useState useReducer
状态类型 简单值 复杂对象、多字段
更新方式 直接设值 dispatch action
逻辑位置 分散在事件处理中 集中在 reducer
可测试性 一般 reducer 是纯函数，易测试
状态关联 多个 state 各自独立 多个字段一起更新
代码量 简单场景更少 复杂场景更清晰
性能优化 setter 稳定 dispatch 稳定，不会变
适合场景 简单、独立状态 复杂、关联状态

什么时候用 useState

  • 状态是简单值：数字、字符串、布尔。
  • 多个状态之间没有关联。
  • 更新逻辑简单。

什么时候用 useReducer

  • 状态是复杂对象，多个字段一起更新。
  • 下一个状态依赖上一个状态。
  • 更新逻辑复杂，包含多个分支。
  • 需要把状态逻辑集中管理、方便测试。
  • 多个事件处理函数修改同一份状态。

七、注意事项

1. reducer 必须是纯函数

2. dispatch 是稳定的

dispatch 在多次渲染之间引用不变，可以安全地作为依赖，不需要放进 useEffect 依赖数组。

3. React 会双调用 reducer

在 StrictMode 开发环境下，reducer 会被调用两次，用来暴露不纯的写法。所以 reducer 必须纯。

4. 不要用 useReducer 替代所有 useState

简单状态用 useState 更直观。useReducer 适合复杂逻辑，不是越多越好。

九、总结

useReducer 的核心：

要点：

  • 用 dispatch({ type, payload }) 描述“发生了什么”。
  • reducer 是纯函数，返回新状态。
  • 适合复杂状态、多字段关联、逻辑集中的场景。
  • 简单状态用 useState 更合适。
  • dispatch 稳定，不需要放进依赖数组。
  • 配合 Context 可以做轻量级全局状态。
  • reducer 必须纯，不能有副作用，不可变更新。

一句话：useState 管简单状态，useReducer 管复杂状态；前者直接设值，后者描述动作由 reducer 计算新状态。
