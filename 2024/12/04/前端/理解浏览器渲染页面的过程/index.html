理解浏览器渲染页面的过程

理解浏览器渲染页面的过程

参考：https://developer.mozilla.org/zh-CN/docs/Web/Performance/How_browsers_work

一、总览

从输入 URL 到页面显示，大致分为：

导航 → DNS → TCP → TLS → HTTP 请求 → 响应 → 渲染

其中渲染的关键路径可以概括为：

HTML → DOM → CSSOM → Render Tree → Layout → Paint → Layer → Raster → Composite → 显示

二、导航过程

1. 导航 URL 解析

在地址栏输入一个 URL、点击一个链接、提交表单或者是其他的行为

2. 进行DNS 查询，拿到服务器真实 IP

3. TCP 连接

浏览器通过TCP“三次握手”与服务器建立连接

4. TLS 协商

决定使用哪种密码对通信进行加密，验证服务器，并在开始实际数据传输前建立安全连接。

5. HTTP 请求

在服务器响应之后，由于现在 http 默认开始长连接 keep-alive，当页面关闭之后，tcp 链接则会经过四次挥手完成断开

6. 响应请求

服务器返回 HTML、CSS、JS 等资源。

HTTP/1.1 默认开启长连接 keep-alive，页面关闭或超时后，TCP 通过四次挥手断开。

三、页面渲染过程

1. 解析 HTML，构建 DOM 树

字节 → 字符 → Token → Node → DOM 树。
解析是增量的，可以边下载边解析。

2. 预加载扫描器

构造DOM树的同时，预加载扫描器会解析可用的内容并请求高优先级的资源

  1. 非阻塞资源：图片、字体，浏览器会请求这些资源并且继续解析
  2. CSS：不阻塞 DOM 解析，但会阻塞渲染。
  3. 普通 JavaScript：阻塞 HTML 解析，直到下载并执行完成。

3. 构建 CSSOM 树

  1. 解析 CSS 并构建 CSSOM 树
  2. 没有 CSSOM 就无法构建渲染树，所以 CSS 会阻塞渲染，避免 FOUC。

4. JavaScript 编译与执行

  1. 脚本被解析为抽象语法树。
  2. 大部分代码都是在主线程上解释的。
  3. Web Worker 中的代码运行在独立线程。

5. 构建渲染树 Render Tree

将 DOM 和 CSSOM 合并成渲染树。渲染树只包含需要显示的节点：

  • display: none 不进入渲染树；
  • visibility: hidden 会进入渲染树，只是不可见；
  • head、script 等不进入。

6. 样式计算

计算每个节点的最终样式，处理层叠、继承、优先级，把相对单位转为绝对值。

7. 布局 Layout / Reflow

计算每个节点的几何信息：位置、大小、盒模型等。
改变宽高、位置、字体大小等会触发重排。

8. 绘制 Paint

根据布局树和样式生成绘制指令，决定先画什么、后画什么。

9. 分层、光栅化、合成

  • 分层：将页面分成多个图层，如 transform、opacity 动画元素。
  • 光栅化：将图层切成图块并转为位图。
  • 合成：合成线程把图块合成为最终画面，交给 GPU 显示。

10. 显示

GPU 将最终帧绘制到屏幕。

四、CSS阻塞

HTML 的 DOM 解析与 CSS 解析是独立进行的，所以 CSS 解析不会阻塞 DOM 解析。
但 CSS 会 阻塞 DOM 渲染，因为没有 CSSOM 就无法构建渲染树。

另外，CSS 可能间接阻塞 JS 执行：
如果脚本在 CSS 后面，浏览器会等待 CSSOM 构建完成后再执行 JS，因为 JS 可能读取样式。JS 又可能阻塞 DOM 解析，所以 CSS 可能间接影响 DOM 解析。

优化方案

  • 关键 CSS 内联到 <head> 中。
  • 非关键 CSS 异步加载。
  • 使用媒体查询。
  • 使用 preload / prefetch 提前加载资源。

五、JavaScript 阻塞

普通 JS 文件会阻塞 DOM 解析、页面渲染和后续 JS 执行。

优化方案

1. 将 JS 放到最后

把 <script> 放到 <body> 底部。

2. defer 延迟加载

defer 表示延迟执行引入的 JavaScript：

  • 下载时 HTML 不会停止解析；
  • 整个 HTML 解析完，并且 defer 脚本加载完成后；
  • 按顺序执行所有 defer 脚本；
  • 然后在 DOMContentLoaded 事件之前执行。

适用于有代码依赖顺序、需要操作 DOM 的 JS 文件。

3. async 异步加载

async 表示异步加载：

  • 浏览器不必等 JS 下载完成，可以边渲染边在后台下载；
  • 下载完后立即执行；
  • 执行顺序不确定。

适用于没有代码依赖顺序、没有 DOM 操作的 JS 文件。

注意：
defer 和 async 只对外部脚本有效。
动态创建的 <script> 默认相当于 async。
<script type="module"> 默认相当于 defer。

4. 两者区别

属性 下载行为 执行时机 执行顺序 是否阻塞解析
普通 script 阻塞下载 下载完立即执行 按文档顺序 下载和执行都阻塞
defer 并行下载 文档解析完后，DOMContentLoaded 前 按文档顺序 不阻塞解析
async 并行下载 下载完立即执行 不保证顺序 不阻塞解析，执行时可能阻塞

5. 怎么选

  • 脚本之间有依赖、需要按顺序、需要操作 DOM：用 defer。
  • 独立第三方脚本、不依赖顺序、越早执行越好：用 async。
  • 关键脚本、必须立刻执行：普通 <script>。
  • 动态插入脚本并要保序：设 script.async = false。

六、FOUC、FOUT、FOIT

  • FOUC：Flash of Unstyled Content，无样式内容闪烁。页面先以默认样式显示，CSS 加载后再变成正常样式。
  • FOUT：Flash of Unstyled Text，无样式文本闪烁。字体未加载时先用回退字体显示，加载完再切换。
  • FOIT：Flash of Invisible Text，不可见文本闪烁。
    字体未加载时文字先不可见，加载完再显示。

避免 FOUC 的核心：让关键 CSS 尽早生效。

七、重排与重绘

重排 Reflow

几何属性变化，如宽高、位置、字体大小、边距等，需要重新计算布局。

重绘 Repaint

外观变化，如颜色、背景、阴影等，不需要重新布局。

重排一定引起重绘，重绘不一定引起重排。

优化手段

  • 批量修改 DOM，避免强制同步布局。
  • 使用 transform、opacity 做动画。
  • 合理使用 will-change。
  • 使用 requestAnimationFrame 做视觉更新。

客户端渲染和服务端渲染

客户端渲染

  • 首屏渲染需要先拿到空的 html 模板，然后继续发起请求
  • 加载慢，可能会白屏
  • 但节省后端资源

服务端渲染

  • 渲染只需要请求一次，html 模板和数据
  • 首页加载快
  • 有利于 SEO
  • 但耗费资源

总结

浏览器先构建 DOM 和 CSSOM，合并成渲染树，再布局、绘制、分层、光栅化、合成，最后交给 GPU 显示。
