TS 核心概念辨析

TS 核心概念辨析

1. Any 与 Unknown（类型安全的天平）

  • Any（万能逃逸口）：放弃所有类型检查。任何属性访问、方法调用都不会报错，相当于回到纯 JavaScript。
    • 风险：会污染其他变量（赋值给 string 类型变量也不报错）。
  • Unknown（安全的未知）：代表“还不知道是什么类型”。必须通过类型守卫（typeof、instanceof）或类型断言（as）才能使用，否则无法读取属性或方法。
  • 关键区别（收窄）：
    • 联合类型：unknown | T → unknown；any | T → any（因为 any 会吞噬所有类型）。
    • 交叉类型：unknown & T → T（不影响结果，因为 T 一定可以赋值给 unknown）。

2. Const 与 Readonly（不可变性的不同维度）

  • Const（值绑定）：声明变量引用不可变。对于对象，仅保证引用地址不变，对象内部属性依然可以修改（如 const obj = {a:1}; obj.a = 2; 是允许的）。
  • Readonly（属性修饰）：标记属性本身只读，通常在接口、类或类型别名中使用。赋值后（构造时或声明时）不可修改。
  • 进阶补充：
    • as const：将字面量推断为最具体的只读类型（如 let a = [1,2] 推断为 number[]，使用 as const 后推断为 readonly [1, 2]）。
    • 泛型工具：Readonly<T> 可将对象所有属性变为只读。

3. Interface、Type、抽象类（定义结构的三种武器）

Interface vs Type

  • 相同：均可定义对象结构，绝大多数场景可互换。
  • 不同：
    • 合并能力：同名 interface 会自动合并（声明合并）；同名 type 报错。
    • 适用范围：interface 只能描述对象/函数/类；type 可用于联合类型（|）、交叉类型（&）、元组、原始类型别名（如 type MyStr = string）。
    • 计算属性：type 支持 in 关键字做映射类型，interface 不支持。

Interface vs 抽象类

  • 相同：都定义类的契约（必须实现哪些方法/属性）。
  • 不同：
    • 实现代码：抽象类可包含具体方法的实现，接口只能定义签名（纯抽象）。
    • 继承数量：类只能继承一个抽象类，但可以实现多个接口（implements A, B）。

4. Keyof 与 Typeof（查询操作符的组合技）

  • Keyof（键查询）：作用于类型，获取对象类型所有属性名组成的联合类型（string | number | symbol 的子集）。
  • Typeof（类型提取）：作用于变量/值，在类型上下文中提取该值的静态类型。
  • 黄金搭档：keyof typeof object 是 TS 中最常见的组合写法，用于获取已有变量的键名联合类型。

5. 模块 与 命名空间（组织代码的容器）

  • 模块（Module）：ES6 标准。文件包含 import/export 即成为模块，拥有独立作用域。依赖关系明确，适合现代工程（推荐）。
  • 命名空间（Namespace）：TS 遗留特性。本质是全局对象下的嵌套对象（如 MyLib.Utils）。依赖关系需要手动管理（/// <reference>），容易造成全局污染。
  • 最佳实践：新代码优先使用 ES Module；仅在编写声明文件（.d.ts） 或处理遗留全局库时使用命名空间。

6. 元组 与 数组（有序集合 vs 同质列表）

  • 数组（Array）：同构类型（如 number[]）。元素类型必须一致，长度动态，可随意增删（push/pop）。
  • 元组（Tuple）：异构类型（如 [string, number]）。各元素类型、顺序和数量固定。

  • 在 TypeScript 的默认检查中，允许对元组使用 push、pop 等数组方法（运行时长度会改变），类型系统只能保证已知索引的类型正确。若想要真正固定长度，必须配合 as const 或标记为 readonly（即 readonly [string, number]）。

  • 扩展：支持可变元组（Rest 元素），如 [string, ...number[]] 表示第一个是字符串，后面可跟任意数量的数字。

复习速查小贴士

  1. 想让代码绝对安全，遇到未知类型就用 unknown，别用 any。
  2. 定义对象结构用 interface（可扩展性好）；定义联合/交叉/映射类型用 type。
  3. const 防的是“变量重新赋值”，readonly 防的是“属性被篡改”。
  4. 想要元组真的不可变，记得加 readonly 关键字。
