大文件上传和断点续传

大文件上传和断点续传

一、大文件上传的问题

直接上传大文件通常存在两个问题：

  1. 上传时间长：上传过程中用户往往只能等待，无法进行其他操作。
  2. 容易失败：网络波动或请求超时会导致整个文件重新上传，浪费时间和带宽。

解决思路主要有两个：

  • 文件切片：将大文件拆分成多个小分片，分批上传。
  • 断点续传：记录已上传的分片，中断后只补传未完成的部分。

在此基础上，还可以结合秒传（相同文件不重复上传）进一步优化体验。

二、整体流程

一次完整的大文件上传通常包含以下步骤：

  1. 读取用户选择的文件。
  2. 将文件切成固定大小的分片。
  3. 计算文件内容的唯一 hash。
  4. 将 hash 发送给服务端校验：
    • 文件已存在 → 秒传成功；
    • 文件部分存在 → 返回已上传的分片列表，进入断点续传；
    • 文件不存在 → 上传全部分片。
  5. 上传缺失的分片。
  6. 所有分片上传完成后，请求服务端合并分片。
  7. 服务端合并完成，上传结束。

四、文件切片

在 JavaScript 中，File 继承自 Blob，而 Blob 提供了 slice(start, end) 方法，可以对二进制内容进行截取。利用它即可把大文件拆成多个分片。

分片大小的选择：分片过小会导致请求数量过多，增加网络和服务端压力；分片过大则单次失败重传成本高。常见取值在 1MB～10MB 之间，可根据网络环境和业务场景调整。

五、计算文件 hash

服务端不能仅凭文件名区分文件（文件名可被修改），需要根据文件内容生成唯一标识。常用做法是计算文件内容的 MD5 或 SHA 值。

  • 已上传了哪些分片（断点续传）。

4. 暂停与继续

断点续传的核心是记录已上传的分片。实现方式有两种：

  • 服务端记录：每次上传成功后服务端持久化分片状态，下次上传前通过校验接口取回；
  • 前端记录：将已上传的分片 hash 存入 localStorage，配合服务端校验使用。

用户点击“暂停”时，取消未完成的请求（如使用 AbortController）；再次点击“继续”时重新走校验接口，只上传缺失分片。

七、合并分片

所有分片上传完成后，需要服务端将分片合并为完整文件。常见方案有三种：

  1. 前端主动通知：分片全部上传后，前端发送合并请求，服务端收到后合并。
  2. 服务端自动合并：服务端记录分片上传状态，检测到所有分片齐全后自动合并。
  3. 按偏移写入：服务端创建一个与原文件大小相同的目标文件，按每个分片的起始位置直接写入对应区间。这种方式可以实现并行写入，效率更高。

无论采用哪种方式，合并完成后服务端都应清理临时分片文件，避免占用磁盘空间。

八、断点续传

断点续传是一种网络传输机制：当传输中断后，可以从上次中断的位置继续，而不必从头开始。它在大文件、弱网、带宽有限的场景下尤其有价值，能够节省时间、减少带宽浪费、提升用户体验。

原理

  1. 将大文件切分为多个分片，每个分片有唯一标识（通常是 文件 hash + 分片序号）。
  2. 客户端与服务端分别记录已成功上传的分片。
  3. 传输中断后，客户端重新校验，只上传服务端缺失的分片。
  4. 所有分片齐全后合并为完整文件。

断点续传需要客户端与服务端配合：客户端负责切片、校验、补传；服务端负责记录分片状态、提供校验接口、最终合并。

九、秒传

秒传是指：当用户上传的文件在服务端已存在时，直接复用已有文件，无需真正上传内容。

实现方式

  1. 前端计算文件内容的 hash（如 MD5）。
  2. 上传前将 hash 发送给服务端校验。
  3. 服务端在文件记录中查找相同 hash：
    • 存在 → 直接返回成功，并把已有文件关联到当前用户/业务；
    • 不存在 → 走正常上传流程。
  4. 服务端需要维护一张文件信息表，记录文件 hash、存储路径、大小、分片状态等。

注意事项

  • 文件 hash 必须具备唯一性和稳定性，否则无法正确判断“相同文件”。
  • 完整计算大文件 hash 耗时较长，可结合抽样 hash + 完整校验，或使用服务端已有的快速校验机制。
  • 秒传本质是内容去重，适合多用户上传相同文件的场景；对安全性要求高的场景，还需考虑权限校验与文件归属关系。

作用

  • 减少重复上传，节省带宽；
  • 降低服务端存储与处理压力；
  • 用户上传相同文件时几乎瞬间完成，体验更好。

十、小结

大文件上传与断点续传的核心可以概括为：

  • 切片：把大文件拆小，降低单次请求失败成本；
  • hash：用文件内容生成唯一标识，用于校验、秒传和续传；
  • 校验：上传前先问服务端“缺什么”；
  • 补传：只上传缺失分片，配合并发控制与暂停/继续；
  • 合并：所有分片齐全后由服务端合并并清理临时文件。

整套方案需要前后端协同设计，前端负责切片、hash、并发与进度展示，后端负责分片存储、状态记录、校验与合并。
