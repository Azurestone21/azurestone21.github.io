前端模块化

前端模块化

一、什么是模块化

模块化是指将一个复杂的程序按照一定规则拆分成多个文件，每个文件内部实现私有，只通过暴露的接口与外部通信。

模块化的核心思想是：模块之间默认私有隔离，通过导入和导出共享数据和功能。

模块化开发的优点

  • 避免变量污染和命名冲突
  • 提高代码复用率
  • 提高可维护性
  • 更清晰地管理依赖关系

二、主流模块化规范

常见的前端模块化规范有 CommonJS、AMD、CMD、ES Module。目前主流使用的是 CommonJS 和 ES Module，AMD、CMD 已较少使用。

1. CommonJS

早期 JavaScript 没有模块化概念。Node.js 诞生后，将模块系统引入 JavaScript，Node.js 使用的是 CommonJS 规范。

CommonJS 的特点：

  • 导出：module.exports、exports
  • 导入：require
  • 在 Node.js 服务端，模块加载是运行时同步加载
  • 在浏览器端使用 CommonJS，通常需要提前编译打包处理
  • require 导入的是值的拷贝（对于基本类型而言）

补充说明：

  • exports 是 module.exports 的初始引用，通过 exports.xxx = ... 添加属性是有效的。
  • 不能直接给 exports 赋值来替换导出对象，例如 exports = { name } 不会生效，应使用 module.exports = { name }。
  • CommonJS 模块首次加载后会缓存，再次 require 得到的是同一份导出对象。

2. ES Module

ES Module（ES6 模块化）是官方标准的模块化规范，在语言标准层面实现了模块化功能。它目前是最流行的模块化规范，浏览器和 Node.js 均支持。

ES Module 的特点：

  • 导出：export、export default
  • 导入：import
  • 导入的是值的引用（live binding）。多个文件导入同一模块时，一个文件修改了模块内部的值，另一个文件读到的也会是修改后的值。

补充说明：

  • 命名空间导入 import * as test 得到的对象中，默认导出会挂在 test.default 上。
  • import 声明只能写在模块顶层，不能写在条件语句或函数内部。
  • 如果需要按需或条件加载，可以使用动态导入 import()，它返回 Promise。

export 和 export default 的区别

  • 两者都可以用于导出常量、函数、类、对象等。
  • 一个模块中可以有多个 export，但 export default 只能有一个。
  • export 通常需要具名导入，导入时使用 { }；export default 使用默认导入，导入时可以自定义名称，不需要 { }。
  • export default 后面可以直接跟表达式，例如 export default 1 + 1；而 export 后面通常跟声明或导出列表。

在 Node.js 中运行 ES Module

有两种常见方式：

  1. 将文件后缀从 .js 改为 .mjs，Node.js 会自动按 ES Module 识别。
  2. 在 package.json 中设置 "type": "module"，该目录下的 .js 文件会按 ES Module 处理。

三、CommonJS 与 ES Module 的区别

CommonJS 和 ES Module 都是 JavaScript 的模块系统，主要区别如下：

对比项 CommonJS ES Module
导入导出语法 module.exports / exports，require export / export default，import
加载时机 运行时加载，require 可出现在任意位置 静态解析，import 声明通常在模块顶层
导入值类型 值的拷贝（基本类型） 值的引用（live binding）
静态分析 较弱，不利于 tree-shaking 强，便于静态分析和 tree-shaking
按需加载 可通过运行时 require 条件加载 静态 import 不支持条件加载，可用动态 import()
严格模式 默认非严格模式 默认严格模式
浏览器支持 通常需要打包工具处理 原生支持 <script type="module">

需要说明的是：

  • CommonJS 的“运行时加载”使其可以动态 require，但也导致依赖关系不够静态。
  • ES Module 的静态解析便于在编译阶段确定依赖关系，有利于 tree-shaking 和优化。
  • ES Module 支持动态 import()，可以实现按需加载和异步加载，不阻塞主线程。
  • 在 Node.js 中，CommonJS 模块加载是同步的；在浏览器中，ES Module 的加载行为由浏览器模块加载机制决定。

四、小结

模块化的本质是隔离与共享：模块内部实现私有，通过导出暴露能力，通过导入使用其他模块。

  • CommonJS 适合 Node.js 服务端场景，语法简单，运行时加载，导入的是值的拷贝。
  • ES Module 是官方标准，静态解析、支持 tree-shaking，导入的是值的引用，是现代前端工程的主流选择。

实际项目中，应根据运行环境和构建工具选择合适的模块规范，并注意两者在加载机制、值传递方式和严格模式上的差异。
