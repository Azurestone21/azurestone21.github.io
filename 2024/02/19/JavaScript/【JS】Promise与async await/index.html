Promise 与 async/await

Promise 与 async/await

一、Promise

Promise 是异步编程的一种解决方案，用于解决回调地狱，特点是链式调用和状态机制。

1. 状态与执行时机

Promise 有三种状态：

  • pending：等待中
  • fulfilled：已完成
  • rejected：已失败

且一旦变化不可逆、不可二次修改。

执行时机：

  • new Promise(executor) 中的 executor 是同步执行的。
  • then、catch、finally 注册的回调是异步执行的，进入微任务队列。
  • then 方法本身是同步的，它会返回一个新的 Promise。
  • executor 内同步 throw 会让 Promise 变成 rejected。
  • executor 内异步回调抛错，例如 setTimeout(() => { throw err })，不会改变 Promise 状态，会变成全局未捕获错误。

2. 实例方法

then()

  • 第一个参数处理成功，第二个参数处理失败。
  • 返回一个新的 Promise，所以可以链式调用。
  • 如果回调返回 Promise，会等待它 settle。
  • 如果回调抛错，新 Promise 变成 rejected。

finally()

3. then 的 err 回调与 catch 的关系

catch 在 then 之后

  1. then 写了 err 回调，则错误由该 err 回调处理。
  2. then 没写 err 回调，则错误会穿透到后面的 catch。
  3. 如果 err 回调也抛出错误，则错误继续交给后面的 catch。
  4. 如果 catch 之前有多个 then，只要其中一个 then 抛出错误，就会直接走到 catch。
  5. 如果 catch 之前有一个 err 回调处理了错误，并且没有继续抛错，则后面的 then 成功回调会执行。

catch 在 then 之前

  1. 前面的错误由 catch 解决，之后 then 的成功回调会执行。
  2. 如果后面的 then 又抛错，需要再写一个 catch 处理。

4. 静态方法

Promise.all()

  • 参数：Promise 数组或可迭代对象。
  • 全部成功才成功，返回结果数组，顺序与传入顺序一致。
  • 只要有一个 rejected，就立即 rejected，原因是第一个 rejected 的值。
  • 其他 Promise 仍会继续执行，只是结果不再被 Promise.all 采用。

注意：如果某个 Promise 自己定义了 catch，它一旦被 rejected 并自己处理成 fulfilled，则不会触发 Promise.all 的 reject。

Promise.allSettled()

  • 等待所有 Promise 都结束。
  • 返回每个结果对象：
    • { status: 'fulfilled', value }
    • { status: 'rejected', reason }

Promise.race()

  • 第一个 settle 的 Promise 决定结果。
  • 无论是 fulfilled 还是 rejected，都会立即采用。

Promise.any()

  • 第一个 fulfilled 的 Promise 决定结果。
  • 如果全部 rejected，则抛出 AggregateError，其中 errors 包含所有 rejection 原因。

5. Promise 解决了什么问题

  1. 通过 then 实现链式回调，避免回调地狱。
  2. 通过 Promise.all 并发发起多个异步请求，并统一等待结果。
  3. 通过 Promise.race 获取多个异步请求中最快返回的结果。
  4. 通过状态机制让异步结果更可控、可组合。

二、async/await

async/await 是基于 Promise 和 Generator 的异步语法糖。

async

  • async 声明的函数一定是异步函数。
  • 调用后返回一个 Promise。
  • return value 相当于 Promise.resolve(value)。
  • throw err 相当于返回 rejected Promise。
  • async 函数可以看作 Generator 函数的语法糖：* 换成 async，yield 换成 await。

await

  • await 只能出现在 async 函数中，或 ES Module 顶层。
  • await 后面可以接 Promise，也可以接普通值。
  • 如果接普通值，会包装成 Promise.resolve(value)。
  • await 会暂停当前 async 函数的执行，但不会阻塞主线程。
  • Promise fulfilled 时，await 返回结果。
  • Promise rejected 时，await 抛出原因，可用 try/catch 捕获。

三、Promise 与 async/await 的原理

Promise

  • 本质是一个状态机。
  • 内部维护状态 pending / fulfilled / rejected。
  • 通过回调队列保存 then 注册的处理函数。
  • 状态改变后，把回调放入微任务队列执行。
  • then 返回新 Promise，实现链式调用和错误穿透。

async/await

  • async 函数执行结果是一个 Promise。
  • async/await 是 Generator 的语法糖。
  • 核心逻辑是自动迭代执行 next()。
  • await 相当于 yield，等待 Promise settle 后恢复执行。
  • 遇到 rejected，会向 async 函数返回的 Promise 抛出错误。

四、async/await 与 Promise 的差别

对比点 Promise async/await
语法 .then().catch() 链式 同步写法
可读性 链长时较差 复杂逻辑更清晰
错误处理 .catch() try/catch
代码流程 回调式 更接近同步代码
本质 异步基础 Promise 的语法糖
并发 适合Promise.all 等组合 也可配合Promise.all

注意：async/await 并没有取代 Promise，很多场景仍需 Promise 的静态方法处理并发。

六、易错点总结

  1. Promise 状态一旦改变不可逆。
  2. executor 同步执行，then/catch/finally 回调异步执行。
  3. executor 内异步抛错不会被 Promise 捕获。
  4. then 的第二个参数只处理当前 Promise 的 rejection，不处理 onFulfilled 内抛出的错误。
  5. catch 等价于 then(null, onRejected)。
  6. Promise.all 一个失败就失败，但其他 Promise 仍会执行。
  7. 独立异步任务不要串行 await，可用 Promise.all 并发。
  8. forEach 里 await 不会等待，应该用 for...of 或 Promise.all + map。
  9. async/await 是 Promise 的语法糖，不是替代品。
