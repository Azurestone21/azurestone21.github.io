React ref Hook

一、ref 概念

ref 可以理解为一个贯穿组件生命周期的可变盒子。它有两个核心特点：

  1. 修改 .current 不会触发重新渲染。
  2. 它在多次渲染之间保持同一个引用。

用一句话概括：

和 state 对比：

维度 state ref
修改后是否重新渲染 是 否
是否跨渲染保持 是 是
是否参与渲染计算 是 不应该
典型用途 驱动 UI 存 DOM、存定时器 ID、存不需渲染的值

关键区别：state 用来渲染，ref 用来记住东西，但不告诉 React 要重渲染。

二、useRef 基本用法

  • ref.current：当前值，可读写。
  • initialValue：初始值，只在首次渲染时使用，之后被忽略。
  • useRef 返回的对象在组件整个生命周期内是同一个。

点击时 countRef.current 会递增，但组件不会重新渲染，界面上的数字不会变。

四、ref 和渲染的关系

ref 的核心特性：修改 .current 不会触发重新渲染。

这带来两个推论：

  1. 不要在渲染期间读写 ref 来影响 UI。因为读写 ref 不会触发渲染，UI 可能和 ref 不一致。
  2. 不要在渲染期间写 ref（除非是惰性初始化）。React 的渲染应该是纯的，写 ref 属于副作用。

正确用法是：

  • 在事件处理函数中读写 ref。
  • 在 useEffect / useLayoutEffect 中读写 ref。
  • 在渲染期间只读取，且用于非 UI 逻辑时要谨慎。

八、常见陷阱

1. 在渲染期间读取 ref.current

2. 在渲染期间写 ref

3. 用 ref 存需要渲染的值

如果值变了要反映到 UI，用 useState。

4. 依赖 ref.current 触发重新渲染

ref 变化不会触发渲染，所以不要期望它驱动 UI。

九、什么时候用 ref

  • 访问 DOM：聚焦、滚动、测量、播放媒体。
  • 存定时器 ID、订阅句柄、WebSocket 连接。
  • 记录上一次的值、渲染次数。
  • 存不需要触发渲染的可变值。
  • 与第三方库集成，需要传 DOM 节点。

什么时候不用：

  • 需要驱动 UI 更新 → 用 useState。
  • 能通过 props / state 计算出来 → 不需要 ref。
  • 想在渲染期间同步数据 → 用 state 或 useMemo。

十、总结

ref 的核心：

要点：

  • useRef(initialValue) 返回 { current }，跨渲染稳定。
  • 主要用途：访问 DOM、存不驱动 UI 的可变值。
  • 不要在渲染期间读写 ref。
  • 需要驱动 UI 就用 state，不需要就用 ref。
  • 函数组件默认不能接收 ref，需要 forwardRef（React 19 起可直接作为 prop）。
  • useImperativeHandle 可以自定义暴露给父组件的接口。

state 用来渲染，ref 用来记住；改 state 会重渲染，改 ref 不会。
