React useEffect Hook

React useEffect Hook

React 有三个处理副作用的 Hook，它们的区别主要在执行时机和用途：

  • useEffect：异步，浏览器绘制后执行，不阻塞渲染。
  • useLayoutEffect：同步，DOM 更新后、浏览器绘制前执行，会阻塞绘制。
  • useInsertionEffect：同步，在 DOM 变更阶段、useLayoutEffect 之前执行，主要用于 CSS-in-JS 插入样式。

一、执行时机对比

用一句话概括：

  • useInsertionEffect：最早，在 DOM 变更时插入样式，早于 useLayoutEffect。
  • useLayoutEffect：DOM 已更新，但浏览器还没绘制，可以读取布局。
  • useEffect：浏览器已经绘制，不阻塞用户看到界面。

二、useEffect

1. 是什么

useEffect 用于处理组件中的副作用，例如数据请求、订阅、事件监听、操作 DOM 等。它在浏览器绘制完成后异步执行，不会阻塞用户看到界面。

2. 基本语法

  • 第一个参数：副作用函数。
  • 返回值：可选的清理函数。
  • 第二个参数：依赖数组。

3. 依赖数组

  • 不传依赖数组：每次渲染后都执行。
  • 传空数组 []：只在挂载时执行一次，卸载时执行清理。
  • 传依赖：依赖变化时重新执行。

4. 清理函数

清理函数会在组件卸载或依赖变化导致下一次执行前调用。

5. 常见用途

  • 数据请求
  • 事件监听与解绑
  • 订阅与取消订阅
  • 定时器
  • 操作 DOM（非布局测量）
  • 日志上报

6. 注意事项

  • 不要直接修改 state，应通过 setter。
  • 依赖数组要完整，否则可能捕获过时闭包。
  • 副作用是异步的，不会阻塞绘制。
  • 如果依赖了对象或数组，注意引用变化。
  • 在 SSR 中不会执行。

三、useLayoutEffect

1. 是什么

useLayoutEffect 的用法和 useEffect 几乎一样，但它在所有 DOM 变更之后、浏览器绘制之前同步执行。

因为它在绘制前执行，所以如果在里面对 DOM 做了修改，用户不会看到中间状态，可以避免闪烁。

3. 典型场景：测量布局

4. 其他常见用途

  • 读取元素尺寸、位置、滚动位置
  • 根据布局同步更新 state
  • 设置焦点、滚动条位置
  • 动画初始状态设置，避免首帧跳动

6. 注意事项

  • 会阻塞浏览器绘制，逻辑太重会拖慢页面。
  • 不要滥用，大多数副作用应该用 useEffect。

四、useInsertionEffect

1. 是什么

useInsertionEffect 是 React 18 引入的 Hook，专门给 CSS-in-JS 库作者使用。

它在 commit 阶段的 mutation 阶段执行，早于 useLayoutEffect，也早于浏览器绘制。它的目的是：在布局计算之前，把样式插入到 DOM 中。

2. 基本语法

3. 为什么需要它

CSS-in-JS 库（如 styled-components、emotion）在运行时动态生成样式。如果样式插入太晚，浏览器可能先按旧样式布局，然后再重排，导致闪烁或性能问题。

useInsertionEffect 保证：

  • 样式在 useLayoutEffect 读取布局之前就已经插入。
  • 不会触发额外的重排。
  • 适合插入 <style> 标签或更新 CSSOM。

4. 与 useLayoutEffect 的区别

特性 useLayoutEffect useInsertionEffect
执行时机 DOM 更新后、绘制前 DOM 变更前
主要用途 读取布局、同步更新 插入样式
能否读 DOM 布局 可以 不推荐，ref 可能还没挂上
能否 setState 可以，但会同步重渲染 可以但不推荐
使用者 普通组件 CSS-in-JS 库作者

5. 注意事项

  • 普通业务组件几乎不需要它。如果你不是写 CSS-in-JS 库，用 useEffect 或 useLayoutEffect 就够了。
  • 它运行在 ref 挂载之前，所以不要在里面读取 ref 或做布局测量。
  • 它不支持 SSR，只在客户端运行。
  • 不要在里面做数据请求、订阅等常规副作用。

五、三者对比

Hook 执行时机 是否阻塞绘制 主要用途 典型场景 SSR 使用者
useEffect 浏览器绘制后，异步 否 常规副作用 请求、订阅、事件监听 不执行 所有组件
useLayoutEffect DOM 更新后、绘制前，同步 是 读取布局、避免闪烁 测量尺寸、设置焦点 不执行且警告 需要测量布局的组件
useInsertionEffect DOM 变更前，同步 是 插入样式 CSS-in-JS 不执行 CSS-in-JS 库作者

四、如何选择

Hook 使用场景
useEffect 绝大多数副作用：请求、订阅、日志、事件监听
useLayoutEffect 需要读取 DOM 布局，并且要避免闪烁
useInsertionEffect 开发 CSS-in-JS 库，需要在布局前插入样式

简单判断：

  • 不影响 DOM 布局的副作用 → useEffect
  • 需要测量 DOM、同步修改以避免闪烁 → useLayoutEffect
  • 你是 CSS-in-JS 库作者，需要插入样式 → useInsertionEffect

六、总结

  • useEffect：异步，绘制后执行，不阻塞，最常用。
  • useLayoutEffect：同步，DOM 更新后、绘制前执行，会阻塞绘制，用于读取布局、避免闪烁。
  • useInsertionEffect：同步，DOM 变更阶段执行，早于 useLayoutEffect，专用于 CSS-in-JS 插入样式。
