二、浏览器渲染管线：CPU 与 GPU 的分工

浏览器渲染一帧，大致分两个阶段：

CPU 负责的部分：

  1. 解析 HTML/CSS，构建 DOM 和 CSSOM
  2. Layout（布局）：计算每个元素的位置和尺寸
  3. Paint（绘制）：生成绘制指令，比如”在 (x, y) 画一个红色矩形”

GPU 负责的部分：

  1. Raster（光栅化）：把绘制指令变成像素，生成纹理（Texture）
  2. Composite（合成）：把多个图层的纹理按位置、透明度、变换矩阵叠加成最终画面

关键认知：光栅化和合成都发生在 GPU 上。也就是说，页面上所有可见内容，最终都以某种形式存在于 GPU 纹理中。区别只在于——是”独享”一张纹理，还是和别人”合租”。

三、Layer：GPU 纹理的分配单位

浏览器不会给每个 DOM 元素都分配一张 GPU 纹理（显存扛不住）。它采用的策略是合成层（Compositing Layer）：

  • 普通元素：没有独立 Layer，它们的绘制指令被合并到最近的合成层里，和成千上万个”室友”共享同一张纹理。改动其中任何一个，整张共享纹理都要重新光栅化。
  • 被提升的元素：满足特定条件（使用 transform、opacity 动画，或设置了 will-change）的元素，会被提升为独立合成层，独占一张纹理。改动它时，GPU 只需修改这张纹理的变换矩阵或透明度，不连累别人。

这就是为什么”用 transform 做动画比改 left/top 流畅”——前者只触发 Composite，GPU 直接移动已有纹理；后者触发 Layout → Paint → Composite，CPU 要重新计算布局和重绘。

四、谁决定属性”能不能上 GPU”

一个常见的误解是”CSS 规范规定了哪些属性能 GPU 加速”。实际上，决定权在浏览器渲染引擎的实现里，最典型的是 Chromium 的 Blink 和合成器 cc。

Blink 中有一个关键判断函数 CheckCanStartAnimationOnCompositor()，它会检查：属性类型是否可合成、元素能否被提升为合成层、合成模式是否满足条件。只有通过检查的属性变化，才会被”委托”给合成线程，由 GPU 执行。width、height、margin 这类改变布局的属性，永远走 CPU，没有资格进入这条路径。

所以”分配”的本质不是把属性拆给 CPU 或 GPU，而是通过合成层机制：符合条件的元素被提升为独立层，它的 transform/opacity 变化就由 GPU 在合成阶段处理。

五、回到那个 Bug：为什么 translate3d 能修好圆角

现在可以解释 iOS 的现象了。

在 WebKit 里，当图片或父容器因为某些原因（Flex/Grid 拉伸、动画、will-change）被提升为合成层时，会触发一个存在已久的 Bug：合成层元素的 border-radius 裁剪失效。元素变成独立层后，圆角裁剪指令没有正确应用到这一层上，图片就露出了直角。

而加上 transform: translate3d(0, 0, 0)，本质是用魔法打败魔法：它强制元素进入一种特定的渲染状态，迫使 border-radius 的裁剪路径被重新正确应用，或者让父容器的 overflow: hidden 重新”抓住”这个图片。它不是在”开启加速让圆角生效”，而是把一个有 Bug 的渲染路径，推到了正常的路径上。

六、GPU 在前端还有哪些用武之地

除了动画加速，GPU 在前端的应用远比想象中广：

  • 滚动与合成：页面滚动流畅的基础，就是 GPU 移动已光栅化的纹理。
  • Canvas 2D / WebGL：现代浏览器默认启用 GPU 加速的 Canvas；WebGL 让前端能用 JS 调用 GPU 做 3D 渲染、数据可视化、粒子效果（Three.js、地图渲染）。
  • WebGPU：WebGL 的继任者，支持计算着色器，可用于前端做通用并行计算，如机器学习推理、视频处理。
  • 滤镜与视频：CSS filter、backdrop-filter、视频帧合成都依赖 GPU 并行运算。
  • 3D 变换：perspective、rotate3d 由 GPU 做矩阵变换，实现卡片翻转、视差滚动。
  • 兼容性 Hack：就像这次的圆角问题，translateZ(0) 是前端处理渲染 Bug 的常用手段。

七、总结

浏览器把某些 CSS 属性（transform、opacity、filter）映射为 GPU 的合成/像素运算，通过合成层机制绕过 CPU 的布局与重绘。 普通元素并非”不进 GPU”，而是和别人共享纹理；被提升的元素独享纹理，从而获得独立变换的能力。

理解这条链路的价值在于：

  1. 写高性能动画：优先用 transform/opacity，只触发 Composite。
  2. 谨慎使用图层提升：will-change 和 translateZ(0) 不是免费的，滥用会导致层爆炸和显存浪费。
  3. 看懂兼容性 Bug：很多诡异的渲染问题，根源都在合成层的创建与裁剪逻辑上。translate3d 能修圆角，isolation: isolate 能更优雅地修，背后都是同一套机制。

GPU 不是魔法，它只是把”重复的像素级工作”从 CPU 手里接了过去。理解它接了什么、怎么接的，才能真正驾驭它。
