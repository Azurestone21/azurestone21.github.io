MySQL：索引与慢查询优化

一、索引的本质与作用

概念 说明
索引是什么 一种有序的数据结构（InnoDB 使用 B+ 树），类似于书的目录，用于快速定位数据。
核心优势 极大提升 SELECT 查询速度（尤其大数据量），避免全表扫描。
核心代价 占用额外磁盘空间；INSERT/UPDATE/DELETE 时需要同步维护索引树，写入变慢。
黄金原则 为“查多改少”的字段建索引，不为“写多读少”的字段滥建索引。

二、索引的类型

索引类型 关键字 特点 典型场景
主键索引 PRIMARY KEY 唯一且非空，一张表只能一个，自动创建 每张表都有
唯一索引 UNIQUE 保证字段值唯一，允许 NULL 手机号、邮箱、订单号、学号
普通索引 INDEX 无唯一性要求，只为加速查询 外键字段、用户 ID、分类 ID
联合索引 INDEX(a, b, c) 多字段组合，遵循最左前缀原则 多条件查询、排序优化、覆盖索引
全文索引 FULLTEXT 用于文本搜索，支持模糊匹配、排序优化 文档搜索、商品描述

三、索引语法

四、联合索引与最左前缀原则（面试核心）

规则：联合索引 (a, b, c) 相当于同时建有 (a)、(a, b)、(a, b, c) 三个索引。
查询条件必须从索引的最左边开始匹配，才能用到索引。

索引 (a, b, c) 查询条件 是否命中 说明
✅ WHERE a = 1 命中 (a) 带头大哥在
✅ WHERE a = 1 AND b = 2 命中 (a, b) 连兄弟也在
✅ WHERE a = 1 AND b = 2 AND c = 3 命中 (a, b, c) 完美命中
❌ WHERE b = 2 失效 没带头大哥
❌ WHERE b = 2 AND c = 3 失效 没带头大哥
⚠️ WHERE a = 1 AND c = 3 只用 (a) 跳过了 b，c 用不上
⚠️ WHERE a > 1 AND b = 2 只用 (a) 范围查询断了右边的路

口诀：“带头大哥不能丢，中间兄弟不能断。”

五、索引失效的 5 大经典场景（必查清单）

场景 错误写法 正确写法
隐式类型转换 WHERE phone = 13800001111（phone 是 VARCHAR） WHERE phone = '13800001111'
对索引列使用函数 WHERE DATE(create_time) = '2026-09-08' WHERE create_time >= '2026-09-08' AND create_time < '2026-09-09'
对索引列做运算 WHERE id - 1 = 10 WHERE id = 10 + 1
LIKE 以 % 开头 WHERE name LIKE '%明' WHERE name LIKE '张%'
OR 中有非索引列 WHERE id = 1 OR age = 18（age 无索引） 改用 UNION 或给 age 也建索引
使用 != 或 IS NOT NULL WHERE status != '已删除' 一般只能全表扫，考虑业务逻辑规避

EXPLAIN 执行计划解读

EXPLAIN 是分析 SQL 性能的核心工具，重点看以下字段：

字段 含义 关注点
type 表的访问方式（性能从高到低） const > eq_ref > ref > range > index > ALL（全表扫描）
possible_keys 可能用到的索引 如果为 NULL，考虑建索引
key 实际用到的索引 目标：不为 NULL
key_len 索引实际使用的字节数 判断联合索引用了几列：INT 每列约 5 字节（含 NULL 标志）
rows 预估扫描的行数 越小越好
Extra 额外信息（见下表） 重点看是否有 Using filesort 或 Using temporary

Extra 列速查表

Extra 值 含义 风险
Using index 覆盖索引，数据全从索引拿，不用回表 🟢 最优
Using index condition 索引条件下推（ICP），减少回表 🟢 好
Using where Server 层过滤数据，正常现象 ⚪ 中性
Using filesort 需要额外排序，索引未覆盖 ORDER BY 🔴 警惕，需优化
Using temporary 使用了临时表（常见于复杂 GROUP BY） 🔴 严重，必须优化

七、如何选择索引类型

业务场景 推荐索引 理由
手机号/邮箱登录（WHERE email = ?） 唯一索引 查得快 + 防重复
用户订单列表（WHERE user_id = ? ORDER BY create_time DESC） 联合索引 (user_id, create_time) 过滤 + 排序都走索引
多条件筛选（WHERE a = ? AND b = ? AND c > ?） 联合索引 (a, b, c) 等值在前，范围在后
后台按时间排序（ORDER BY create_time） 普通索引 (create_time) 避免 Using filesort
查询只查固定字段（SELECT a, b FROM table WHERE a = ?） 联合索引 (a, b) 覆盖索引，不回表

九、针对 enrollments 表的实战索引设计

查询 SQL 推荐索引 理由
SELECT * FROM enrollments WHERE student_id = 2; (student_id) 单列等值查询
SELECT * FROM enrollments WHERE student_id = 2 AND course_id = 1; (student_id, course_id) 联合索引完美命中
SELECT student_id, course_id FROM enrollments WHERE student_id = 2; (student_id, course_id) 覆盖索引，不回表
SELECT * FROM enrollments WHERE course_id = 1; 外键自带 (course_id) 无需额外建
