MySQL：事务与锁

一、事务基础

1.1 什么是事务？

事务是一组 SQL 语句的集合，它们被当作一个整体来执行。要么全部成功（提交），要么全部失败（回滚）。

经典场景：银行转账

1.2 事务的四大特性（ACID）

特性 英文 大白话解释
原子性 Atomicity 一捆 SQL，要么全做，要么全不做
一致性 Consistency 转账前后，钱的总数不变
隔离性 Isolation 多个事务并发执行时，互不干扰
持久性 Durability 一旦 COMMIT，数据永久保存，断电也不丢

2.3 MySQL 的自动提交陷阱

MySQL 默认 autocommit = ON，每条 SQL 执行后自动提交，无法回滚。

重要：在 MySQL 中，BEGIN 只是关闭了自动提交，但 CREATE TABLE、ALTER TABLE 等 DDL 操作会隐式提交当前事务！

三、锁的核心概念

3.1 为什么需要锁？

多个事务并发操作同一数据时，如果没有锁，会出现数据错乱。锁的作用是保证并发时的数据一致性。

3.2 锁的分类（按粒度）

锁类型 锁定范围 开销 并发能力 存储引擎
表锁 锁定整张表 小 低 MyISAM、InnoDB
行锁 只锁定某一行 大 高 仅 InnoDB

铁律：InnoDB 的行锁是通过索引实现的。如果 WHERE 条件没用上索引，行锁会升级为表锁！

3.3 锁的分类（按模式）

共享锁 S 锁 读锁 读锁和读锁兼容
排他锁 X 锁 写锁 写锁和任何锁都不兼容

3.4 意向锁（Intention Lock）

作用：当一个事务要锁住某行时，先在表级别加一个“意向锁”，告诉其他事务“这表里有人正在锁行”。

特点：由 InnoDB 自动管理，无需手动操作。

四、隔离级别（Isolation Level）

4.1 三大并发隐患

问题 英文 大白话解释
脏读 Dirty Read 读到了别人未提交的修改
不可重复读 Non-Repeatable Read 同一事务内，两次读同一行数据，结果不一样
幻读 Phantom Read 同一事务内，两次查询的记录数不一样（多了或少了）

4.2 SQL 标准定义的 4 种隔离级别

隔离级别 脏读 不可重复读 幻读 MySQL 默认？

六、死锁（Deadlock）

6.1 什么是死锁？

两个或多个事务互相持有对方需要的锁，形成循环等待，全部卡死。

6.2 经典死锁案例

时间 事务 A 事务 B
T1 UPDATE t SET a=1 WHERE id=1;（持有 id=1 锁）
T2 UPDATE t SET a=2 WHERE id=2;（持有 id=2 锁）
T3 UPDATE t SET a=3 WHERE id=2;（等待 B 释放 id=2）
T4 UPDATE t SET a=4 WHERE id=1;（等待 A 释放 id=1）

结果：死锁形成，MySQL 自动回滚其中一个事务。

6.3 如何避免死锁？

  1. 固定访问顺序：所有事务按相同顺序访问表和行。
  2. 缩短事务长度：事务越小，持有锁越少，死锁概率越低。
  3. 尽量用 = 等值查询，减少范围查询（范围查询产生间隙锁，易死锁）。
  4. 应用程序捕获死锁异常并重试。

七、MVCC（多版本并发控制）

7.1 MVCC 是什么？

MVCC 让数据库在高并发下做到 “读不阻塞写，写不阻塞读”。核心思想是：数据修改时生成新版本，而非覆盖旧版本。

7.2 每一行数据的隐藏字段

InnoDB 每行数据偷偷藏着 3 个隐藏列：

隐藏字段 含义
DB_TRX_ID 最近一次修改这行数据的事务 ID（全局递增）
DB_ROLL_PTR 指向“上一个版本”的指针（Undo Log）
DB_ROW_ID 隐含自增 ID（无主键时使用）

7.4 Read View（读视图）

InnoDB 执行 SELECT 时生成一个 Read View，记录当时所有未提交的事务 ID。

可见性判断逻辑（精简版）：

  1. 如果版本的 DB_TRX_ID < 最小活跃事务 ID → 可见
  2. 如果版本的 DB_TRX_ID = 当前事务 ID → 可见
  3. 如果版本的 DB_TRX_ID 在未提交列表里 → 不可见，沿指针找上一个版本

7.5 RR 和 RC 的本质区别

隔离级别 Read View 生成时机 效果
读已提交（RC） 每次 SELECT 重新生成 能看到别人最新提交的数据
可重复读（RR） 事务内第一次 SELECT 生成，后续复用 全程看到同一份快照

九、核心总结

  1. 事务 = 一组 SQL 的捆绑包，要么全成功（COMMIT），要么全失败（ROLLBACK）。
  2. 锁 = 解决并发问题的工具，行锁通过索引实现。
  3. 隔离级别 = 在“一致性”和“性能”之间做平衡。
  4. MVCC = 通过 Undo Log 版本链 + Read View 实现快照读，让 SELECT 不加锁。
  5. 可重复读（RR） = MySQL 默认，通过间隙锁解决幻读，适合“先查后改”的业务。
  6. 读已提交（RC） = 每次 SELECT 生成新快照，适合“纯查询展示”场景。
