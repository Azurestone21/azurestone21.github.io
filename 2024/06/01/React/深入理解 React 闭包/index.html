深入理解 React 闭包

深入理解 React 闭包

如果你曾经写过这样的代码——定时器里的 count 永远是 0，事件监听里拿到的永远是旧 state，useEffect 里的变量像是被”冻住”了——那么你已经和 React 闭包正面撞上了。

闭包是 JavaScript 最基础也最容易被人忽略的概念之一，而在 React(尤其是 Hooks)中，它从”面试题”变成了”每天都会踩的坑”。这篇文章会从原理讲到实战，帮你把 React 闭包彻底吃透。

一、先回到 JavaScript:闭包到底是什么

闭包(Closure)的定义很简单:

函数能够访问它定义时所在作用域中的变量,即使这个函数在其定义的作用域之外被执行。

outer 执行完后，按理说 message 应该被回收了，但 inner 依然能访问它。这就是闭包: 函数会”记住”自己被创建时的环境。

关键认知：闭包捕获的不是”变量的当前值”，而是”变量本身所在的词法环境”。只不过在 React 里，每次渲染都创建了一个全新的环境，所以你看到的是”快照”。

二、React 函数组件:一个每次渲染都在重建的闭包

React 函数组件的本质，就是一个每次渲染都会被重新调用的函数。这意味着:

每一次渲染:

  1. 调用一次 Counter 函数;
  2. 创建一个新的作用域，count 是这次渲染的值;
  3. 创建新的 handleClick，它捕获的是这次渲染的 count;
  4. 返回新的 JSX。

所以当 count 从 0 变成 1 时，并不是”同一个 count 变了”，而是产生了一个全新的闭包，里面的 count 是 1。旧的闭包(捕获 0 的那个)还在被旧的事件处理器引用着，直到它被替换。

理解这一点，React 中 90% 的闭包问题都能解释清楚。

三、经典陷阱:定时器里的 count 永远是 0

为什么会这样?

useEffect 的依赖数组是 []，意味着这个 effect 只在组件挂载时执行一次。它执行时，创建了一个 setInterval，而这个 setInterval 的回调函数捕获的是首次渲染时的闭包——那个闭包里的 count 永远是 0。

后续 count 确实在更新，但那是新的闭包里的事，和这个”活着的老定时器”无关。老定时器还在用它的旧快照。

这就是所谓的陈旧闭包(Stale Closure)。

四、四种解决方案,对应四种思维

方案 1:补全依赖 —— 让闭包跟着重建

思路:依赖变了就重建闭包。缺点是频繁重建定时器，如果逻辑重，性能会有损耗。

方案 2:函数式更新 —— 不依赖外部值

思路:与其捕获旧值，不如让 React 把最新值传给你。这是最优雅的写法，也是 React 官方推荐的。

方案 3:useRef —— 主动读取最新值

思路:闭包捕获的是 ref 对象的引用，而 ref 引用不变，.current 永远指向最新值。这是打破闭包的经典手段。

但要记住:ref 变化不会触发重渲染，所以它只适合”读最新值”,不能用来驱动 UI。

方案 4:把逻辑抽到自定义 Hook

这是 Dan Abramov 的经典实现。核心思想：用 ref 保存最新回调，effect 只依赖 delay。这样既避免了频繁重建，又能拿到最新逻辑。

五、闭包陷阱的三个高发区

1. useEffect 依赖不完整

ESLint 的 react-hooks/exhaustive-deps 规则就是专门抓这个的，不要轻易关掉它。

2. 异步回调(定时器、Promise、防抖)

防抖、节流、请求回调都是重灾区。解决思路同样是：依赖补全 / ref 保存 / 函数式更新。

但 useCallback 本身也受闭包影响：如果依赖写错，它缓存的函数同样会捕获旧值。所以 useCallback 不是”消除闭包”，而是”控制闭包何时重建”。

一个常见误区是给所有函数都套 useCallback，结果依赖数组写得一塌糊涂，反而制造了更多陈旧闭包。按需使用才是正道。

七、一句话总结每个概念

概念 本质
函数组件 每次渲染都是一个新闭包
state / props 是那次渲染的”快照”
依赖数组 控制 effect / 回调何时重建闭包
useRef 跨渲染保持引用,读取最新值的逃生舱
函数式更新 避开对外部值的依赖,最安全的写法
useCallback 缓存函数,但依赖写错同样会陈旧

八、结语:闭包不是敌人

很多初学者把 React 闭包当成”bug 制造机”，但其实它恰恰是 React 设计的基石。

函数式组件、Hooks、并发渲染全都建立在”每次渲染是一次独立快照”这个模型之上。闭包带来的”陈旧”不是缺陷，而是这个模型的自然结果——它保证了每次渲染的 UI 和逻辑是一致的、可预测的。

你真正要做的不是”消除闭包”，而是学会:

  1. 补全依赖,让闭包按需重建;
  2. 用 ref 或函数式更新,在需要时拿到最新值;
  3. 理解快照模型,不再和 React 的渲染机制对抗。

当你不再觉得 count 永远是 0 是”玄学”，而是能一眼看出”哦，这是 effect 只跑了一次，捕获了首次渲染的闭包”——你就真正掌握了 React。
